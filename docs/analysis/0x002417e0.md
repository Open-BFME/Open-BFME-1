## What the decompiler got wrong

The draft loses the x87 adjustment `point36.float0 - ownerPreferredHeight + planarDistance` and forwards plain distance to the final AI setter. It assigns pending outer-call pushes to getLayer, undercounts the terrain virtual arguments, and misidentifies the local address passed to one updateGoal call. Its inverted near/far comparison must also be restored to the retail ordered comparison so NaNs take the far arm.

One important correction goes the other way: **Ghidra was right about the near-arm angle variable.** The first manual analysis overlooked the still-pushed cdecl argument at +02FA, making `[esp+14]` appear to be the wrong steady stack slot. It actually overwrites steady ESP+10. Differential case105 disproved probes01-13; probe14 onward correctly uses absolute angle for the record-state thresholds. Those older snapshots are retained as rejected experiments.

## CONTROL FLOW

Notation: H = entry ECX; M = member Object; O = H[8]; A = M[204]; B = O[204]; L = A[1CC]; K = B[1CC]; F = TheAI[0C]; D/P/Q and distance `d` are as above. `Cxxxx` denotes the direct callee whose **body RVA** is xxxx, and `V(A,n)` is the method through A's vtable byte offset n. Arguments below are in logical left-to-right order, not push order. Every static call instruction appears below and in the contracts tables.

1. **+0000..+0081: prologue and entry guards.** Snapshot M position (y first materialized), load A, O, B. O is dereferenced without a null test. Exit +05B1 if B or A is null. Copy all three destination floats, load K and L, and exit if either is null. These guards precede the first call.
2. **+0087..+00BB: independent member guard.** Call C001B49C0(M) at +0088, with ECX incidentally L but unused by that stdcall function. If AL is zero go +00BE. Otherwise inspect M[114] bit 0x10000000: if already clear, exit +05B1; if set, clear it, call C001BE1C0(M) at +00AF, and return at +00BB. The incoming stash inverted this branch and changed the receiver.
3. **+00BE..+0107: destination suppression.** C00278830(B) at +00C2. If true, continue at +010B. If false and H[1AC]==0, load M[9C], M[A4], M[A8]. If signed M[9C]>=0, M[9C]==M[A4], and M[A0]==M[A8], replace D with the member's live position. Otherwise preserve D. The four words are integer pair fields, not floats.
4. **+010B..+0148: planar distance.** Build `(D.x-P.x,D.y-P.y,0)` and call `Coord3D::length` at +012F. Save its result both as d and as initial adjusted distance. Reload B; test B[140] Path pointer.
5. **+014A..+0173: optional path extension.** If Path is non-null, C003FD7D0(Path; O,B[1CC],&point36,false) at +015D. Then C001B46A0(K) at +0166. The adjusted distance is **point36.float0 - preferredHeight + d**, in that x87 order (`fsubr` +016B, `fadd` +016F). D and d are unchanged. No output coordinate is read by the hub.
6. **+0177..+01D2: command guards when H[1FC]==0.** V(A,184) at +018A, then only if true V(B,184) at +0198. If both are true, skip to +01D7. Otherwise C00278830(B) at +01A4. 8. **+01D7..+0206 and +0230: threshold.** C001B8010(L;M) at +01DE returns a float saved as t. C001B7E90(L;M) at +01EA returns a float multiplied by VA 01080BBC (float 0.2). If the product is ordered less than t, replace t. Discard the other x87 value. Then +0232 compares d with t. Ordered d<t goes to block 9; equality, d>t, and unordered go to block 23 at +0516 (`test ah,5; jp`).
