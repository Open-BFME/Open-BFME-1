## Reconstruction and independent validation

The final complete source is `body.cpp`, probe 16. Its measured result is 1524 bytes, four differing non-relocation bytes, score **0.9973753280839895**. Every instruction boundary, prologue/frame instruction, branch displacement, epilogue and call offset agrees with retail. This is a near match, not an exact landing.

Three productive source levers explain the improvement and should survive follow-up work:

1. Use the existing `coord3d.h` and its real copy construction, in-place Sub2D and GetLengthEstimate2D member shapes. Copying Object position into a local Coord3D before subtraction produces the actual 32-byte frame and x-component float spill. A direct scalar expression or two-argument subtraction did not. This proves an emitting source shape, not the exact original local declarations.
2. Use the ternary StringBase-style string-data choice after resolving the override, preserving the pre-call Object ID capture. This fixes the entry diagnostic instruction choice.
3. Reuse the landed sibling `AIInternalMoveToStateUpdate00172E70.cpp` STLport bitset operation shape: explicit Boolean word test, `_Unchecked_set`, and notify only after a previously clear bit is set. This fixes the broad Object/AI register allocation difference, reaches retail size, and leaves only the two virtual-dispatch register choices.
