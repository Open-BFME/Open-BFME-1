## What was proved

- The hub has an ECX receiver and three stack arguments, with `ret 0x0c`.
  Callers use the value stack for its result; source return-type spelling and
  original class/member identity remain unproved.
- The two scripted descriptors differ: D1 stream/length are +18/+0C; D2
  stream/length are +1C/+10. D2 formal records are eight bytes; its preload
  flags are bytes +0A/+0B. Receiver S has a real unused word at +4C before
  register width/base/current at +50/+54/+58.
- The discriminator is virtual **+4C**, and the hub calls it again before
  testing representation 2. Both bound-receiver gates use +4 and +60.
- `0089C290` receives the value object, a string-holder pointer and an
  optional alternate value receiver; it returns a nullable value and uses
  `ret 8`. `0089D890` receives the embedded table at frame+8 and uses `ret 8`;
  its null-value path delegates to the pinned erase helper `0089CC80`.
- `008CC690`, `008CC940`, and `008CCED0` respectively clean up 28, 24 and
  12 argument bytes. The hub's last stack adjustment is **008A0CF0**, not
  the earlier 008C5BB0; their behavior for nonpositive counts differs.
- Retail's final preload stores the global pointer but retains the previously
  carried value. Its register cleanup reads the flag word before testing the
  pointer for null. These surprising instructions are preserved.
- [AUDIT.md](AUDIT.md) verifies all **64 call sites**, **79 conditional
  branches**, and **89 jumps** with the same conditions and target transfer
  landmarks. All **ten EH states**, predecessor states, cleanup instruction
  shapes and stack slots agree. The entry frame/prologue matches after
  relocations, and the complete epilogue matches verbatim at its shifted
  location. The 22-byte string destructor agrees after its pool relocation.

This audit checks structure and selected byte evidence. It does not prove all
within-block dataflow or resolve the external declarations through a linker.

## What the decompiler got wrong or could not establish

- It types the hub's signed count as `int*`, conflating integer counts, value
  pointers and reused stack homes. In particular, a parameter home later holds
  a descriptor and then a string holder; those are separate lifetimes.
- It labels the no-stack-argument member at 008A1940 `__fastcall` despite only
  ECX carrying an input. Raw entry/exit evidence supports a member ABI, not an
  invented EDX parameter.
- In 008BC3E0 it types an incoming argument as `short*` because that stack home
  is reused for a string. Entry stores separately prove the output arguments
  point to a dword and a byte. The reused home does not prove the incoming type.
- Its fixed four-argument prototype for 00893410 omits the trailing variable
  arguments read from the caller stack.
- The bridge reports sizes 837 and 811 for 0089C290/0089D890. The terminal
  three-byte `ret 8` instructions start at +345/+32B, so the complete executable
  extents are **840 and 814 bytes**. The old 852-byte carved span at 0089D890
  includes another routine. Neither bridge length nor carving alone is an ABI.
- It does not supply original identities, full type layouts, C++ string
  lifetime structure or trustworthy implicit ECX contracts. These were checked
  against retail and landed sources. Its broad control flow was useful.

Separately, the old bank had omitted cleanup bodies, the wrong virtual slot,
one merged descriptor layout, a shifted receiver layout and the wrong final
pop helper. Those were reconstruction errors, not newly attributed decompiler
algorithm errors.

## Biggest remaining obstacle and next useful lever

The remaining obstacle is **VC7.1 source shape in string cleanup and the last
register-release loop**. The first byte difference, +002C, is the displacement
of a forward JE to a tail shifted by two bytes. The first ordinary instruction
difference is +0278: retail selects the string entry through ECX and extracts
the full code into EAX; the reconstruction uses EAX/EDX and a byte mask.
Pool-release register choices then create local one-byte displacement changes.
At the final register release, an extra `mov eax,edx` accounts for the final
two-byte excess. Restore and common-exit scheduling also differ.

Typed bound and array views recovered most of the body. Enum/bitfield/string
switch variants, slot declaration order, slot destructor spelling, a combined
flag/null helper and a typed pool did not improve the best result. Resume from
the active bank; do not reconstruct cold or remove the witnessed null branch.
Opaque external declarations also need address bindings before a landing gate;
this session installed no speculative pins.

shared value stack. Caller 008A1940 supplies records on the branch accompanied
