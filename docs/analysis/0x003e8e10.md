# Astra pilot report: 0x003E8E10

The pilot moved the target from a 526-byte fragment to a complete control-flow
reconstruction with the retail SEH registration, 0xE8 local frame, all 38 call
sites in their retail order, both search paths, and the two-pass loop. It did
**not** reach an exact match. No conversion was landed or claimed.

The score is `max(0, 1 - (979 + 2*abs(1846-1852))/1852)`.
It is a byte-distance metric, not a percentage of proved behavior. The raw
differing-byte count grew because the reconstructed body is much longer. The
probe also reports **26 relocation sites misaligned with retail operands**;
its masked comparison is not relocation-resolved byte verification.

`body.cpp` is the selected source. `PROGRESS.md` records B000 and P001-P065,
including compile failures and regressions; each successful probe retains its
source, object receipt, bytes, disassembly, and full probe output. P045 also
remains useful: it has an exact masked prefix through +0x070 and first differs
in the common-epilogue jump displacement at +0x071, but its measured score is
0.458963283 and its size is 1,844. P047 scored 0.491360691 but expanded the frame
to 0xEC and forced a volatile pointer spill. It was rejected under the requested
priority of correct SEH/frame and call structure before the numeric score.

The selected body was banked successfully through `re_log.py` at approximately
19:40 UTC, 50 minutes into the session. The preferred bank is
`targets/game/reverse/attempts/0x003e8e10.cpp`; the record includes the actual measurement,
scope of validation, elapsed time, and model. All authored analysis and
experiments are under `build/astra_3e8e10/`. No git command, full gate, game
launch, source-tree edit, or speculative pin was used.

## What the decompiler contributed

The useful advance was a full working control-flow draft, rather than an
additional identity guess. It exposed the fast-path source-position copy,
radius/direction preparation, repeated template overrides, conditional vector
adjustment, two source world-to-cell calls, effective-zone comparison, module
predicate, two callback contexts, and the final zero-displacement retry in one
view. That made omissions in the old fragment conspicuous. Each operation and
edge was then checked against instructions; ANALYSIS.md contains all 92 basic
blocks and every call's arguments.

The callee decompiles made it practical to audit 22 distinct contracts together:
output buffers versus scalar arguments, integer/float use, callback storage,
and the source of returned pointers. The three caller decompiles established
the five-argument handoff independently of the target's guessed prototype.
Existing outputs were reused; only the missing 0x00170680 caller needed a new
function definition, in a read-only Ghidra run. All 26 required decompiles are
present: target, three callers, and 22 distinct callees.

None of this is information that the machine code fundamentally lacks.
Ghidra supplied a coherent draft quickly enough to spend the session validating
and reconstructing the whole body rather than repeatedly reconstructing its
opening fraction.

## What it got wrong, and what needed independent evidence

* The target's `undefined4` return and extra apparent first parameter are not
  its source signature: ECX is the receiver, there are five stack arguments,
  and callers observe AL. The final instruction is `ret 0x14`.
* Ghidra describes 0x003D5670 as returning void. Its instructions preserve
  ECX in EAX, and the caller immediately pushes EAX as the callback pointer.
  It has twelve arguments and `ret 0x30`; the extra pending push belongs to
  the surrounding search call.
* The 68-byte local array is not a proven source object. It combines an
  8-byte conversion output with a separate 60-byte callback context.
  Tracking outstanding pushes places the second context at SP0+0xBC.
* The body size reported for 0x003DF580 is a count of 2,013 included addresses,
  not its 2,029-byte contiguous extent. All return tails were decoded directly.
* Most importantly, the large frame does **not** imply stack objects with
  destructors. Retail FuncInfo has one unwind state, solely for the local
  static `SiegeDeploySpecialPower` key initializer. Its cleanup clears the
  initialization flag. Native `/EHsc` scalar static initialization reproduced
  this prologue immediately. Inventing fourteen RAII objects would be wrong.
* Existing ledger names also required correction in the analysis, independently
  of Ghidra: 0x001F8AB0 is a one-argument cdecl pointer finder, not the pinned
  WorkerAIUpdate key getter; 0x0008FFC0 is NameKeyGenerator::nameToKey, not the
  duplicate allocator identity. The experiment calls their witnessed ILTs
  through address-derived ABI views and does not spread those names.

Pointer/reference distinctions, constness, and original enum/class spellings
remain source-level assumptions where instructions cannot distinguish them.
The machine-level slots, ECX use, cleanup, and observed return widths are
documented separately. Literal 10/5/1 floating values were read from retail;
no INI default was substituted.

## Validation and remaining obstacle

The selected P065 machine code and retail target passed **250 isolated
differential cases**. They compared call order and argument values, callback
payloads, output coordinates, AL, stack cleanup, preserved registers, static
key/guard state, and restored FS chain. The actual retail normalization leaf
executed; all other callees were stubbed from the documented contracts.
The cases visited all 38 call sites and 523 of 524 target instructions. The
unvisited instruction is the destination-outside-bounds zero store at +0x2AA;
the stub's clamping contract prevents that state. This is not proof of every
branch edge, arbitrary floating-point input, exception unwinding, or gameplay
integration. No game was launched.

After banking, `check_csv.py` passed with 168,689 function rows and 88,553 symbol
rows. FINAL_RECEIPT.json confirms that the preferred bank contains the exact
selected source and that all 26 decompiles and the ordered 38-call inventory
are present.

The single biggest remaining obstacle is **the original local-variable and
register-lifetime model**. Retail spills the source cell and reuses an
eight-byte scratch region for unrelated dead values; the compiler currently
keeps the source cell in a register and assigns a separate circular-search
output slot. Even with the same total frame size, that changes register choices,
stack displacements, later instruction scheduling, and the six-byte size
deficit. At +0x034 the selected candidate first uses EDI for the source-position
pointer where retail uses ESI. Explicit aggregate/union/volatile models,
coordinate value temporaries, helper-boundary changes, and natural constructor
inlining were measured and retained, but did not solve this. The next useful
attempt should start from P065/P045 and this layout evidence, not another small
opening fragment or a fabricated destructor frame.

## 1a. Control flow

The complete instruction CFG follows the semantic outline. All calls, including
otherwise redundant conversions and the out-of-line callback constructor, must
survive reconstruction. Local labels below identify observed roles, not new
claims about original source names.

1. **Entry and fast success, +000..+074 (B00-B03).** Install EH registration,
   reserve E8 bytes, save EBX/EBP/ESI/EDI. Call C01 with S's cached position,
   T and T's cached position. If AL is nonzero call C02(P,S). If both succeed,
   copy **S+38/3C/40** into Q; set AL=1 and jump to common epilogue +721.
2. **Radius and initial displacement, +075..+150 (B04-B06).** C03 obtains
   integer radius and one-byte center flag. Copy S's position to A; C04 fills D
   from S's direction. D.x and D.y *=10; A +=D, including unscaled D.z.
   V=(A.x-Q.x,A.y-Q.y,0); C05 normalizes V; V*=10 in all three axes.
   The input Q matters before it is overwritten in the loop.
3. **Conditional adjustment, +151..+1A6 (B07-B16).** If bit 7 of F(T)+C8
   OR bit 27 of F(T)+CC is set, and bit 21 of F(T)+D8 is clear, C09(P,S,T,&V).
   Preserve the short-circuit ordering and repeated override lookups.
4. **Retry header and destination, +1A7..+244 (B17-B26).** Counter=0.
   The only target loop starts +1B0. C10(T,Q) refreshes Q. If F(T)+D8 bit21,
   zero V. Q += V. If center flag is false, add 5 to Q.x/Q.y (not z).
   C12(P,Q,&C). Its true return means clamped/outside: **return false**.
5. **Destination cell, +245..+2B1 (B27-B36).** C13 gets destination layer d.
   Bounds check C.x/y against P+14/18/1C/20. Outside -> destinationCell=null.
   For 2<=d<=15 call C14(&P.layers[d],x,y); nonnull wins. Otherwise choose
   P.map[x]+16*y. This is the existing inline Pathfinder::getCell pattern.
6. **Source-side cell, +2B2..+34B (B37-B46).** C15 converts A into a temporary
   cell at SP0+B4; ignore its return. C16(S) gets integer source layer.
   C17 converts A again, this time into C2 at SP0+70; ignore return.
   Bounds-check C2: any failure returns false. For layers 2..15 call C18;
   null falls back to P.map[C2.x]+16*C2.y. Null sourceCell returns false.
7. **Layer and movement profile, +34C..+40E (B47-B62).** If F(T)+CC bit27
   and not F(T)+D8 bit21, force d=1. Read F(S)+444, F(S)+4CC. C23(S) returns
   bool. Build 12-byte profile M: dword from L+10; byte !F(S)+4CC; byte C23;
   dword F(S)+444 minus 1. Padding bytes are not initialized.
8. **Zone comparison, +40F..+469 (B62-B64).** C24(Z,&M,sourceCell.word8)
   returns a 16-bit zone, zero-extended into EBX. sourceSpecial=false.
   If (sourceCell.dwordC & 7)==4: sourceSpecial=true; C25 then C26 map zone
   through terrain and effective tables. C27(Z,&M,destinationCell.word8).
   The destinationCell is dereferenced without a new null guard in retail.
9. **Direct destination acceptance, +46A..+4CF (B65-B68).** Only if zones
   match: C28(P,S,C.x,C.y,d,radius,center,&cellOut,0). If AL !=0 AND cellOut==0,
   C29(W,S,S+38,T,Q,0.0). If true, return true via +06E. Otherwise continue.
10. **Optional module predicate, +4D0..+583 (B69-B79).** special=false.
    If F(T)+D0 bit28: C31(T) returns a pointer (only null-tested here).
    Lazily initialize a static key via C32(NameKeyGenerator,
    "SiegeDeploySpecialPower"). C33(T,key) returns module pointer.
    Only when both pointers are nonnull call C34(module); if true special=true.
11. **First circular search, +584..+639 (B80).** Initialize a 60-byte callback
    object K1 at SP0+78 with the exact field mapping in LAYOUTS. Its initializer
    is inlined, with no vtable/destructor. C35(P,&C,50,&searchCell,&K1,1).
    If true, return true; callbacks may update Q through K1+34.
12. **Second circular search, +63A..+6BF (B81-B86).** Fresh F(T); only when
    D8 bit21 is set and d!=1, construct K2 at SP0+BC with C37, setting its layer
    to 1. C38(P,&C,100,&searchCell,K2,1). If true, return true.
13. **Retry/false, +6C0..+720 (B87-B90).** Compute V.x*V.x + V.y*V.y and
    compare with 1.0. Retail `fcomp; fnstsw; test ah,41; jne` exits false for
    <=1 **or unordered**. Otherwise increment counter; zero V; if counter>=2
    return false; reload S/Q/T and jump +1B0. Therefore at most two searches
    through the outer loop, with the second using zero displacement.
14. **Common epilogue, +721..+73B (B91).** Restore prior FS:[0], registers,
    release F4 frame bytes including registration, `ret 0x14`. AL is the
    observed boolean return; upper EAX is not a return-value contract.

### EH states and actual lifetimes

There are **not fourteen EH states and no nontrivial stack-object destructors**
in this body. Handler VA 0101FDCE loads FuncInfo VA 01210064. Magic 19930520,
maxState=1, unwind table VA 0121005C contains only `{previous=-1,action=0101FDC0}`.
That action loads flag 012F1088, ANDs with FFFFFFFE, writes it back, and returns.
It never receives or destroys a stack object.

| State | Begin | End | Cleanup / live object |
|---|---|---|---|
| -1 | initial push at +000 | +535 on lazy-init branch | no pending cleanup; all vectors, cells, profile and callbacks trivial |
| 0 | store at +535 (SP0+100; SP temporarily -4) | store -1 at +54A | initialization of static integer key at 012F1084; exception clears flag bit0 at 012F1088 |
| -1 | +54A | epilogue | no pending cleanup |

The flag is set before initialization at +523. An exception from nameToKey
resets it, permitting another initialization attempt. Correct ordinary C++ is a
function-local static scalar initialized by that call with /EHsc. A fabricated
RAII destructor would add cleanup behavior absent from retail. Stack allocation
E8 comes from values/temporaries, not a large hidden destructor-bearing object.
