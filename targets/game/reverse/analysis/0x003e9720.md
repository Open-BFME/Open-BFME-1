# Hub 0x003E9720 analyst report

The bounded hub session produced a complete analysis, a complete but nonmatching C++ reconstruction, all probe records, and a preferred banked body. **No conversion was landed.** The 16 open neighbours each have an explicit handoff row in [ANALYSIS.md](ANALYSIS.md).

## What was proved

- The hub is `Pathfinder::updateGoal(Object*, const Coord3D*, PathfindLayerEnum, const char*, int)`, using ECX plus five stack arguments and `ret 0x14`. Matched GiantBird and AIUpdate callers establish identity through ILT 0x000294E2. File and line are unused in this body; the position's z is unread.
- The boundary is 1305 bytes: `push ebp`, 8-byte stack alignment, `sub esp,0x34`, no EH/SEH state, two returns, INT3 at +0x519. The analysis maps all numbered blocks, loop backedges, exits, calls and witnessed storage.
- All **25 call instructions** are accounted for: 22 direct calls through 11 independently decoded ILT routes, plus containment +0x100, AI +0x1EC and terrain +0xA4 virtual dispatch. [Static call validation](static_call_validation.md) pairs retail and candidate offsets. No callee is missing and no new pin was needed.
- Ordinary ground processing applies to layer 1 **or signed layer >=16**. Other values use the layer lookup, additionally updating ground when the bridge predicate succeeds. Both occupancy gates are `goal != pos || goal == 0`. These were behavioral errors in the incoming bank and are repaired.
- The aircraft arm reloads Object ID each setter visit; the ground arm caches it once. Goal setters can change/allocate cell info, so position checks reload that pointer. Map extents are inclusive, rectangle bounds exclusive, and PathfindCell stride is 16 bytes.
- Template +0xD4 bit 12 and the later `Thing::isKindOf(108)` refer to the same kind ordinal: the independent isKindOf body computes `C8 + 4*(ordinal>>5)`. Its gameplay name, Object coordinate member names and containment slot100's semantic name remain deliberately unknown.
- The nested terrain destination-layer helper takes **two** arguments and pops 8. Caller file/line pushes preceding that helper belong to the later five-argument hub call. This is a concrete ABI constraint for the upcoming neighbour sessions.

## What the decompiler got wrong

1. Its apparent three-argument declaration omits the two unused diagnostic arguments and does not identify the incoming ECX receiver. Caller setup and both `ret 0x14` instructions settle the actual ABI.
2. It represents reused integer stack homes, coordinate stores and loop counters as floats, emitting misleading float comparisons/casts. Retail uses integer CMP, ADD, SUB and signed loop branches after x87 conversion.
3. Its apparently uninitialized `local_30` is the saved incoming Pathfinder pointer. Byte flags are movement state, not EH state.
4. It conflates stack homes reused by float spill/reload and integer FISTP results. The required conversion is the float wrapper at 0x00069750 followed by float narrowing and the native FISTP helper, not an arbitrary C++ truncating cast or a direct double-floor call at the hub boundary.
5. Ghidra has no containing function at neighbour 0x00178140. Its raw retail body was inspected and saved; no adjacent draft was substituted. Other inferred caller signatures remain explicitly limited to what their real cleanup and hub-facing uses prove.

The two incoming-bank predicate bugs are listed separately above; they should not be attributed to this Ghidra draft, which actually exposes the correct conditions. Context-pack strings such as `password` and `encryptedInfo` are irrelevant attribution noise and were rejected as identity evidence.

## Biggest remaining obstacle

VC7.1 local-storage reuse and instruction scheduling remain different. The first reported byte difference (+0x1E) is the displacement to the shared exit, because the complete candidate is three bytes longer. The first meaningful storage mismatch is +0xB8: aircraft center uses S+0x12 instead of S+0x13. Radius, old-goal pair, setter pairs and conversion temporaries occupy different homes despite the correct total frame.

The aircraft instruction span now ends at the right offset. Ground conversion flag/radius scheduling, the position-pair comparison/store schedule, register selection and loop alignment still differ. [aligned_diff.txt](aligned_diff.txt) and [ours.asm](ours.asm) preserve that evidence. Separate scopes, an inlined aircraft helper, radius lifetime variants and explicit bounds were measured; their unsuccessful variants are retained. The best lever was copying the escaped radius to a scalar **at scan entry**, allowing the compiler to derive invariant rectangle bounds. Another useful correction was materializing the old position pair before comparison. No speculative pins, fake callee names, volatile padding or lifted naked body were introduced.

The next neighbour sessions can use the layouts and ABI facts without requiring this hub to match. Full neighbour names/return types not established by the evidence are left open.

# Retail hub 0x003E9720 (1305 bytes)

Prepared from the live retail image and current landed sources, 2026-09-22 UTC.
Offsets written `+NNNN` are hexadecimal offsets from RVA **0x003E9720**, unless a different body is explicitly named. RVAs and VAs are distinguished; image base is 0x00400000. Primary evidence is `retail/0x003e9720.asm`. Ghidra's draft is `docs/ghdec/0x003e9720.c`; its inferred types and three-argument declaration are **not** evidence.

## Identity and public ABI

The supported identity is **Pathfinder::updateGoal(Object *, const Coord3D *, PathfindLayerEnum, const char *, int)**. The current ledger still calls the body `?d_003e9720@@YAXXZ`. The enum and int overload spellings both exist as pins; they describe the same five machine arguments. No new pin is needed.

Evidence:

- ILT RVA **0x000294E2** jumps to this body. Both retail returns (`+0233`, `+0516`) pop **0x14** bytes.
- `GiantBirdAIUpdate.cpp`, landed `GiantBirdNormalFlightState::onExit` at **0x002BE180**, declares the five-argument method and passes Object, Object+0x38, ground ordinal 1, the retail GiantBird source-file literal, line 381. Its preceding call names `Pathfinder::removeGoal`.
- Landed `AIUpdate.cpp` `doPathfind` contains three calls through the same ILT, using the explicit `BFMEUpdateGoalCall` adapter. The local adapter is not a different retail function.
- Current pins include `?updateGoal@Pathfinder@@QAEXPAVObject@@PBUCoord3D@@W4PathfindLayerEnum@@PBDH@Z` at this RVA. The independent caller and argument evidence supports this identity; the pin alone would not.

At entry: ECX=Pathfinder, `[ebp+08]=Object*`, `[ebp+0C]=const Coord3D*`, `[ebp+10]=layer`, `[ebp+14]=file`, `[ebp+18]=line`. The last two arguments are never read in this body. Return value is unused and no return value is established: **void**. The body does not read `newGoalPos->z`.

Important for the upcoming caller sessions: in calls whose layer is computed by ILT **0x0001C675 -> 0x001A7C20**, the caller often pushes `line,file` **before** calling `getLayerForDestination(Object*,position)`. That helper takes two stack arguments and pops 8 bytes. File/line remain for the subsequent five-argument hub call. They are **not** extra arguments of the terrain helper. See landed `TerrainLogicGetLayerForDestinationObject.cpp` and the raw windows in `neighbour_hub_windows.txt`.

## Control flow

Notation: `P`=Pathfinder receiver, `O`=Object argument, `Q`=position argument, `L`=layer. `r` and `c` are the output integer radius and one-byte center flag. `n=r+(c?1:0)`. `I(x,y)` is an eight-byte integer pair. `floorf_call(v)` means the **out-of-line** float overload at 0x00069750, followed by an explicit float store/reload and x87 `fistp` to a signed dword. It is not a C++ truncating cast.

1. **+0000..+0021, prologue/private-status exit.** `push ebp; mov ebp,esp; and esp,-8; sub esp,0x34`; save EBX, ESI, EDI. EBX=O, EDI=P, spill P. Test O+0x344 bit 0. If set, jump to exit +0510. No null guard on O.
2. **+0022..+0034, first template resolution.** EAX=O->field04. If nonnull and its +4 link is nonnull, ECX=that link and call **+0030** `getFinalOverride()`. EAX is the final template. Null does not produce an early return: the next block still dereferences EAX, preserving the retail invariant rather than adding a fallback.
3. **+0035..+005C, template/containment guard.** Read template dword +0xD4, test bit 0x1000. If clear skip to +005D. Otherwise read O+0x1FC; if null skip. Call **+004E** its vtable **+0x100**, ECX=contain pointer, one stack dword 0. Compare EAX **unsigned** with 2; `<2` exits at +0510. Semantic method name remains unknown.
4. **+005D..+007C, second template resolution/flag guard.** Reload O+4 and optionally call **+006B** `getFinalOverride()` on link +4. Test final-template byte +0xC8 bit 4; set exits. This reload is required after the virtual containment call.
5. **+007D..+009C, movement split.** ESI=O+0x204; null exits. Call **+008F** vtable +0x1EC with ECX=ESI and no stack args (`isDoingGroundMovement`). AL nonzero enters ground path +0236. AL zero takes the aircraft path.
6. **+009D..+00AB, aircraft eligibility.** Call **+009F** `isAircraftThatAdjustsDestination()` on the same AI pointer. AL zero exits.
7. **+00AC..+00EB, aircraft radius and old coordinates.** Snapshot O+0x9C and +0xA0 before calling **+00CD** `P->getRadiusAndCenter(O,&r,&c)`. Set n=r. Load Q.x and multiply by float at VA 0x01075C70. The common multiplication is scheduled before the center branch.
8. **+00EC..+012F, centered aircraft coordinate conversion.** If c is nonzero, increment n. Calls **+00F6** and **+011B** to floor(float) convert Q.x*scale and Q.y*scale. Each result is narrowed to float, then reloaded for `fistp`. Jump to +0179. New x ends in EDI; new y in a dword stack home.
9. **+0131..+0178, uncentered aircraft conversion.** Calls **+013A**, **+0165** convert `(Q.x*scale)+bias`, `(Q.y*scale)+bias`, with bias at VA 0x0107533C. Same float round trip and integer conversion. n remains r.
10. **+0179..+018C, unchanged aircraft goal.** Compare both new integer coordinates with the saved old pair. Both equal exits. Comparisons are integer CMPs, not floating comparisons.
11. **+018D..+01C4, aircraft rectangle setup.** Store new pair at O+0x9C/+0xA0. Form xStart=newX-r, xEnd=newX+n, yStart=newY-r, yEnd=newY+n. If xStart>=xEnd exit. All loop comparisons are signed and upper endpoints exclusive.
12. **+01C5..+01D7, aircraft outer/inner-loop entry.** Reset y to yStart for each x. If y>=yEnd go to x increment +0224. Otherwise form byte offset y*16.
13. **+01D8..+0213, aircraft ground-cell visit.** Require `P.extent.lo.x<=x<=hi.x` and `lo.y<=y<=hi.y`; out-of-bounds goes to +0214. Compute `P.map[x]+16*y`. If the computed pointer is zero skip. Write aircraft-local I(x,y), call **+0207** `cell->setGoalAircraft(O->m_id,I)`. The ID is reloaded from O for **each** visit, not cached across the whole aircraft loop. P and the y byte offset reload after the call.
14. **+0214..+0235, aircraft increments and return.** Increment y and its byte offset by 16, loop at +01D8 while y<yEnd. Increment x at +0224 and loop at +01C5 while x<xEnd. Normal aircraft completion has its own epilogue +022D and `ret 0x14` at +0233. Earlier exits share +0510.
15. **+0236..+026A, ground/layer selection.** Initialize ground=false and layerFlag=false. If **L==1 OR signed L>=16**, jump directly to +0266 to set ground=true. Otherwise set layerFlag=true and call **+025C** `TheTerrainLogic->objectInteractsWithBridgeEnd(O,L)` through vtable +0xA4. AL nonzero sets ground=true, zero skips that store. Negative and zero L follow the layerFlag path; do not silently add a lower-bound test.
16. **+026B..+029C, ground radius.** Cache O+0x74 ID once. Call **+027F** `P->getRadiusAndCenter(O,&r,&c)`; set n=r and multiply Q.x*scale. Center flag is a different byte home from the aircraft flag and is reused later for the position-update condition.
17. **+029D..+02E6, centered ground conversion.** Increment n and call floor(float) at **+02AC**, **+02D1** for scaled x/y, each with float spill/reload then `fistp`. New x is ESI, y eventually EDI. Jump +0330.
18. **+02E7..+032F, uncentered ground conversion.** Add bias before floor calls **+02F1**, **+031C**. n stays r. Same integer conversion semantics.
19. **+0330..+0348, remove old goal then set layer.** Call **+0339** receiver P, stack O, body 0x003E3D20. Then **+0344** `O->setDestinationLayer(L)`. This occurs even when the new ground coordinate equals the old one; there is no ground-path unchanged-goal early return.
20. **+0349..+0384, position-update condition.** Read O+0xA4/+0xA8. Store new pair at O+0x9C/+0xA0. Set bool `samePosition=(newX==fieldA4 && newY==fieldA8)`. At **+0377**, call `Thing::isKindOf(108)` with ECX=O. If AL nonzero, clear samePosition. The semantic name of kind ordinal 108 is not established here.
21. **+0385..+03C9, ground rectangle setup.** Same signed half-open rectangle as aircraft; x held in EBX, y in EDI. If empty x range exit. Set yStart/yEnd, then for each x reset y; empty y range goes to +0503. Form y*16. +03CA is a six-byte alignment NOP (`lea ebx,[ebx]`), not a field access.
22. **+03D0..+03EC, layer lookup.** If layerFlag=false skip to +0450. Otherwise call **+03E2** `P->getCell(L,x,y)`; EAX->ESI. Null skips. Note getCell can fall back to the ground map if its layer lookup returns null; this is proven existing callee behavior, not a new fallback in the reconstruction.
23. **+03ED..+040C, layer occupancy gate.** Read `cell->m_info` once. Goal ID is info+0x14, or 0 if info=null. Position ID is info+0x18, or 0. **Proceed when `goal != pos || goal == 0`.** Equal nonzero IDs skip to +0450. The `jne +040D` at +0407 is decisive; the incoming bank had this wrong.
24. **+040D..+044F, layer writes.** Materialize ground-local I(x,y); call **+0421** `cell->setGoalUnit(cachedID,I)`. If samePosition=false skip. Otherwise **reload** m_info and its position ID because the setter may allocate/modify it. If that ID equals cachedID skip. Else call **+044B** `cell->setPosUnit(cachedID,I)`.
25. **+0450..+0485, ground lookup.** If ground=false go +04EB. Read P from spill; apply the four inclusive bounds at +0460/+0465/+046A/+046F. Failure sets cell=null. Success computes map[x]+y*16. Null skips.
26. **+0486..+04A5, ground occupancy gate.** Same independently emitted goal/position reads and `goal != pos || goal == 0` predicate as block 23. Equal nonzero skips.
27. **+04A6..+04EA, ground writes.** Use the **same ground-local pair home** as the layer path. Call **+04BA** setGoalUnit, then conditionally reload info/position ID and call **+04E6** setPosUnit if samePosition and ID differs.
28. **+04EB..+050F, ground loop backedges.** Increment y and its byte offset by 16; `jl +03D0` at +04FD. Then increment x; `jl +03AF` at +050A resets y for next row. Each iteration handles layer before ground.
29. **+0510..+0518, shared exit.** Pop EDI, ESI, EBX; restore ESP from EBP, pop EBP, `ret 0x14`. INT3 padding begins exactly **+0519**. No code after this belongs to the 1305-byte body.
