# 0x003ADED0 Glo012F1024Item::j_00015e42 (192 B) -- s500 handoff

Bank: `targets/game/reverse/attempts/0x003aded0.cpp` (s500, probe 192/192 B,
29 non-reloc diffs, shape 0.983; the earlier 0.9-estimate bank had 63 diffs).
Compiler `/DNDEBUG /MD /EHsc` (the Glo012F1024Entry_bfmeStep.cpp TU flags).

What fixed the frame and the flag argument:
- Retail copies the element byte at +8 into a 4-byte frame temp
  (`mov cl,[e+8]; mov [esp+10],cl; mov edx,[esp+10]; push edx`) after the
  `operator new` test, i.e. a 1-byte struct returned BY VALUE by an inline
  helper and passed by value. `bfmeFlagOf(char)` returning `BfmeFlag1VNE`
  reproduces it (also as a member getter, `= { c }` init, or a struct with a
  converting ctor returned from the helper).
- Ruled out: plain `char` arg or struct field passed directly (`xor ecx,ecx;
  mov cl` + push, 173 B), struct with ctor(char) as the parameter conversion or
  user copy ctor (constructed in the push slot, 35 diffs -- but THIS variant
  gets retail's ebx=this/esi=begin/edi=offset allocation), `char` local before
  new (old bank), typed 16-byte vector view with operator[] (179-180 B).

Remaining residue: register rotation only. Retail this=ebx, begin=esi,
offset=edi, and the width load reuses esi (`mov esi,[edi+esi+4]`) so the three
args are loaded before the pushes; ours this=esi, begin=edi, offset=ebx and
the temp is pushed before the height/width loads. Unchanged by while vs for,
element pointer vs `begin[i]` repeats, a global local before append.

Landing prerequisite: the callee 0x003BBF70 is a constructor (base then
derived vtable, returns this) but is ledgered as the method
`?bfmeInitVNE@BfmeRectVNE@@QAEPAV1@IID@Z` (BfmeConv1507.cpp). The probe bank
uses /alternatename only for diagnosis; a real landing needs that row renamed
to a ctor whose third parameter is the 1-byte struct, and its own bytes
reverified.

## Sibling 0x003ADCC0 j_00021f26 (192 B, Flag16 vector at +0x9C)

Same family and the same fix: `BfmeRectVNG(width, const BfmeRefVNG &, BfmeFlag1VNE)`
(callee 0x003BBB70, also really a ctor) with `bfmeFlagOf(begin[i].flag)`, and

the same this/begin/offset rotation. Also tested inside a copy of the real

Observation for the rotation: moving the flag into a struct local BEFORE the
new-expression (`BfmeFlag1VNE flag = bfmeFlagOf(...)`) gives retail's
this=ebx / begin=esi / offset=edi allocation (first diff moves to +0x46) but
then loads the byte before `operator new` (38 diffs). The struct constructed
in the push slot (ctor(char) parameter) also gets the right allocation. So
the rotation follows the flag temp's form, not the loop. Inert: assignment
expression `(flag = bfmeFlagOf(..))` with flag in loop or function scope,
reference-returning `bfmeFlagInto(flag, c)`, 2- and 4-byte struct, bool
member, const/aggregate local, `self = this` copy, while loop, result local.
