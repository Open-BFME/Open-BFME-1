2026-11-13, `5d9c42eb8e9ab0d06bab68bb834f095777d00f2c`; read-only candidate, model openai/gpt-6.1-terra:high. Not a production configuration or full ABI proof. Canonical `game/Libraries/Source/LibPNG/png.h` SHA-256 `e368e66f9b28f41e759641f5dc32645d078a6feb9671b8c93f76bfe5e14b1730`, `pngconf.h` `f88e056928fc2e45e94ad717d27c7b9df6bc9f4ea65bb89854b726c11f5668ef`.

Original `pngmem.obj` `png_create_struct` at RVA `0x00AABE80` allocates INFO `0x40` and PNG `0x19c`. Published D3DXPngTrans flags produce canonical `png_info/png_struct/png_row_info` sizes `0xb8/0x1f0/0x0c`, not the native full allocations. The published Trans member's actual pointer field accesses are within offsets `0x5c`..`0x159` (and distinct row-info offsets), and its eight code bodies match native; neither establishes full class layout or ODR equivalence. This remains a published-source ABI qualification, not a demonstrated body mismatch.

Under the following scratch-only VS2003 flags, candidate sizes are `0x40/0x19c/0x0c`, and three probed offsets agree independently with original consumers: `flush_dist=0x124` (`png_set_flush` in pngwrite), `shift=0x155` (`png_set_shift` in pngtrans), and `empty_plte_permitted=0x198` (`png_permit_empty_plte` in pngset). A private compile of both published Trans bodies and upstream Get candidate produces `.text` sections exactly identical to their original respective physical members. This is not full COFF/relocation verification or a normal source gate.

Flags, in addition to `-MD -Gz -Os`: `PNG_NO_READ_USER_TRANSFORM`, `PNG_NO_WRITE_USER_TRANSFORM`, `PNG_NO_READ_bKGD`, `PNG_NO_READ_BACKGROUND`, `PNG_NO_CONSOLE_IO`, `PNG_NO_READ_cHRM`, `PNG_NO_READ_tEXt`, `PNG_NO_WRITE_tEXt`, `PNG_NO_READ_zTXt`, `PNG_NO_WRITE_zTXt`, `PNG_NO_READ_tIME`, `PNG_NO_WRITE_tIME`, `PNG_NO_READ_sBIT`, `PNG_NO_WRITE_sBIT`, `PNG_NO_WRITE_bKGD`, `PNG_NO_WRITE_cHRM`, `PNG_NO_READ_oFFs`, `PNG_NO_WRITE_oFFs`, `PNG_NO_READ_pHYs`, `PNG_NO_WRITE_pHYs`, `PNG_NO_READ_hIST`, `PNG_NO_WRITE_hIST`, `PNG_NO_READ_pCAL`, `PNG_NO_WRITE_pCAL`, `PNG_NO_PROGRESSIVE_READ`, `PNG_NO_STDIO`, `PNG_NO_READ_RGB_TO_GRAY`.

Evidence for some profile conditions: original pngget has only signature, valid, rowbytes, channels, gAMA, sRGB, IHDR, PLTE and tRNS getter publics. Original pngset has gAMA, sRGB, sRGB_gAMA_and_cHRM, IHDR, PLTE, tRNS, permit_empty_plte. Original pngrtran and pngget lack the RGB-to-gray setter/status getter; png, pngrio and pngwio lack the investigated RFC1123/stdio entry points. These bounded object inventories and offsets support hypotheses, but absence must not be generalized without checking relevant source definitions and physical archive members. Conversely original pngwrite contains both `png_set_flush` and `png_write_flush`; canonical `PNG_WRITE_FLUSH_SUPPORTED` retains the function pointer **and two counters**, so disabling it solely to hit a size is unjustified. No `.debug$T` section was found in original pngmem, pngtrans, pngget or pngrtran; `.debug$S` records compiler/path only in the inspected pngmem object.

Before proposing production flags, establish remaining native field offsets and conditional member use, actual stock consumers, original member presence/absence, canonical class identity across all D3DX TUs, runtime relocation/COMDAT invariance and all normal gates. Do not replace conditional fields with padding or infer a profile from total size alone.
