## What this session established (new, measured)

1. The merged amount store A is formed before the final schedule; the scheduler then
   refuses to lift B above A. Swapping B's base pointer is decisive:
   - `other->m_id` (parameter pointer) -> order B,D,A exactly as retail (1 diff, only
     the ModRM base ebp vs edi) [w/b1.cpp];
   - a stack-parameter load, a `this`-relative load, a global -> also hoisted above A
     [w/x1, w/d7, w/b2, w/b3, w/x2];
   - any pointer loaded from memory (`object` = [this-0x18], `data` = [this-0x1c]) stays
     after A [bank, v/d1]. So ours treats `object->m_id` as possibly aliasing the
     address-taken `damage`; retail did not (or had B before A in its IR).
   Not changed by: no DamageInfo ctor (address escapes only at the call), removing the
   reflected local, reference parameter / const pointer for attemptDamage, reference or
   `register` object local, inline-member/inline-param wrappers (getID, forceinline helper
   taking object as a parameter), `/Oa`, `/Ow` (both reshape the whole body; B still after
   A), `/G5`, `/Ob1`, `/Ob2`. `/G7` reshapes everything.
2. Donor-order hypothesis (amount kept in a local, stored after sourceID) does fix the
   join: with an integer view of the amount and the else arm assigning amount FIRST,
   the join is byte-exact and only the else arm differs (12 diffs) [w/i2.cpp]:
       retail else arm: ld type ecx, st, ld death edx, st, ld amount eax
       i2 else arm:     ld type ecx, ld amount eax, st, ld death edx, st
   The scheduler always fills the load-latency slot with the independent amount load.
   With amount assigned LAST in the else arm (the natural spelling, = donor), the else arm
   rotates to eax/ecx (65 diffs) because a cross-block value never takes a scratch
   rotation turn: unsigned local, Real local under /Op (integer moves, same 65), 4-byte
   struct, inline bitsOf/bitsv/bitsr accessors, temp-then-copy, reference out-param,
   ternary (with comma arms) into a local or an inline-call argument - all identical
   (65) [w/i1, l1-l3, l5_Op, m1-m5, r1-r5, t4, w1, w2]. Retail's arms take exactly three
   turns each (type, death, amount), which only block-local amount temps (the bank's
   per-arm stores, tail-merged) give.
3. So retail = bank arms + bank merge + B scheduled ahead of A; the open question is why
   retail's compiler treated `[edi+0x74]` as independent of the merged store.
