## The destructor is not virtual

No slot routes to the complete destructor (0x609E30) or the scalar
deleting destructor (0x60A130, gen-dtor row). A virtual destructor
must occupy a vtable slot; MSVC provides no virtual-dtor-without-slot.
Therefore `??1Rva006092D0State@@UAE@XZ` is over-claimed: the row
should be `??1Rva006092D0State@@QAE@XZ`. Supporting evidence: no
??_E row exists anywhere for this class, and the dtor body still
restores the vtable (needed for the inherited virtuals during member
destruction) with unchanged bytes either way.

Spread is small: no game/ TU references the UAE name; all retail
callers go through ILT 0x11356 (?j_00011356 -> 0x609E30).
