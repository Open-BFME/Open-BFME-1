# Module-info erase helper contracts

The 97-byte clearAiModuleInfo body at 0x00141770 walks 20-byte elements and
checks the module pointer at +8 through virtual slot +0x10. After an erase it
copies the remaining elements and destroys the last live element. Its actual
record belongs to the already-address-qualified Gen00134590 destruction family,
not the independently compiled ModuleInfo::Nugget destructor specialization.
The 76-byte destructor at 0x00134590 releases string buffers at +4 and +0 and
returns without popping arguments. Three independently matched destroy-range
helpers in Rva00134590Vector.cpp use that same destructor and 20-byte stride.

The copy call at caller +0x32 reaches ILT 0x0000EE03, then body 0x0013EA50.
Caller +0x28..0x37 pushes five cdecl arguments: first, last, destination,
reference to an empty iterator-category tag, and a null distance pointer, then
removes all 20 argument bytes. The complete 105-byte callee reads only the first
three arguments, copies two owning strings at +0/+4, DWORDs at +8/+0x0C and
bytes at +0x10/+0x11, advances by 20 bytes, and returns the advanced destination
with plain ret. The two remaining arguments are unused. BfmeConv1482.cpp already
models this body with three used parameters; that reconstruction does not assert
that the caller passed only three physical arguments.

The address-qualified Rva0013EA50Copy declaration retains the independently
observed five-argument ABI. Its body pin is at 0x0013EA50; thunk routing is
resolved by the existing resolver. No Nugget copy or destructor is pinned to
an unrelated specialization. The corrected caller reproduces all 97 bytes and
both relocations. This repairs an existing failed claim, with zero ledger gain.
