Complete decoding of 0x0089D180 through ret at +0x338 shows no incoming stack arguments and no receiver adjustment. Its direct branches stay in the body; there are no external tail jumps. ## Experiment and refutation

The retry differs from earlier attempts by reconstructing both bounded scan rings and the grow/retry path. The sibling bank 0x0089d180.cpp supplied a source hypothesis, whose loops, argument contracts and tombstone tests were checked against complete decoded retail instructions. Later tombstone visits update the saved index only when a tombstone index has already been saved; the source preserves this condition. No Zero Hour Apt hash donor was found in the searched GeneralsMD tree.

Trials and unedited probe output remain under build/rva0089d5b0/. Trial01 reproduced the scan but had retry and key-store differences. Trial02 used separate native value-store branches; trial03 used that store through an inline receiver helper and reproduced trial02. Trial04 retained the saved tombstone across retries. Trial05 moved the first-slot store outside a while loop. Those alternatives did not recover retail. Trial06 changed key construction to an inline reference helper and recovered the store paths. Trial07 moved the sentinel local initialization before slot calculation and wrote the capacity expression before the hash operand. It matches all target bytes outside relocations; probing the source at its final game path reproduces the same result.

This recovery is refuted by a decoded caller passing a non-wrapper first argument or a different value ABI, a reachable branch outside the proven extent, any actual helper reading or writing fields absent from these declarations, or a strict byte gate resolving a relocation to a different retail target. The original class and method names remain unknown and are retained as address-derived identities.
