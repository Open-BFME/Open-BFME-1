# `lanUpdateSlotList004CAF70` at 0x004CAF70

The 125-byte body at 0x004CAF70 is BFME's version of Zero Hour's `lanUpdateSlotList` (`LanGameOptionsMenu.cpp`). The name keeps its address because that file still holds Zero Hour's own, unmatched `lanUpdateSlotList` definition.

* **Body.** It returns when a gate call returns zero (the shape of `AreSlotListUpdatesEnabled()`) or when a byte flag is set (`s_isIniting`). It then fetches the game through `TheLAN`'s vtable slot +0xC0 (`GetMyGame()`) and makes an eight-argument cdecl call (0x20 bytes popped): the game, four gadget arrays, the accept-button array, one window pointer pushed by value and one more array, which is Zero Hour's `UpdateSlotList( TheLAN->GetMyGame(), comboBoxPlayer, comboBoxColor, comboBoxPlayerTemplate, comboBoxTeam, buttonAccept, buttonStart, buttonMapStartPosition )` with `buttonStart` as the single window. A second three-argument call (0x0C popped) passes the game, the last array and 0, which is `updateMapStartSpots( TheLAN->GetMyGame(), buttonMapStartPosition )` with its default third argument. The one BFME addition is an early path that only sets a flag on an object when one is present.
* **Callers.** The matched `LANAPI::OnAccept` (`game/GameEngine/Source/GameNetwork/LANAPIOnAccept.cpp`, through ILT 0x00039202) and `LANAPI::OnHasMap` (`LANAPIOnHasMap_Bfme.cpp`) call it where Zero Hour's `LANAPICallbacks.cpp` calls `lanUpdateSlotList()`, and `handlePlayerTemplateSelection` (0x004CD820) calls it after changing the slot's template, where Zero Hour calls `lanUpdateSlotList()` too.
