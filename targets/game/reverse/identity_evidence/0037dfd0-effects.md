The source keeps the bank's `rva0037dfd0`, `Rva0037DFD0Container`, `FXEntry`, `fx`, `name`, `begin` and `ocl` names. It uses the canonical Object, FXList and Coord3D declarations. ## Retry hypothesis and measurements

The saved body's register allocation problem can arise from spelling the contiguous range as two raw pointers rather than exposing STLport 4.6's vector accessors. Retail reloads the range through the container and retains an element pointer across the virtual calls. The current tree supplies the landed ExperienceLevel parser and assignment, canonical Object virtual slot 10, canonical FXList signatures and StringBase implementation. These provide independent type and ABI evidence beyond the original bank. Refutation would be a decoded value helper touching different fields, a caller with different argument order, or native vector accessors failing to improve the compiler output.

The reproduced original emits 348 bytes with 225 probe-reported non-relocation differences. Canonical declarations alone emit the same shape. A getLength condition emits 349 bytes with 273 differences. Providing the actual inline isEmpty body with the raw pointer range emits 348 bytes with 299 differences. Keeping that body and using STLport 4.6 vector size and indexing emits all 347 bytes exactly modulo seven relocation slots. The same result was reproduced from the final source path. These are probe diagnostics; acceptance additionally requires the scoped relocation gate.

Each complete candidate and its unedited probe output is retained under `build/rva0037dfd0/`. `00-original.cpp`, `01-canonical.cpp`, `02-length.cpp`, `03-visible-empty.cpp` and `04-native-vector.cpp` preserve the trials. `Rva0037DFD0Effects-probe.log` records the final-path probe. `measurements.jsonl` records the runs. ## Element and ownership evidence

The landed parser source is evidence to check, not a type oracle. Its complete 280-byte retail body at 0x00381A00 obtains the FX pointer into the first local word, constructs the name in the next word, and appends to the range at instance +0x34. It reads finish at +0x38 and capacity at +0x3C, invokes the actual copy helper through ILT 0x0000EBFB when storage is available, and advances finish by eight.

The complete 76-byte helper reached at 0x0037E4A0 copies exactly the source word at +0 into destination +0, then passes source +4 and destination +4 to StringBase<char>'s copy constructor at 0x00887B60. It has no other value-field accesses. Its existing generated pair name is not used as type evidence. The complete 121-byte string constructor copies the one buffer pointer and increments the buffer's reference count when nonnull. The target's inline emptiness check reads the same pointer and an unsigned 16-bit length at buffer +4; str selects buffer +8 or its canonical null character. The complete StringBase implementation and header agree with these accesses.

The complete ExperienceLevel assignment at 0x00381690 independently uses the same +0x34 range, copies the first word and string at +4, destroys elements at an eight-byte stride, and appends through the same copy-helper route. Its destructor ILT 0x00007928 reaches the eight-byte +4 adjustment and tail call to releaseBuffer at 0x0037E1A0. The complete 134-byte releaseBuffer body decrements the buffer reference count, frees a zero-reference buffer and clears the member pointer. Thus only the string owns storage; the first word is a borrowed FX pointer. No allocation-size or donor-name inference is needed.

The copy helper's EH handler at 0x00C1B2F1 names FuncInfo at RVA 0x00E0B730. `eh_map.log` retains its one unwind state, which transitions to -1 through the complete 17-byte cleanup at 0x00C1B2E0. That cleanup calls ILT 0x0002AAA9 with the allocation and placement arguments. Its final target at 0x000607F0 is a one-byte return, retained in `placement_delete.log`; it does not destroy an unconstructed string or release the borrowed FX pointer. The source target constructs only a stack Matrix3D and Coord3D, with no owning temporaries or EH cleanup.

STLport 4.6's `_vector.h` supplies start, finish and end-of-storage pointers and computes size from their difference; `_construct.h` uses placement construction from the source value. These templates agree with the independently decoded parser and copy helper. The target's keyless sequence contains FXEntry values, not map keys or scalar values. Identity remains address-derived even though the data slice agrees with the ExperienceLevel range.
