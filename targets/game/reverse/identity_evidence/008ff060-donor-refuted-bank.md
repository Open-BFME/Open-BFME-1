# Exact masked renderer candidate at RVA 0x008FF060

The proposed Open BFME 2 donor `Code/Libraries/Source/WWVegas/WW3D2/DX8WebBrowser_Is_Browser_Open.cpp` at game.dat 0x00177710 is refuted. Its source constructs a BSTR, loads a COM browser global, checks a browser receiver, and invokes its interface. The complete BFME 1 target instead receives a renderer in ESI, passes a filename and two zero integers to the independently landed water-track texture lookup at 0x0090E910, and passes the resulting handle to the private renderer helper at 0x008FEF60. Compiling the browser donor reproduces its reported 135-byte extent but leaves 78 masked differences against the 144-byte target, with the first divergence at +0x16 and seven misaligned relocation fields. It is a shared exception-frame shape, not a cross-game implementation counterpart.

The BFME 1 target has returns at +0x2A and +0x8F. All conditional branches remain inside its 144-byte extent. It returns bool in AL and leaves both filename and index stack arguments for the caller to remove. The complete callers at 0x008FF0F0, 0x008FF6A0, and 0x008FFF40 were decoded. Calls pass index followed by filename on the stack, preserve the renderer in ESI, remove eight bytes, and consume AL where needed. The actual target call to 0x008FEF60 passes the renderer in ECX, the address of the four-byte texture handle in EBX, and one pushed integer index, then removes four bytes. The complete 244-byte helper reads precisely this contract; its compiler-private convention is reproduced by the same-TU candidate.

The complete 309-byte water-track lookup writes its owned texture pointer to hidden return storage, returns that storage pointer in EAX, and leaves its four pushed words for the caller. It has both null-name and normal return paths. The complete 36-byte Release_Ref body at 0x009EB7A0 decrements a 16-bit reference count at +4 and conditionally tail-jumps through virtual slot +0x20. Ownership is one retained texture reference in the local handle. The target's retail unwind map has one state, 0 to -1, whose action at 0x00C5AC20 addresses EBP-0x10 and routes through ILT 0x00030652 to the 12-byte BfmeHandleCX destructor at 0x0005CC00. The compiled target has the same cleanup offset and state, with its locally defined water-track handle destructor. Both normal cleanup and exceptional cleanup must use this one-pointer ownership contract.

The first complete renderer candidate compiles to 144 bytes with ten masked differences beginning at +0x3A, caused by initializing its result after the texture lookup. Placing `bool result = false` before the lookup reproduces all 144 target bytes outside eight aligned relocation fields, including ESI and EBX argument routing. The same source's 0x008FEF60 helper remains 244 bytes with one different branch displacement at +0x7A: retail JNE at +0x79 reaches +0x85, while the candidate reaches the reload at +0x81.

This is an exact masked target bank, not a verified landing. It includes the helper's existing descriptive names without asserting they are original identities. The helper still conflicts with canonical renderer declarations: the name Mesh_Self for virtual slot +0x14 lacks independent proof; the actual material texture getter returns an owning four-byte handle, whereas `matinfo.h` declares a raw pointer; and the 0x0092C3E0 indirect tail thunk receives two stack arguments despite its existing zero-argument declaration. The target cannot be compiled separately with an external ordinary declaration while retaining the private EBX helper parameter. No new pin or helper ledger row is added, and the assigned scope excludes landing that helper.

The saved candidate is `targets/game/reverse/attempts/0x008ff060.cpp`. Unedited experiments, complete target, helper, caller, texture-lookup and release decodes, and object unwind evidence are under `build/writer-12-donor/`. Reopening is justified by an independently verified canonical contract for the 0x008FEF60 cluster and a byte-verified helper in the same translation unit. Refutation of this bank is a caller that supplies a different filename or index position, a helper that consumes a different register, or an unwind action that destroys something other than the single retained texture pointer.
