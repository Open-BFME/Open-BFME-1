# NetworkDirectConnectInit at 0x004D2700

Retail's FunctionLexicon entry at RVA `0x00EA9A90` contains name pointer
`0x01086AB4` and callback pointer `0x00409E1C`. The first points to the
NUL-terminated string `NetworkDirectConnectInit`; the second reaches ILT thunk
RVA `0x00009E1C`. Its bytes `E9 DF 88 4C 00` jump to body RVA `0x004D2700`.
This directly proves the callback name, rather than inferring it from a Zero
Hour shape twin. The `NetworkDirectConnectShutdown` lexicon entry at
`0x00EA9D4C` routes through thunk `0x00038537` to the already matched
`0x004D2680` body in the same source file.

Retail's `0x004D2700` body has an EH frame, a `0x3C` local allocation, and a
plain `ret` at `+0x531`, so its contiguous extent is 1,330 bytes. Its 24 direct
call targets are all named in the ledger, though those names alone do not prove
each callee ABI. The existing `NetworkDirectConnect.cpp` source emits
`?NetworkDirectConnectInit@@YAXPAVWindowLayout@@PAX@Z`; a real probe compiles
it to 1,285 bytes against the 1,330-byte retail body, with 784 non-relocation
differences and 111 displaced relocation operands. The first structural
difference at `+0x1E` is retail's EBP/ESI/EDI save order versus the source's
EBX/EBP/ESI/EDI. The source is a useful behavioral starting point, not a
verified conversion. The dump row remains address-named until real C++ passes
the byte, relocation and identity gates.

Two bounded source-shape trials did not recover that register schedule.
Volatile writes of the two initial LAN flags compiled byte-identically.
Moving the `ipstr` lifetime earlier emitted 1,276 bytes with 768 non-relocation
differences and 112 displaced relocations, while retaining the same first
divergence. Both trials lived only under `build/`; production source was not
changed.
