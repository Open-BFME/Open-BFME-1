# FX particle category data at VA 0x012F64D8 through 0x012F6508

The twelve FX particle objects in this range are individual four-byte category pointers. The three objects at 0x012F64D8, 0x012F64DC and 0x012F64E0 are `CategoryModuleClassBase<5, 1>::s_defaultModule`, `<6, 1>::s_defaultModule` and `<7, 1>::s_defaultModule`. The nine objects at 0x012F64E8 through 0x012F6508 are `CategoryModuleClass<0>` through `<8>::s_firstList`. They are not arrays or concrete-module singleton pointers. The intervening object at 0x012F64E4 is the separate STLport facet ID documented in `012f64e4-num-put-id.md`.

All twelve objects occupy `.data`. Each has one pointer element, a size of four bytes, and four zero initial bytes. There are no initial pointer relocations. Retail's PE base relocation directory is absent. The raw dump checks every proposed extent against `dir32_addresses.csv` and `data_rows.csv`; no distinct DIR32 address or preexisting data row lies inside any extent. The next named start is four bytes later for each object except the last head, whose next named start is 0x012F684C. The last head's four-byte size is established independently by its reads and stores and the compiler's `sizeof` probe, not by that gap.

Each accessor loads the pointer from its selected slot into EAX and returns. Each default-capable category constructor receives ECX as its receiver and a stack `setDefault` boolean followed by two source string pointers. When the boolean is nonzero it stores its receiver in the default slot. It writes the two strings at receiver offsets 4 and 8, copies the previous head to offset 12, and stores its receiver into the head slot. Category 8 performs the list operation without a default store. The shorter base constructors take a category reference and boolean and conditionally publish the reference in the default slot. These operations establish a category-wide pointer contract independently of a concrete module's constructor.

The concrete constructors independently corroborate the shared head. For example, the box, cylinder, lightning, line, point and sphere emission constructors all read and replace 0x012F64FC while writing the former head into their offset-12 link. The draw modules similarly share 0x012F6500, the emission-velocity modules share 0x012F64F8, and life-event and terrain-collision modules share 0x012F6508. The parser bodies traverse the same heads and compare the object key at offset 4. A head typed as one particular `ConcreteModuleClass` specialization therefore excludes other retail nodes occupying that same list. The three category-default slots are also accessed by generic `getDefault` and category constructors, so their contract is a category pointer even where the current built-in default happens to be one concrete module.

All selected decorated spellings already exist in `dir32_addresses.csv`; they are retained beside the competing spellings, without adding duplicate CSV entries. The competing free `RegistryHead` spellings have no C++ game declarations at the start of this run. The remaining three free `CurrentInstance` spellings occur in `fx_particle_system_bulk.cpp` and their corresponding `getInstance` source, and are replaced by the selected inherited static member. The detailed spelling and declaration census, including declaration lines, is preserved in `build/rlink/identity-15/retail-extra-complete.log` and `spelling-census.log`. Declaration counts establish where to edit, not which identity to choose.

No FX particle category implementation is present in the Zero Hour reference. The decision rests on retail's independent category constructors, accessors, shared lists and parsers, with the existing category spellings. The MSVC spelling `$0A@` encodes zero, while `$00` through `$07` encode integers one through eight. The compiler-size probes reproduce the same decorated objects from the existing header. The source comments that described a numerical category shift have been corrected.

## Correction and refutation

The existing category template definitions remain in `fx_particle_system_category.h`, which is unchanged. Their owning explicit instantiations in `fx_particle_system_category_accessors.cpp` receive twelve verified data rows. The three concrete-default callers refer to `CategoryModuleClass<N>::s_defaultModule`, whose declaration and mangled owner remain `CategoryModuleClassBase<N, 1>`. The existing friendship permits that access; no new inheritance, wrapper, alias identity or shared-header edit is introduced. `extern template` declarations prevent these callers from emitting additional definitions. The raw compiler access probe is `build/rlink/identity-15/protected-access-fixed.log`.

`add-data-012F64D8.log` through `add-data-012F6508.log` and `add-data-fx-zero.log` under `build/rlink/identity-15/` record the compiler-sized, byte-verified registrations. `add-data-fx-initial.log` records the initial mechanical refusal to parse a templated member. `tools/data_rows.py` now decodes the required literal integral and nested type template scopes while continuing to reject private, local and unsupported scopes; it does not infer size from allocation padding. Its compiler and refusal tests are recorded in `data-rows-tests-fixed.log`.

A default accessor referring to a different slot, a category constructor publishing a different receiver contract, a parser traversing another head, a head used as a scalar or concrete-only value, an interior datum boundary, or a changed verified instruction would refute the corresponding address's correction. Each address is gated independently. Source gates, LINKED receipts and any retained blockers are recorded in `build/worker-final.md`.
