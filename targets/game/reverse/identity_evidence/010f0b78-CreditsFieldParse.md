# Credits FieldParse identity

Corrected: VA 0x010F0B78 is CreditsManager::m_creditsFieldParseTable, not ChallengeGenerals::s_fieldParseTable. The existing Credits spelling and public static FieldParse type are retained. The competing ChallengeGenerals table definition is removed and that parser's datum reference is respelled to the Credits table. This does not rename or alter any function row.

Retail has no PE base-relocation directory (`build/rlink/contracts-retail.log`). Here a relocation means a verified pointer field and its compiled COFF DIR32 relocation. FieldParse is the reference structure of four 32-bit fields: token pointer, cdecl parser pointer, userData and destination offset. Retail `INI::initFromINIMulti` at RVA 0x00851910 passes `(INI *, instance, instance + tableOffset + fieldOffset, userData)` and removes the four arguments after the callback at VA 0x00C51A11. Its field lookup helper and MultiIniFieldParse appender provide the record and table contract. `build/rlink/contracts-retail.log` contains the instructions. Table-address consumers pass or return the table; the shared INI routines read it and write the destination instance. No direct table write appears in those measured consumers. The tables lie in retail read-only `.rdata`.

### VA 0x010F0B78: CreditsManager::m_creditsFieldParseTable

The retail datum occupies 160 bytes in `.rdata`. Its complete logical array contains 10 records, including the first all-zero terminator. The initial bytes are `b8 0c 0f 01 60 2a c5 00 00 00 00 00 14 00 00 00`. The full bytes, every record, code references and ILT jump bytes are in `build/rlink/010f0b78-retail.log`. Direct address-reference sites have RVAs 0x0040BFB1, 0x0040BFCE. The next pre-existing named datum is at VA 0x010F0D04; the log also records the bytes immediately after the terminator. There is no pre-existing data row overlapping this extent and no other DIR32 address inside it.

Competing initial spellings: `?m_creditsFieldParseTable@CreditsManager@@2QBUFieldParse@@B` (1 game files), `?s_fieldParseTable@ChallengeGenerals@@1QBUFieldParse@@B` (1 game files). Counts include macro declarations and do not decide identity.

Zero Hour `GameClient/Credits.cpp` defines exactly the nine retail keys: ScrollRate, ScrollRateEveryFrames, ScrollDown, TitleColor, MinorTitleColor, NormalColor, Style, Blank and Text. Its Scroll fields and color destinations match retail offsets 20 through 44. Zero Hour ChallengeGenerals instead declares GeneralPersona0 through GeneralPersona11, which do not occur here. The retail getter at RVA 0x0040BFB0 returns the table; the parser at RVA 0x0040BFC0 reads the singleton at VA 0x012F1260 and passes it with this table to INI::initFromINI.

Blank callback ILT RVA 0x00020C3E has bytes E9 ED C8 3E 00 and reaches RVA 0x0040D530. That callback loads argument two into ECX and tail-jumps through the five-byte ILT at RVA 0x0004800E. The final member constructs and appends an empty credit line. Text callback ILT RVA 0x0002E307 has bytes E9 74 F4 3D 00 and reaches RVA 0x0040D780. Text obtains a quoted token through its INI receiver and passes it to the member on argument two. Those contracts match the named reference callbacks; the extra routes are read in `build/rlink/secondary-retail.log`. The data initializer uses the existing matched spellings `?rva0040D530@@YAXPAXPAVGen_0040D4A0@@@Z` and `?bfmeParseD780@@YAXPAVINI@@PAX1PBX@Z`. The former is cast to the four-argument INIFieldParseProc contract: its cdecl body reads only argument two, and the shared INI caller removes all four arguments. No callback body, wrapper or alias is added.

An attempted pair of descriptive callback routing pins was refused by pin_consistency because the function ledger still carries the above placeholder names. `build/rlink/pin_consistency-postfix.log` records the refusal. Both unlanded pins were removed, preserving the original symbols.csv bytes, and the initializer was changed to the actual matched spellings. The final passing data and pin checks are `build/rlink/build-credits-callback-fix.log` and `pin_consistency-complete.log`. The already-present competing parseChallengeModeDefinition and parseCredits function rows share RVA 0x0040BFC0. Callback body renames and that separate function-identity issue are left for the coordinator; they do not block this datum correction.

The Style dependency at VA 0x010F0B50 is five LookupListRec records, size 40, ending exactly at the Credits table. Its four string/value entries are TITLE=0, MINORTITLE=1, NORMAL=2 and COLUMN=3, followed by a null record. Every byte and string relocation is recorded in `build/rlink/pin-credits.log`. It has no interior DIR32 name or overlapping data row, and is defined as the address-bearing CreditsStyleNames010F0B50 array with its own verified data row. This exposes the reference header's TU-local name table through a placeable definition without editing that header. Verification logs are `add-credits-style.log` and `add-credits.log`.

A pointer that follows an E9 to a different final body, a token or scalar differing from the saved retail bytes, an interior DIR32 or overlapping data row, or a user passing a different record layout would refute this correction. Function bytes must continue matching in every changed source.
