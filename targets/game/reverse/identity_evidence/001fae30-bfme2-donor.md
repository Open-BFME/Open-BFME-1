# 0x001FAE30 native status accessor

The Open BFME 2 donor Code/GameEngine/Source/GameLogic/Object/Update/AIUpdate/Rva0045906E.cpp at game.dat 0x0045906E supplies an inline scalar-status accessor and branch-local calls. BFME 1 instead passes a three-word BitFlags<86> status mask, with bit 53 selected. The mask is status data, not the ten-word model-condition mask. The repository's ObjectStatusBits.h and the matched Object::setStatusBit body provide the native accessor. Replacing direct writes to the old bank's anonymous three-word array with that accessor is the new experiment.

The old bank emits 136 bytes and has 83 masked byte differences starting at +3. The donor's branch structure with the canonical accessor emits exactly 139 bytes with four relocation slots. The final game source also matches, and add_match's strict scoped gate verifies the four direct call relocations. No new STL symbol or pin is needed. ObjectStatusBits.h is included, not edited, and the visible copy of Object::setStatusBit is inline to avoid a second strong definition.

The complete target returns at +0x53 and +0x88, each popping its one four-byte stack argument. The argument is read as a byte; the prior bank's unsigned-byte ABI and address-derived owner name are retained. Its receiver yields an Object pointer at +8. Complete callee decodes show a three-word status mask at Object+0x90 with an 86-bit top-word mask, and setStatus pops a mask reference plus a Boolean stack slot. The paired edge handlers at 0x001C9A10 and 0x001C9AC0 each pop their integer argument. These are the bank's existing actionA and actionB call views; no sequel weapon-set name is claimed.

The indirect call uses Object+0x204, then vtable+0x1FC, which is slot 127. The receiver is unadjusted. It receives one 32-bit value, 8 or 0, and ignores the result. An independent read of the recorded primary AI vtable at VA 0x010BA8A8 resolves slot 127 through ILT VA 0x004289B1 to the matched AIUpdateInterface::chooseLocomotorSet body at RVA 0x00272ED0. Its complete 123-byte decode has two Boolean AL return paths, both with ret 4. The canonical header declares one LocomotorSetType argument. The source's opaque bank names BfmeSink and slot127 are retained, with the now-proven Boolean return width and a same-width argument view. All outgoing conditional branches reach in-body returns or the second arm. The raw vtable calculation, full decode and checked-callee output are retained in slot-check.txt, indirect-retail.txt and indirect-checked.txt. The final scoped gate still matches all 139 bytes after this declaration correction.

Raw probes, complete target and direct callee decodes, declared-function and class checks, and the strict scoped gate are preserved under build/donor-retry/001fae30/. The owner and method remain address-derived. The donor supplies structure, while BFME 1 instructions establish the ABI and status layout.
