# 0x007110B0: receiver ABI correction

The previous address-derived row named a `__stdcall` free function. Its 40-byte body ignores the incoming ECX value and returns with `ret 4`, so that body alone cannot distinguish `__stdcall` from a one-argument `__thiscall` member.

The only direct caller, at 0x006E27E6, loads ECX from global 0x012F8058 immediately before calling the ILT at 0x0003ED6F. The same global is loaded before calls to 0x00711130, whose body reads `[ECX+0x12C]` and returns with `ret 8`. This independently establishes that the global is a receiver for this call family. The one argument remains the existing `Open2Triple*` output type; the owner retains the address-derived Sink006E2540 spelling from the caller bank and its descriptive read method name; no semantic class identity is asserted.

Compiling `Sink006E2540::read(Open2Triple*)` in the original translation unit reproduces all 40 bytes and both relocation sites of retail. Its object bytes and relocation tuples are identical to the old wrapper's, while all eight other defined symbols in that translation unit remain identical. The old decorated name has no source or pin consumers beyond its row and source comment.
