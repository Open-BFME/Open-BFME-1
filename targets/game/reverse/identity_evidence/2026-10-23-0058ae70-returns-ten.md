# 0x0058AE70 is not AudioManager::getFieldParseTable

Retail 0x0058AE70 (6 bytes before int3 padding):

    b8 0a 00 00 00    mov eax, 0Ah
    c3                ret

`AudioManager::getFieldParseTable` returns the address of
`audioSettingsFieldParseTable`; GameAudio.cpp's object emitted
`mov eax, offset _audioSettingsFieldParseTable` with a DIR32 relocation, and the
byte check only passed because it copies DIR32 operands from retail. The body
guard reported it (`static: +1 _audioSettingsFieldParseTable outside the retail
image`): the operand is the constant 10, not an image address.

The only reference to 0x0058AE70 in the image is its incremental-link thunk
0x000204D7 (`jmp`); no REL32 call or jump reaches 0x000204D7 and no dword in
the image holds VA 0x004204D7 or 0x0098AE70, so there is no caller to name it
from. Nothing in the tree references
`?getFieldParseTable@AudioManager@@QBEPBUFieldParse@@XZ` (only GameAudio.obj
defined it).

The old name is retired and the body is claimed under the address-derived
`Rva0058AE70ReturnsTen`, which compiles to the same six bytes.
