# RVA 0x009A8410: address-owned serialized timestamp read

Retail has INT3 immediately before 0x009A8410 and after RET at +0x1C,
confirming the 29-byte extent. There are no calls or relocations in the
body (`callees.py 0x009A8410 29`). It preserves the general registers around
CPUID followed by RDTSC, keeps the low 32 timestamp bits in a local word,
and writes that word through its one stack pointer argument.

Direct callers at RVAs 009A51A9, 009A527E, 009A52D4, 009A52F9, 009A562E,
and 009A5764 pass addresses of output storage. For example, 009A5279 loads
EDX with ESP+2C, 009A527D pushes EDX, and 009A527E calls this body. The
following code does not consume EAX. These sites and the callee's plain
RET support a cdecl output-pointer function; no original semantic name
is claimed. The reconstruction remains Rva009A8410.

## Required hardware assembly

CPUID serialization and reading the hardware timestamp counter cannot be
expressed in portable C++, and this MSVC 7.1 build uses inline assembly for
them. The five-instruction block preserves registers, reads the counter,
and assigns a named C++ local. It contains no prologue, return, hard-coded
stack offset, emitted byte, or naked declaration. All surrounding code,
including the frame and output-pointer store, is generated by the compiler.
The same primitive pattern is already used in the verified nearby
Get_RDTSC_CPU_Speed implementation at 0x009A8430; this does not establish
an original name or ownership for this separate helper.

A new native probe with that minimal assembly block reproduces all 29
retail bytes with zero relocations. Earlier logs reporting an unavoidable
35-byte prologue do not apply to this source: no manual callee-save
prologue is necessary. The two typed calls in the already verified Rva009A5800Forward.cpp are
updated from the retired dump spelling to the recovered function. The
commit hook exposed these dependencies and both callers are reverified.
No header, data row, pin, or other body implementation changes.
All boundaries, instruction semantics, and caller observations were
cross-checked against retail-1.03-unpacked lotrbfme.exe with pefile/Capstone.
