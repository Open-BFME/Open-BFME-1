# Unresolved particle manager identity at VA 0x012F64BC

The datum's storage is conclusive, but its canonical C++ namespace and pointee identity are unresolved. The attempted global-namespace `ParticleSystemManager *TheParticleSystemManager` data row and its two source declaration changes have been removed. All original spellings and pins remain unchanged. No correction for this address is retained.

Retail allocates one mutable four-byte pointer in the zero-filled virtual tail of `.data`. Its initial image value is `00 00 00 00`. The unpacked image has an empty base-relocation directory, and no address is present in this initializer. There is no original data row overlapping this extent and no DIR32 name strictly inside it. The instruction-aligned probe records 121 direct references, including initialization and readers using the value as a member receiver. This is a pointer to a particle manager, not an integer or a table.

At VA 0x004798F5, initialization constructs its subsystem name from VA 0x01076440. Those bytes spell `TheFXParticleSystemManager`. At VA 0x004798FF it passes this slot's address to ILT VA 0x00428777. The five bytes `E9 14 B6 04 00` jump to VA 0x00473D90. The 154-byte initializer loads the slot-address argument into ESI and the object argument into EDI, then stores EDI through ESI at VA 0x00473DB9. It therefore publishes the created FX particle manager into this slot.

The lookup ILT at VA 0x00415267 has bytes `E9 24 4D 5B 00` and ends at VA 0x009C9F90. Its 36-byte body uses ECX as a manager whose template registry starts at receiver offset 0x9C. `functions.csv` names it in the global namespace. However, `symbols.csv` also pins `FXParticleSystem::ParticleSystemManager::createParticleSystem` at ILT RVA 0x0000EBE7, with destination RVA 0x005C3A30. A competing DIR32 spelling uses the namespaced FX manager. Retail also contains the pool-name string `FXParticleSystemManager`. Adapted global-namespace consumer byte matches do not resolve this namespace conflict.

The datum's receiver contract is a pointer to the primary FX manager object. The initializer takes its slot by address and stores the object into it. Template lookup receives the loaded pointer in ECX and a string reference on the stack. The Zero Hour reference declares and defines its legacy global `ParticleSystemManager *TheParticleSystemManager`; it has no declaration establishing the BFME FX manager's namespace or variable spelling.

The complete original spellings and direct declaration counts are recorded in `build/rlink/particle-exact-declaration-counts.txt`. The initial counts in `build/rlink/012F64BC-retail.txt` are basename mentions and are not exact decorated-type declaration counts. The namespaced spelling has no direct game declaration, while the global spelling has many. Count does not decide identity.

An EA declaration or validated name-bearing type record binding the published object's vtable to its exact manager namespace and global spelling would settle the issue. A validated global-namespace type record would refute the namespaced candidate; one naming the FX namespace would refute the legacy global candidate. A green comparison of an adapted caller would not settle this distinction.
