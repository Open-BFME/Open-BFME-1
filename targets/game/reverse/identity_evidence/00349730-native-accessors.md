# ScriptEngine cache insertion at RVA 0x00349730

The reconstruction keeps the bank's symbol `?rva00349730@ScriptEngine@@QAEXPAVObject@@ABVAsciiString@@@Z`. The Zero Hour `ScriptEngine::addObjectToCache` source supplies the named-cache algorithm and diagnostic string, but its one-argument declaration does not describe BFME's two-argument ABI. The address token remains in the method name.

No receiver adjustment occurs at this call site.

## Inline visibility and experiments

The new hypothesis was that the native empty-string accessor and the donor's Object getter chain expose the expression structure missing from the saved body. Retail compares the fallback buffer's unsigned-short length directly to zero, and the diagnostic evaluates `getTemplate()->getName().str()` as an argument rather than staging a local type-name pointer. ## Refutation conditions

This identity and ABI account would be refuted by a decoded caller that uses a different receiver adjustment, argument order, argument representation or virtual-slot route. The container account would be refuted by an actual construction or cleanup helper reading or owning another element field. The semantic recovery would be refuted by a different cleanup action or predecessor state in the emitted unwind map. The real `addObjectToCache` name is not claimed because the independently verified BFME declaration still differs from the Zero Hour declaration.
