# RVA 0x000A1510 transfer body

Baseline: BFME1 v1.03 unpacked SHA256
`1fbdc0ced8f283732c094c4f0804ce8dc1e3e3675b720bcab066c94fed964e75`.

The opaque owner identity is retained. The served StateMachine source-family
and GeneralsMD transfer routine supply behavior hypotheses, supported by the
actual instructions and 20 matched callers through an ILT. EA BFME2's
StateMachine::DoXfer spelling alone does not prove the BFME1 method name.

Boundary: entry at 0x000A1510, complete RET 4 at +0x27D, exclusive end
0x000A1790 followed by INT3 padding. The retail body is exactly 640 bytes.

The body is entered with one thiscall pointer argument. It first dispatches
IsLightCRC at slot 4, then uses version pair {1,2}, chained unsigned transfers
at slot 29 for owner offsets +0x14 and +0x18, and transfers the current state
ID (state pointer +0x1C, ID at state +4, invalid sentinel 999999). Loaded
version >=2 and invalid state return immediately. IsLoading at slot 1 selects
current-state lookup. The all-states branch counts nodes, validates the saved
count and each ID, and dispatches snapshots at slot 12. The non-all branch
heals a missing state through the default ID before snapshot dispatch.

Direct callees and ABI:

- ILT 0x000124D1 -> 0x000A1310 is matched bfmeFrontABB@BfmeHostABB.
  It accepts one four-byte key, passes that argument's address to a range
  lookup at 0x0004833D, and returns the selected RB-node payload at +0x14,
  with RET 4. The old source prototype represents the word as BfmeIterABB
  and returns void*. This caller's constant member-pointer cast correctly
  views the same physical argument as unsigned and the result as a state
  pointer, without inventing another callee identity or adding a pin.
- Native STLport _Rb_global<bool>::_M_increment at 0x0082B870 is used twice.
  Node base layout is canonical; keys are at +0x10 and state payloads +0x14.
- bfmeFormatText at 0x009D6220 accepts (record*, tag, format, ...) by cdecl;
  its body stores pointer at +0 and tag at +4. All three calls here pass
  tag 5 and null format. The exception RTTI from ThrowInfo VA 0x011DFE5C
  names `.?AVXferException@@` and declares an eight-byte object. Explicit
  noreturn stdcall _CxxThrowException matches the no-EH-frame retail call
  shape; existing _g_rva005c5100ThrowInfo names that independently read table.
- ILT 0x0000C9B4 -> 0x0010C3C0 is the matched 25-byte address-derived cdecl
  slot-0x90 forwarder. Its virtual result is left in EAX. This caller uses
  a return-ABI function-pointer cast to Xfer&, preserving the current exact
  mangled provider, following the already source-backed VersionedRecord37A610.
- ILT 0x0001F253 -> 0x0009A510 is GameLogic::findObjectByID(int). The
  canonical Thing/GameLogicObjectLookup.h declaration and TheGameLogic
  global at VA 0x012F0898 are reused.

Tail serialization uses the actual nested returned-Xfer chain. The address
at +0x30 pushed before the inner Coord3D call is the pending outer cdecl
argument, not a second argument to the virtual Coord3D operator. The chain
transfers +0x20, Coord3D +0x24, +0x30, Coord3D +0x34, bools +0x40/+0x41;
boolean +0x42 explicitly returns to the original receiver. Owner ID is
transferred last and optionally resolved on load. Existing canonical Xfer,
Coord3DBase and GameLogic headers are included, not duplicated.

Compiler experiment five reproduced all 640 bytes with 19 relocation slots.
The inline constructed two-byte version preserves canonical Version storage;
its source scope corrected the version/owner-ID stack-slot rotation. The
constant member-pointer ABI view corrected the default-ID register load and
its downstream scratch-register rotation. Strict gate results, not masked
probe similarity, determine integration acceptance.

## Current canonical lookup adoption (2026-10-04)

Upstream 0ff5a4df supplies Rva000A1310StateLookup.h and the sole 63-byte lookup provider at RVA 000A1310. Retail ILT 000124D1 forwards to this thiscall body: unsigned stack key, map receiver at +4, returned node payload at +0x14, RET 4.
