# 0x007110F0: receiver ABI correction

The previous address-derived row named a `__stdcall` free function. Its 50-byte body overwrites ECX before reading it and returns with `ret 4`, which also fits a one-argument `__thiscall` member whose receiver happens to be unused in this body.

All four direct callers at 0x006E2625, 0x006E272B, 0x006E2802 and 0x006E6B63 load ECX from global 0x012F8058 immediately before calling the ILT at 0x00022BB0. At 0x006E6B89 the neighboring caller loads the same global as receiver for 0x00711130, which demonstrably reads `[ECX+0x12C]`. The argument retains the existing `const Open2Triple5*` bit-record type; the owner retains the address-derived Sink006E2540 spelling from the caller bank and the descriptive write method name; no semantic class identity is asserted.

Compiling `Sink006E2540::write(const Open2Triple5*)` in the original translation unit reproduces all 50 bytes and four relocation sites of retail. Its object bytes and relocation tuples are identical to the old wrapper's, while both other defined symbols in that translation unit remain identical. The old decorated name has no source or pin consumers beyond its row.
