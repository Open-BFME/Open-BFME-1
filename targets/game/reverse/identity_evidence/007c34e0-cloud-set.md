An aligned suffix comparison exposed another incorrect operation in the old reconstruction: retail's final ALPHAOP value is three (SELECTARG2), whereas the saved body used MODULATE, value four. `alpha-operation.cpp` corrects this value. Although the unaligned raw difference count stays 273, the aligned suffix removes the incorrect literal comparisons and leaves only the second snapshot load schedule. `suffix-comparison.json` preserves this comparison instead of treating its register-normalized similarity as equality.

The exact remaining blockers are snapshot load schedules at `+0x6A3` and `+0x767`. At the first, retail loads the buffer into EDX, then the character into AL; the retained compiler output loads the character into DL, then the buffer into EAX. Its longer character load shifts the remaining code by one byte. At the second, after correcting that shift for comparison, retail loads the buffer into ECX then the character into DL, whereas ours loads the character into CL then the buffer into EDX. The aligned suffix has seven differing bytes at retail offsets `0x767`, `0x768`, `0x76D`, `0x76E`, `0x76F`, `0x770` and `0x772`; these are additional register and instruction-order differences, not missing target bytes. Reopening requires an independently supported source or inline-accessor visibility change that improves these measured divergences, or new compiler evidence explaining these register assignments. Merely repeating exception flags, swapping the two local declarations, switching the snapshot wrapper or asserting that the shape score is equality does not justify reopening.
