# StateMachine::halt owns the complete 12-byte body at 000A00A0

All addresses below are RVAs unless labelled VA. The original retail image is
`inputs/baselines/bfme1/retail-1.03-unpacked/files/lotrbfme.exe`, SHA256
`1fbdc0ced8f283732c094c4f0804ce8dc1e3e3675b720bcab066c94fed964e75`.

## Native boundary and ABI

The bytes at 000A00A0 are `c6414001c7411c00000000c3`:

- 000A00A0: `mov byte ptr [ecx+40h],1`
- 000A00A4: `mov dword ptr [ecx+1Ch],0`
- 000A00AB: `ret`
- 000A00AC through 000A00AF: CC padding; the following bytes start at 000A00B0.

This is a void no-argument instance method with its receiver in ECX. There are
no calls or relocations within the body. Ghidra's original function range is
VA004A00A0 through VA004A00AB, and `ghidra_functions.csv` independently records
12 bytes. Actual read-only MCP decompilation at the start and at the interior
returns the same full function with both stores. All MCP read-bytes results
were independently compared with the pinned PE.

## Identity and fields

The native StateMachine constructor at 000A1BD0 installs vtable VA01080710.
Slot +3C contains VA00425676, an E9 ILT jump to VA004A00A0. Independently
identified Contester (VA01097310) and Horde (VA01097238) machine tables use the
same slot and entry. The ILT has 24 table references and one original direct
caller: `AIDockMachine::halt` at 0014E660 ends with its tail jump at 0014E685.
That caller first finds the goal object and dock interface, then cancels the
dock for the owner at +10 before invoking this base halt.

The existing constructor, destructor and update-state-machine providers agree
on the current `State *` at +1C. `tools/name_oracle.py --class StateMachine
--offset 0x1c` witnesses `m_currentState`; offset 0x40 witnesses `m_locked`.
GeneralsMD's `Common/StateMachine.cpp`, `StateMachine::halt`, sets the lock and
clears the current state without calling onExit. The native destructor at
000A1130 calls the state's onExit only when the +1C pointer is nonzero. These
independent uses explain why omitting the second store changes behavior.

The established TU-local partial layout is retained, with only its +1C slot
made explicit. The goal object remains at +20 and the lock at +40. No canonical
header, broad StateMachine provider, vtable, or other layout is changed.

## The interior is not UDP::ClearStatus

The deleted row `?dup_000a00a4@@YAXXZ` incorrectly claimed the last eight bytes
using `udp.cpp`'s `?ClearStatus@UDP@@QAEXXZ` object symbol. Actual MCP list_xrefs
at VA004A00A4 returns a symbol-not-found error, which is not evidence of no
references. A separate read-only Ghidra reference-manager query at the exact
address establishes all three facts: no function starts there, its containing
function is VA004A00A0..004A00AB, and getReferencesTo returns no references.

An independent exhaustive scan of all file-backed PE sections finds no
absolute dword pointer to VA004A00A4; scanning every byte of every executable
section finds no E8/E9, near conditional, short jump/conditional, or loop-family
branch candidate targeting it. At VA004A00A0 the same scan finds exactly the
native ILT at VA00425676, agreeing with Ghidra. These checks supplement the
native table/caller chain; they do not claim to enumerate arbitrary computed
branches.

The real UDP row at 006DF1E0 and the separately existing alias at 006846E0 are
both complete eight-byte bodies with their own ILT entrants, respectively
0001611C and 000175A3. Their identical bytes cannot assign UDP identity to an
interior instruction in halt. `tools/one_identity.py` confirms native
incremental linking without identical-COMDAT folding, including 60,965 ILT
entries and hundreds of identical byte patterns retained at distinct bodies.
The old re_attempts.log annotations alleging tail sharing are contradicted by
this original entry/boundary evidence. The UDP source and both unrelated rows
are preserved; only the false interior row is tombstoned.

## Verification and accounting

Reproduce the source gate with `./build.sh
game/GameEngine/Source/Common/StateMachine_getGoalObject.cpp`. The claim is
expanded through supported `add_match.py --replace-existing`, which also
requires a complete compiler extent. Both halt and the unchanged 16-byte
getGoalObject sibling must match. Removed-row impact selection, the UDP
provider, and the original AIDock caller are checked separately with ordinary
strict relocation checks and normal commit guards.

This is a behavioral and ownership repair. The former 4-byte prefix plus
8-byte interior alias already covered the same 12 bytes; it adds no distinct
covered address or claimed byte.
