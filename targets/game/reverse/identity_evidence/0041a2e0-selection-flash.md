# RVA 0x0041A2E0 selection flash

The reconstruction preserves the bank's `Rva0041A2E0::flash(const RGBColor *)` identity and descriptive declarations. It does not introduce a `Drawable::flashAsSelected` pin. The tested base revision is `871e04e61d8563350f71ca698afcd652e9016d94`. Raw decoding, compiler trials and gate output are retained under `build/0041a2e0-run/`.

## Retry hypothesis and measurements

The saved body omitted the STLport marker and the compiler settings used by the landed `Rva00443F60Selection.cpp` horde-list caller. Restoring that environment should recover the one-word list and its frame. An unchanged or worse compiled shape would refute the hypothesis. The saved body was measured first, with only its relative include corrected for the trial directory.

Eight independent trials generated by `eh_levers.py` and evaluated through `shape_search.py` left the 489-byte shape unchanged. The generator did not recognize the constructor declaration. The explicit constructor exception specification removed the allocation cleanup state, consistent with its fully decoded body. A contain local with a conditional expression was rejected at 485 bytes and 299 differing bytes. It inlined list construction and changed loop layout. The retained endpoint avoided repeated list-header loads. Replacing the named half constant with the literal recovered retail's x87 operand order. Assignment in the contain guard removed the extra receiver move. Each trial source and unedited probe output is retained; `measurements.jsonl` indexes the later trials.

Every conditional branch and the jump joining the two tint-play paths targets an instruction inside the extent. The first byte after the final return is `INT3` at RVA `0x0041A4B2`. No tail transfer leaves the function. `checked-target.log` records the checked callee inventory.

## Indirect calls and list payload

The target loads Object from receiver `+0xFC`, passes kind `0x6C` to the decoded kind query, and loads the contain interface from Object `+0x1FC`. The contain-interface virtual call is slot 26 at `+0x68`, with no stack arguments. Retail HordeContain's constructor installs VA `0x010AF048` at owner `+0x20` and VA `0x010AED58` at owner `+0xE4` (`horde-decoded.txt`). Slot 26 of the former routes through ILT `0x00027831` to the complete 17-byte body at `0x00230730`. Both return paths are decoded: it tests `this-0x20`, returns zero if that owner is zero, and otherwise returns `this+0xC4`. This establishes the secondary receiver adjustment.

The returned interface's slot 60 at `+0xF0` routes through ILT `0x00011D24` to RVA `0x002388F0`. Its full 286-byte body is decoded in `horde-decoded.txt`, and its checked inventory is in `checked-horde-fill.log`. It receives the output list pointer as one 32-bit stack argument and ends in `ret 4`. It clears that list, obtains the existing contained list through a no-argument virtual returning its address in EAX, and copies each value. The inline value construction at `+0x65` reads exactly one dword from source-node `+8` and writes exactly one dword to destination-node `+8`. The other append path reads the found object's pointer from hash-node `+8` and writes exactly that pointer to destination-node `+8` at `+0xED`. Neither path reads or writes another payload field. The other node writes are the next and previous pointers at `+0` and `+4`. Allocation size alone is not the payload evidence.

The target itself reads each copied value from node `+8`, checks it for null, and uses it as the ECX receiver of virtual slot 10 (`+0x28`). Object's primary vtable at VA `0x0109EE58` routes that slot through ILT `0x0002074D` to the complete seven-byte `Object::getDrawable` body at `0x001BE440`. That body returns Object `+0x80` in EAX, without receiver adjustment or stack arguments. The result is checked for null and used as the recursive flash receiver. This establishes a list of Object pointers rather than a scalar or pair. `vtable-contain.log`, `vtable-horde.log`, `vtable-object.log`, `routes-decoded.txt` and `checked-drawable-getter.log` retain the independent route and ABI evidence.

## Caller ABI and color representation

`callers-decoded.txt` contains the complete Object::defect body (`0x001D22C0`, 556 bytes), ObjectDefectionHelper::update body (`0x002563E0`, 552 bytes), and SpecialAbilityUpdate::continuePreparation body (`0x002A71E0`, 681 bytes), plus following padding. Their checked inventories are retained separately. The Object caller obtains Drawable from virtual slot 10, moves it unchanged into ECX, and pushes zero before calling ILT `0x0004067E` at `0x001D23E8`. The helper caller pushes a local address whose three dwords are all `0x3F800000` before its call at `0x00256488`; its other call at `0x00256580` pushes zero. The special-ability caller converts the indicator color through RGBColor::setFromInt, saturates that same three-float local, and passes its address at `0x002A7370`. None reads a return value or supplies hidden return storage.

The target passes the color pointer followed by three 32-bit frame arguments to TintEnvelope::play. Its complete callee reads RGBColor's three channels, stores the peak channels at envelope `+0x1C`, `+0x20`, `+0x24`, calls the frame setters, writes sustain state and counter, and returns with `ret 16`. The null-color path reloads receiver `+0xFC`, reads the house-color byte from GlobalData `+0xBF4`, and the saturation float from `+0xBF0`. The subtraction constant at VA `0x0107533C` is represented by the compiler's `__real@3f000000` literal.

## Exception cleanup and ownership

Retail's handler is RVA `0x00C20AC8`; FuncInfo is RVA `0x00E10DEC`. There is one unwind state, `0 -> -1`, with action RVA `0x00C20AC0`. That action computes ECX as `[ebp-0x1C]` and jumps through ILT `0x00018949` to the five-byte list-destructor wrapper at `0x000D0020`. The wrapper jumps through `0x0000E68D` to the complete list-base destructor at `0x000CEBD0`.

`object-audit.log` records the compiled FuncInfo and cleanup. It also has exactly one state, `0 -> -1`; its action computes the same local address and jumps to the emitted list<Object *> destructor wrapper, which tails to the same list-base declaration. That complete destructor follows node `+0` and deallocates nodes without destroying their Object pointees, then releases the sentinel. Normal cleanup calls the same base destructor. The list owns its nodes and retains nonowning Object pointers. There is no constructor-failure deallocator for the nonthrowing envelope construction in either unwind map.

## Refutation and scope

An external branch beyond the decoded target, a caller passing a different argument representation, a slot route with a different receiver adjustment, a value-copy path accessing another payload field, or a different compiled unwind action would refute this recovery. The original bank's opaque method and member names are retained. No shared header or tooling is changed, and no STL-named ledger row or symbol pin is added or modified. The standard name-regression CLI accepts Git revisions rather than file paths in this revision; its `regressions` API was run directly against the old bank and new source and returned no findings (`object-audit.log`).

## Landing checks and collection blocker

`add-match.log` records successful replacement of the dump row through the strict landing tool, including relocation resolution, float-constant validation, DIR32 validation and the body guard. `scoped-gate.log` records a separate successful scoped `build.sh` gate using the final source. `pin-consistency.log`, `declared-unmatched-after.log`, `class-gate-after.log` and `object-audit-final.log` retain passing pin, declaration, canonical-class and bank-name checks. There are no source recoveries outside this assigned address. A full gate is not required because no header, shim, pin or tooling is changed.

The initial `check_csv.py` passed. The final working-tree invocation is blocked because the read-only Git index still lists the bank that `add_match.py` removed; `check-csv-after.log` records its `FileNotFoundError`. This revision's checker derives working-tree source membership from the index, so the untracked new source also requires staging. The coordinator must stage the source, evidence, ledger changes, attempt record and bank deletion, then run `check_csv.py --staged` and the normal hooks. No index write or checker bypass was used. The landing tool also rewrote unrelated hatch-allowance metadata; that automatic change was restored byte-for-byte from the tested base revision and is excluded from the handoff.
