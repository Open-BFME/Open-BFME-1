# RVA 0x005E2C70 destructor

Retail has 139 bytes through `ret` at +0x8A, followed by INT3. The scalar
deleting wrapper at RVA 0x005ECDF0 calls this body via ILT 0x00032AF6,
conditionally calls operator delete for flag bit zero, and returns the saved
receiver with `ret 4`. The reconstruction retains the bank's address-derived
`Rva005E2C70` identity; no canonical EA class name is claimed.

The EH handler at RVA 0x00C3B5D0 references FuncInfo 0x00E2AE00. Its two
states, independently decoded with `tools/eh_info.py`, are:

- State 0 -> -1 calls RVA 0x005DDD60 through ILT 0x00019858 on the saved
  receiver. This already matched 66-byte destructor resets three base
  vtables at receiver offsets 0x18, 0x14, and 0, then unlinks the list node
  at offset 4. Its existing class is `Rva005DDD60`, with a 0x20-byte layout
  defined in `V3MiDtorsWithListNodeWave2.cpp`.
- State 1 -> 0 calls Snapshot's seven-byte destructor at RVA 0x0005C520
  through ILT 0x00001C80 on the saved receiver +0x20. That body only stores
  vtable VA 0x01073744.

The normal path releases a string at +0x24, resets the Snapshot table at
+0x20, then performs the three-base cleanup described above. Representing
the first three bases as the existing `Rva005DDD60` group produces the
observed two saved pointers and state indices; the bank's flattened four
bases incorrectly produced two additional stack slots and unwind states.
The bank's widened third base is replaced by the existing four-byte
`V3Vt107375C` plus the already documented word at `Rva005DDD60::m_v`.

The unlink call uses the existing `GenNode_006fa270::unlink` binding through
ILT 0x00013994 to RVA 0x001DA440. All 81 bytes of that callee were inspected:
it only tests/updates the owner, previous, and next pointers and contains no
call or throw. Declaring that operation `throw()` removes an unnecessary
state reset before the final cleanup and reproduces retail. This is a local
exception contract backed by the complete callee, not an assembly workaround.
The canonical `ascii_string.h` supplies the real string lifetime and
`StringBase<char>::releaseBuffer` declaration at RVA 0x00887940.

`Rva005E2C70StringView` represents the observed string-then-sentinel cleanup
at +0x20. It replaces the bank's unwitnessed descriptive `BfmeStringBaseVUQ`
helper name with an address-derived ABI view. The cleanup ordering and
subobject offsets are established; the original EA source hierarchy is not
asserted. Existing vtable binding names are reused without adding identities.

The strict source gate verifies all 139 bytes, both direct call routes, and
four vtable references. No new pin, shared-header change, generated-source
edit, or assembly is used. All retail instructions and EH references above
were checked against the unpacked BFME1 1.03 image.

The bank-removal checker also pairs its macro parameter `NAME` with
`Rva005DDD60`. This is a false pairing: the latter is the independently
matched EH cleanup identity, not a rename of a source class. Exact snapshot
corrections document this pair and the unwitnessed string-view helper above.
