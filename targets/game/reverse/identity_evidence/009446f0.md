The former `Visibility_Check@RTS3DScene` claim started 96 bytes inside the actual function and covered five other bodies plus padding. Its 1,075 bytes exactly reproduce retail, but neither that boundary nor its semantic identity is valid. There is no symbols.csv pin for the rejected entry/name.

Ghidra and terminal instruction decoding establish the 552/94/473-byte boundaries; the two 8-byte tail jumps and 3-byte accessor have independent CC-delimited starts/ends. The 552-byte method is reached by slot 27 of vtable 0x0113CF48. The SimpleSceneClass constructor installs that table; named RTS2DScene/RTS3DScene constructor calls independently establish the base constructor identity. Its only direct call passes `this+0x34` to the 94-byte vector constructor, which calls the already-matched bounds and level methods. The two forwarding members adjust ECX by the same +0x34 and tail-call those exact methods.

The old range [0x009446F0,0x00944B23) contains 1,042 instruction bytes and 33 CC padding bytes. All 1,042 instruction bytes are retained. The corrected first function adds its previously omitted 96-byte prefix. New function extents total 1,138 bytes: 586 C++ and 552 remaining ASM. Expected ledger deltas are +586 rebuildable/authored bytes and +63 total exact bytes (+96 true-boundary bytes minus 33 padding bytes no longer claimed as functions). Padding is unchanged in the retail image; its claim removal is an accounting correction, not an implementation loss.

The 552-byte function remains ASM because the admissible C++ bank still differs (505/552 bytes, 423 non-relocation differences). This change does not call that body a conversion. Its bank and immutable attempt evidence remain available.
