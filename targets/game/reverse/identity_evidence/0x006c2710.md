# 0x006C2710 is W3DRadar's taint-cell setter, not W3DRadar::setShroudLevel

The Open-BFME5 lift named this 626-byte body `W3DRadar::setShroudLevel` from its
vtable position. The caller pairing refutes that name.

* **Owner.** The body sits in slot 11 (+0x2C, through ILT 0x0002234F) of vtable
  0x0111D7B4. The matched `W3DRadar` constructor 0x006C1D70 and destructor
  0x006C1780 install that table.
* **Pairing.** Two 58-byte forwarders call TheDisplay and then TheRadar with the
  same (x, y, level):
  * 0x001072A0 calls W3DDisplay vslot +0x10C (`W3DDisplay::setShroudLevel`,
    0x006EA600, ILT 0x0000D0DF at 0x0111EDD0+0x10C) and then radar slot 9
    (+0x24), 0x006C23B0.
  * 0x001072F0 calls W3DDisplay vslot +0x118 (`W3DDisplay::setShroudLevel30BC`,
    0x006EA700, ILT 0x0002A1B7, the TaintBuffer variant) and then radar slot 11
    (+0x2C), which is this body.
  The W3DDisplay vtable base is 0x0111EDD0. The matched `W3DDisplay` destructor
  0x006EFC20 installs it.
* **Slot 9 is Zero Hour's setShroudLevel.** 0x006C23B0 reads the W3DShroud at
  terrain +0x30B8 and maps setting 2 to 0xFF, 1 to 0x7F and anything else to 0,
  as Zero Hour's `W3DRadar::setShroudLevel` does. The name belongs there.
* **This body is the taint variant.** It reads the TaintBuffer at terrain +0x30BC
  (targets/game/reverse/identity_evidence/0071a0d0.md). It returns early unless GlobalData
  TaintOn (+0xCF5) is set. It treats its third argument as a byte level: below
  128 it tints from TaintColor (+0xC88), above 128 from ElvenWoodColor (+0xC94),
  and at exactly 128 it writes white with alpha 0. The GlobalData offsets come
  from FieldParse table 0x00C77018 in targets/game/reverse/field_names.csv. The pixels go into
  the radar texture at this+0x14A0.

The method's real name is not recoverable, so the row keeps the proven owner
and the address: `?rva006C2710@W3DRadar@@UAEXHHE@Z`. The byte parameter (`E`)
is what makes the body compile exact: an Int parameter moves the colour temps
to other argument slots.
