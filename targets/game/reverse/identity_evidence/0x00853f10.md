# INI::loadDirectory at 0x00853F10: five-argument BFME ABI

The ledger row carried Zero Hour's four-argument name
`?loadDirectory@INI@@QAEXVAsciiString@@_NW4INILoadType@@PAVXfer@@@Z`, copied with
the Open-BFME5 `__emit` lift. Retail's body ends in `ret 0x14`: five dword
arguments (AsciiString by value, bool, INILoadType, Xfer*, and a fifth dword the
body never reads). The four-argument name cannot produce that epilogue.

The matched callers SubsystemInterface::loadIniFilesFromLegend (0x009A1A50) and
SubsystemInterfaceList::initSubsystem (0x009A20B0) already call this address as
`ini.loadDirectory(dir, true, INI_LOAD_OVERWRITE, xfer, 0)` through
game/GameEngine/Include/Common/INI/INI.h. That call mangles to
`?loadDirectory@INI@@QAEXVAsciiString@@_NW4INILoadType@@PAVXfer@@H@Z`, and the
existing symbols.csv pin resolves it to 0x00853F10.

The method identity comes from the Zero Hour twin
(reference/CnC_Generals_Zero_Hour/GeneralsMD/Code/GameEngine/Source/Common/INI/INI.cpp:217).
It throws on an empty name, lists `*.ini` through TheFileSystem (0x0134CB48) into a
FilenameList, loads the top-level files, then loads the subdirectory files, all
inside try/catch(...) with a rethrow. BFME makes three changes. The throw is an
INIException (0x00850600). The separator concat is guarded by endsWith("\\"). The
second pass runs only when `subdirs` is set.

The replacement is clean C++ in game/GameEngine/Source/Common/INI/INILoadDirectory.cpp.
Probe: 700/700 bytes exact outside relocations, and the compiled symbol continues
through the 9-byte catch funclet at 0x008541CC, which keeps its own row. The row is
renamed to the five-argument name, and the naked lift file is deleted.
