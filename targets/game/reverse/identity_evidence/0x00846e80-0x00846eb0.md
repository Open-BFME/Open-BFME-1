# RVA 0x00846E80 and 0x00846EB0: opaque STLport copy wrappers

Both addresses independently have preceding INT3 padding, a 40-byte body
ending with RET at +0x27, and following INT3 padding. The first direct call
is at 0x00846E9C, the second at 0x00846ECC; their signed REL32 displacements
both resolve directly to 0x00846E00. `tools/callees.py` identifies that
callee as the already matched STLport 4.5.3 `__copy` specialization in
`game/stlport/X4TimeFacets.cpp`:

```cpp
back_insert_iterator<string> __copy<const char *, back_insert_iterator<string>, int>(
    const char *, const char *, back_insert_iterator<string>,
    const random_access_iterator_tag &, int *);
```

Independent decoding of the 124-byte callee confirms `last-first`, a byte
copy loop appending to the string represented by the output iterator, and
two return paths that store the iterator through the hidden first argument
and return that address. This agrees with the native implementation in
`inputs/vendor/stlport/stl/_algobase.h` and the iterator layout in
`stl/_iterator.h`. The callee is referenced by its existing exact decorated
symbol; no pin or provider change is needed.

In each wrapper the original `[esp+4]` is the hidden result pointer, retained
in ESI. The three source arguments occupy the next three slots. The extra
address passed after the null distance-type pointer is a temporary empty
iterator-category tag; VC7.1 reuses the hidden-result-pointer stack home
for this temporary after saving that pointer. It is not a second output
buffer. Returning the native iterator by value reproduces the entire
40-byte sequence, including argument loads, LEA, all six pushes, cleanup,
and result-pointer return.

STLport's `copy`, `__copy_aux`, and related forwarding templates can share
this instruction shape. There is no independent evidence assigning one
exact original template identity to each address. Both functions therefore
retain opaque names `Rva00846E80` and `Rva00846EB0`; neither claims an
additional real name for the existing callee. The first spells the native
`__copy` call explicitly and the second uses native `copy`; their declaration
of the existing specialization preserves its out-of-line retail call.

Verification: separate probes of both complete extents were exact, and
`add_match.py` verifies their actual REL32 bindings and source together.
