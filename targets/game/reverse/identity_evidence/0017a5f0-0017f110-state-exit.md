# Complete state-exit wrappers at 0017A5F0 and 0017F110

Retail PE bytes and Ghidra `read_memory` agree over all 16 bytes at each
entry. Each is a complete 12-byte body: `mov eax,[ecx+1c]`,
`mov byte ptr [eax+40],0`, then `jmp 00029311`, followed by four INT3s.
ILT 00029311 independently decodes to 00172D80, whose complete 189-byte
body consumes ECX, returns with RET 4 at 00172E3A, and is already matched
as AIInternalMoveToStateOnExitShim::onExit(StateExitType). No new callee
identity or pin is introduced. callees.py was run on each full extent;
its E8-only inventory does not enumerate these terminal E9 calls.

The old generated rows j_0017a5f7 and j_0017f117 are the final instructions
of these methods, not independently entered ILT thunks. Their rows are
retired with tombstones; generated files remain untouched.

## Layout and verification

The unmodified native headers emit State::m_machine at +20 and the lock
byte at +34 under this toolchain, whereas both retail entries read +1C
and clear +40. We include the native header for declarations and use
address-qualified local storage views for the BFME access. name_oracle
independently witnesses State+1C=m_machine and StateMachine+40=m_locked.
No shared-header changes, volatile fields, injected instructions or callee
aliases are needed. Both entries must pass full resolved-callee gates;
relocation-masked probe equality alone is not acceptance.
