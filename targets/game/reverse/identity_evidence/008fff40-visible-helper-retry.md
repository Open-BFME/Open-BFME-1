# RVA 0x008FFF40: preserve the improved partial

The complete target candidate is banked under the existing name `?Rva008FFF40@Rva00900FF0@@UAEXXZ`. It emits 889 bytes with two relocation-masked differences at +0x2D6 and +0x2D9. This is a partial, not a landing. The strict relocation gate rejects the unlanded private helper symbols. The renderer declarations still need integration with shared headers. Reopening needs verified same-TU helper definitions and a renderer interface that reproduces the actual virtual slots. A different receiver, stack argument, string element layout or cleanup action in a complete caller would refute the corresponding declaration.

The tested checkout is revision `43c8949f9ac8e2b5da15fe2e3aa232ad4a0640ff`. The verified game image SHA-256 is `1fbdc0ced8f283732c094c4f0804ce8dc1e3e3675b720bcab066c94fed964e75`. Complete decodes, each trial source and unedited probe outputs are retained under `build/008fff40-retry/`. There are no production source, ledger or pin changes in this retry.

## New evidence and measured experiments

The old bank emits 757 bytes with 614 differing bytes in the common extent and omits 132 target bytes. Its estimate of 0.16 was not a current measurement. New evidence is the 0x008FF060 bank that reproduces the private ESI and EBX conventions, and the independently landed 289-byte vector copy constructor at 0x008FFB80 using STLport 4.6. Both source files were read rather than accepted from their descriptions. The tested hypothesis was that complete helper visibility and the actual string lifetime loop would improve the caller. The observation that would refute it was an equal or worse measured caller after those changes.

The complete target decode refutes the old one-call reconstruction. After copying the vectors at +0x10A and +0x118, retail checks the first copied vector at +0x11D. Each iteration calls 0x008FF0F0, conditionally pops and destroys the second vector's last string, then conditionally pops and destroys the first vector's last string. The branch at +0x1C3 returns to +0x130 until the first copy is empty. Restoring this loop with the actual private helpers emits 897 bytes with 145 differences. Direct texture-return temporaries reduce that to 889 bytes with seven differences. Native STLport narrow strings preserve the same seven differences. Restoring the two actual `StringClass` members at +0x14 and +0x18, together with integer texture indices, removes the five differences in the initial virtual name call and leaves two differences.

The best source before banking is `build/008fff40-retry/11-typed-members.cpp`; its complete raw target probe is `11-typed-members-probe.log`. Retail at +0x2D5 loads the second vector's finish into EAX and then loads its last string pointer through EAX. The candidate uses EDX for the first load and EAX for the second. The differing bytes are +0x2D6 and +0x2D9. There is no remaining size difference and all 27 relocation sites align. This masked measurement does not establish the unresolved call targets.

A 13-trial EH search on the reconstructed caller did not improve its seven-difference predecessor. Its sources and raw results are under `build/shape_search/54fd618244714221ac708dd6aea67684/`; the raw search output is `build/008fff40-retry/eh-search-fixed.log`. Changing the name getter and setter from integer to pointer declarations did not improve the seven-difference predecessor. Native string adoption alone did not improve it. Shared renderer header adoption emits 889 bytes with eleven differences against that predecessor, including virtual calls through +0x208 and +0x20C where retail calls +0x1F4 and +0x1F8. This trial is retained as `10-native-renderer-new.cpp` with `10-native-renderer-valid-probe.log`; it is not the preferred bank.

## Extent, identity and data evidence

The target is fully decoded through its return at +0x378; INT3 padding follows. Every conditional branch stays within its 889-byte extent. Its single epilogue restores the exception chain and stack and executes a plain RET, consistent with a void member and no stack arguments. The installed prototype vtable at image VA 0x01139068 has this body in slot 3. The independently landed constructor at 0x009002C0 and destructor at 0x00900FF0 install that vtable. This supports the existing address-derived owner `Rva00900FF0`, not an original production class name. Slot 0 reads the +0x14 string pointer, which this body passes to the renderer's name setter at virtual offset +0x1C.

The complete 0x008FFB80 copy constructor reads the source vector's start and finish, allocates a 12-byte element range and initializes each destination element's three pointers. For every element it reads the source string start and finish, allocates their byte difference plus one, writes destination start, finish and capacity, copies the character range and writes a trailing zero byte at the destination finish. It returns with RET 4 at +0x11E. The complete 0x007556A0 destructor walks the same 12-byte elements and releases each character buffer using its capacity minus start, then releases the vector buffer. These reads and writes establish narrow strings independently of allocation width and alias names. The per-mesh fourth argument reaches 0x008FF6A0 as a 32-bit value and is compared as an integer index against material offset +0x30. The best bank retains the established holder and member names but uses integer elements for this array.

Complete checked callee inventories are retained for the target, 0x008FF0F0, 0x008FF060, 0x008FEF60, 0x008FF6A0, 0x008FFB80, 0x008FF290, 0x008FEB90, 0x0092C3E0 and 0x0094F300. Complete helper decodes are in `retail-decode.log`, `contract-decode.log`, `value-decode.log` and `supporting-decode.log`. The adjacent unsigned-tree donor was read; it is a distinct tree instantiation and does not supply this target's string payload identity.

## Helper ABI and ownership blockers

At the actual target call +0x140, the renderer is in EAX, the first copied vector is in ECX, and the second vector pointer and integer index are caller-cleaned stack words. The complete 181-byte 0x008FF0F0 body consumes exactly these inputs and returns bool in AL. Separate null and empty guards reproduce its full size and private register routing, but leave five scheduling bytes different at +0x2E through +0x32. Compound and positive guards instead emit 189 bytes with 158 differences. The bank does not claim this helper as landed.

The actual 0x008FF060 calls retain the renderer in ESI, push index followed by filename, and remove eight bytes. Its call to 0x008FEF60 passes the renderer in ECX, the local texture pointer's address in EBX and one pushed integer index, then removes four bytes. In the best caller source 0x008FF060 reproduces all 144 bytes outside eight aligned relocations. Its complete 244-byte helper still differs at +0x7A: retail skips the handle reload on the nonzero reference-count branch, while the candidate joins before the reload. The getter reached through ILT 0x000366DD is the complete 36-byte body at 0x007A0340. It reads the table at +0x24, copies one pointer to hidden return storage, increments a 16-bit count at pointee +4 and returns with RET 8. The complete 36-byte texture release decrements that same 16-bit count and conditionally tail-jumps through virtual +0x20. These are one-pointer owning handles, not scalar pointer returns.

The complete 11-byte thunk at 0x0092C3E0 adjusts ECX through member +0xC8 and jumps to the complete 334-byte MeshModel texture replacement body at 0x0094F300. That body reads both forwarded handle pointers, compares texture payloads, routes both through replacement calls and returns with RET 8. This independently confirms two reference arguments despite the existing zero-argument thunk declaration. The bank preserves the earlier descriptive helper names without asserting that `Mesh_Self` is the correct identity of renderer virtual slot +0x14. Canonical `matinfo.h` still declares a raw-pointer getter where this call uses owned hidden return storage. Resolving these declarations and landing the helper cluster exceeds this target-only scope.

## Exception cleanup and verification

The retail unwind map has four states: 0 to -1 destroys the vector at EBP-0x24, 1 to 0 destroys the vector at EBP-0x18, 2 to -1 destroys the handle at EBP-0x28, and 3 to 2 destroys the handle at EBP-0x2C. The complete vector destructor and the 12-byte handle destructor at 0x0005CC00 were decoded, including their normal returns and conditional tail transfers. The compiled best source has those same four predecessor states and cleanup offsets, with vector-destructor relocations for the first pair and handle-destructor relocations for the second pair. Raw retail and object evidence is in `target-eh.log` and `11-object-eh-full.log`.

The ordinary strict check is `11-scoped-gate.log`, which fails on unresolved private-helper and typed 0x008FF6A0 symbols as well as the two byte differences. The early scratch gate wrapper's `scoped-gate.log` only constructed a patch and printed PASS without checking its eligibility; that wrapper was corrected, and `scoped-gate-verified.log` and `11-scoped-gate.log` are the actual failing checks. No pin was invented to resolve them. Pin consistency passes in `pin-consistency.log`. Source name-regression checks and the registered-class gate pass for the best source; the latter does not certify the private renderer declaration against its shared header. The CLI version of `name_regression.py` accepts revisions, not file paths, so the retained source comparison calls its unchanged `regressions` API in `check_names.py`. `find_declared_unmatched.py --fail` refuses the scratch candidate because it has no matched ledger row; this is expected for an unlanded partial, and no whitelist or baseline was changed. No full gate is required for these bank and evidence changes.

The preferred bank was independently reprobed after `re_log.py` wrote it. `banked-probe.log` reproduces 889 bytes with the same two masked differences; its measured ranking score is 0.9978. `banked-scoped-gate.log` repeats the strict rejection. `check_csv-final.log` passes, and `banked-name-regression.log` and `banked-class-gate.log` pass. `banked-declared-unmatched.log` retains the expected refusal for the unlanded target.
