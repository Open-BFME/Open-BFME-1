# ThingTemplate::setReskinnedFrom at 0x00146840

The 72-byte body at 0x00146840 is reached only through ILT 0x00047799, which
reverse/symbols.csv already pins as `?setReskinnedFrom@ThingTemplate@@QAEXPBV1@@Z`.
That ILT has one caller, at 0x00139EA8 inside the shared Object block body
0x00139D00. The call site is `ecx = thingTemplate`, `push reskinTmpl`. It comes
after copyFrom (0x00148600) and setCopiedFromDefault (0x0013FDB0) and before
initFromINIMulti, in the ObjectReskin branch. That is the exact point where Zero
Hour's ThingFactory::parseObjectDefinition calls
`thingTemplate->setReskinnedFrom(reskinTmpl)`.

The body is a thiscall that ends in `ret 4`. It takes the argument's +0x20
AsciiString and appends it to the STLport `vector<AsciiString>` at this+0x2DC.
The in-place path calls `_Construct` through ILT 0x00007554, and the overflow path
calls `_M_insert_overflow` through ILT 0x0003827B. ThingTemplate::isEquivalentTo
(0x0013FE10, matched) reads the +0x2DC name vector at the point where Zero Hour
compares `m_reskinnedFrom`. BFME therefore records the reskin source by name in
that vector rather than by pointer.

The retired name `?bfmePushQV@BfmeOwnerQV@@QAEXPAX@Z` was a guessed shape label
("vector push-back on the embedded vector"). It had no caller or vtable evidence
behind it, and it gave the body a second identity next to the pin. With the
replacement the body keeps one identity, the one its only caller names.

Probe: 72/72 bytes, EXACT apart from the two relocation slots. The replacement
source (Code/GameEngine/Source/Common/Thing/ThingTemplate_setReskinnedFrom.cpp) is
`m_field2DC.push_back(tt->m_nameString)` with STLport's real vector<AsciiString>.
Its callees resolve to the existing `_Construct<AsciiString>` and
`vector<AsciiString>::_M_insert_overflow` pins at 0x00007554 and 0x0003827B.
