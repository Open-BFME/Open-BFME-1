# Identity correction for 0x002E55A0

Lua 4.0.1's `iolib` registration table names this callback `debug`.  In the
retail image, the `debug` entry's function pointer resolves through ILT RVA
0x0000E81D to the 26-byte body at RVA 0x002E55A0.  The component placement
checker independently reaches the same address from the relocation for
`_io_debug` in `liolib.obj`; this is why the pristine upstream implementation
was previously reported as a 139-byte mismatch at 0x002E55A0.

`python3 tools/callees.py 0x002E55A0 26` identifies exactly two calls.  The
first goes through ILT RVA 0x0003EBAD to the game logger at 0x002E5090.  The
second goes through ILT RVA 0x0000630C to the 0x002E5390 Lua debug-console
helper.  Disassembly of its three return paths shows an explicit `xor eax,eax`
on every path.  `_io_debug` returns that value directly as Lua's result count,
giving both functions an `int` result with no adapter or cast.  The same message
and helper call are independently
witnessed by the matched `ObjectSpy` callback's debug-mode branch.

The previous `bfmeGoTGD(int)` name was generated by the Open-BFME5 conversion
pass and described neither the registration-table identity nor the callback's
pointer ABI.  The table relocation and the matched caller prove `_io_debug` and
supersede that guessed name.
