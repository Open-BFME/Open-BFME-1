# Partial reconstruction at RVA 0x0027C250

The complete candidate is banked as `Rva0027C250::method`. It is not an exact recovery and does not replace the generated ledger row. The original class and method identity remain unproven. The authoritative measurements and retained trial sources are in `build/rva0027c250/measurements.json` and `build/rva0027c250/trial*.cpp`; the final candidate is `trial36.cpp`, with unedited probe output in `probe36.log`.

The tested revision is `7e57d1250bba6d13bff31256e201e2422d8aabe2`. The retry hypothesis was that the currently landed Object layout and typed movement, terrain, pathfinding and angle helpers would resolve the earlier ambiguous callee inventory sufficiently to compile a complete receiver-only body. An incompatible decoded call frame, conflicting member offset or failure to improve the measured reconstruction would refute that hypothesis. No saved body existed for this target before the retry.

## Boundary and receiver evidence

The ledger extent is 2669 bytes. The complete target decodes through the return at `+0xA6C`, followed by padding. All direct conditional and unconditional branches remain inside that extent and land on decoded instructions. Its nine return paths return through EAX without callee stack cleanup. There is no target EH frame or tail jump. `build/rva0027c250/boundary-audit.json`, `boundary-audit.log`, `0027c250-decoded.txt` and `0027c250-checked-callees.log` retain these checks.

The complete caller at RVA `0x0027E5A0` passes ECX equal to its secondary receiver minus `0x10`, pushes no target arguments, calls ILT `0x00020FA9`, stores the four-byte EAX result and eventually returns it. The ledger's destructor label is not adopted as identity evidence: the decoded caller has update-result behavior. Its complete decode and checked callee inventory are retained as `0027e5a0-decoded.txt` and `0027e5a0-checked-callees.log`.

The receiver reads its Object pointer at `+8`, state pointer at `+0x30`, path at `+0x140`, extra distance at `+0x168`, surface mask at `+0x1B8`, locomotor at `+0x1CC`, goal discriminator at `+0x1D8` and three goal floats at `+0x1DC`. The canonical Object and Thing headers provide the Object position, angle, model-condition words, containment, AI and physics offsets. The name oracle independently witnesses AIUpdateInterface's `m_path` and `m_curLocomotor` offsets, but does not establish the target's owning class. Names on the opaque receiver describe decoded roles rather than claiming an original declaration.

## Callee and payload evidence

The complete decoded target contains 29 distinct direct call targets. Every direct ILT was followed to its real body. Each real extent has a retained `<rva>-decoded.txt` and `<rva>-checked-callees.log` pair under `build/rva0027c250/`. Named declarations were checked against their actual donor sources, including `AIUpdate.cpp`, `AIUpdateTurretUpdate00273000.cpp`, `Locomotor_query.cpp`, `LocomotorGetMaxTurnRateObject.cpp`, `Locomotor_rva001BC820.cpp`, `PathfinderValidMovementPosition.cpp`, `PathfinderRva003E7B90.cpp`, `AIUpdateBlockedBy.cpp` and the canonical Object and Thing headers. Unknown direct identities retain existing ILT address names; no new pin is needed.

The direct path helper at RVA `0x003FD7D0` consumes Object, locomotor, explicit output pointer and a low-byte Boolean in four stack slots, then returns with `ret 16`. Its complete body initializes and writes every output field: a float at `+0`, position floats at `+4`, `+8` and `+0xC`, a second node-coordinate copy at `+0x10`, `+0x14` and `+0x18`, a four-byte layer at `+0x1C` and a node identifier at `+0x20`. Float arithmetic establishes the distance and coordinate interpretation; the layer and identifier come from the corresponding node fields. This is a 36-byte explicit output record, not hidden return storage or an inferred STL payload. The second coordinate is retained as three opaque float fields. Its field copies and all return paths were inspected rather than inferring a type from allocation size.

The locomotor movement call at RVA `0x001BC820` takes Object, coordinate reference, two float values and a Boolean output pointer, and returns with `ret 20`. Its code ends before its switch table. All nine table entries at RVA `0x001BCA50` were decoded as addresses and checked against instruction boundaries in the code, rather than treating the table as instructions. The path destructor at RVA `0x003FEB80` deletes the node chain at `this+4`; the target subsequently calls operator delete on the path allocation and clears its owning pointer.

The terrain constructor installs primary table VA `0x0111D090`. Slot `+0x1C` reaches ILT `0x00036F4D`, then the landed layer-height body at RVA `0x006BE2A0`. Its complete decode confirms five four-byte stack slots, a low-byte final Boolean, float return and `ret 20`; its existing declaration is const. `terrain-vtable-slot.txt`, `006be2a0-decoded.txt` and `006be2a0-checked-callees.log` retain this independent virtual-call evidence. The candidate uses the const declaration through an opaque vtable view.

Other indirect calls are retained by slot and observed ABI: receiver slots `+0x184` and `+0x18C` return AL; the state receiver at `+0x30` uses slot `+0x10`; containment slot `+0x68` returns a pointer whose slot `+0x174` returns AL; receiver slot `+0x214` has no explicit arguments and its result is unused. The concrete implementations and all possible receiver classes for these remaining virtual calls have not been enumerated. That audit remains a blocker to any exact recovery claim, even if a later byte probe passes.

## Compiler experiments and remaining work

The trials start with the complete decoded control flow, without assembly injection. Moving the path-output record into its branch allows it to share the native matrix lifetime. Corrected strict float comparisons and ordered goal tests improve the measured shape. Adopting the native Matrix3D rotation improves the instruction sequence. Typed inline containment and AI accessors eliminate the extra receiver move and change the float spill allocation, moving the first non-relocation difference beyond the angle branch. A canonical Coord3D snapshot gives the best measured byte score. Compile-time guards verify the candidate's receiver offsets and output-record layout.

Rejected variants include a switch for the goal discriminator, reordered angle local declarations, a two-float angle array, a function-scope angle local, a reference alias for the angle difference, visible noinline copies of the matched angle helpers, coordinate scale and add methods, a generated adjacent-store reversal, scalar versus reference-returning height clamps, reversed snapshot initialization, a native Vector3 snapshot and a const snapshot. The reference-returning height clamp improves its late instruction sequence but enlarges the frame. Native coordinate setters and accessor variants that produced unchanged output are retained as such, not presented as progress. `build/shape_search/1a3bf425763a45feb4e81af606a3c263/result.json` and its raw `probe-*.log` files preserve the bounded generated store experiment. Trial 12 required an include-path correction before its retained successful probe; that initial failed compile output was not retained on disk.

The final probe still differs in coordinate initialization beginning at `+0x42E`, subsequent x87 evaluation and stores, accessor evaluation order, the reference selection used by the height clamp and the resulting branch and relocation layout. The normalized instruction similarity is diagnostic only. The strict scoped byte gate fails, with no unresolved direct symbols reported, in `build/rva0027c250/scoped-gate-final.log`. Pin consistency and the class gate pass; their raw logs are `pin-consistency.log` and `class-gate-final.log`. No ledger row, pin, shared header, generated source or baseline is changed.

Reopening is justified by independent evidence for the position snapshot's native construction and lifetime, or a concrete native inline context that improves the first coordinate-copy divergence. Repeating the unchanged local-order, visible-callee or store-order experiments without new evidence is not justified. A future exact claim also requires the remaining virtual implementation audit and the ordinary landing gates.
