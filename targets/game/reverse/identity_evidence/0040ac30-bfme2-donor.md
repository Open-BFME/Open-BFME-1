The new hypothesis is that native statement structure and the original key's lifetime resolve the exception-frame and register allocation failures. It is refuted as an exact recovery if the register residue or provider ambiguity remains.

The native method has better instruction shape, but is not represented as an exact constructor or silently substituted for one.

Original method spelling and return semantics are not established by a caller. An opaque member is appropriate once the operator authorizes the bank identity correction.

The lookup at `0040A6C0` takes hidden iterator result storage followed by an unsigned key reference. Both complete return paths write one node pointer and clean eight stack bytes. The caller uses the original argument's address. The complete insert at `0040AAD0` routes through `_M_insert` at `0040A920`; that helper reaches value construction through `0001D390` to `0040A240`. The complete construction body reads exactly two source dwords at zero and four and writes the corresponding result fields. Thus the payload is one pointer, not a twelve-byte value inferred from an old generated declaration or allocation padding.

The two target unwind states each free the current allocation from the original first argument's stack home. This matches normal `new Bfme5MaterialPass` expressions, rather than the old placement-new reconstruction. No member referent is destroyed by those cleanup states; the sibling release method owns normal referent release.
