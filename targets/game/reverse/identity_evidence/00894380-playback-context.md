## New hypothesis and measurement

The earlier callee blocker can be narrowed using the current landed container constructor, element copy and release bodies, the holder query in `game/Libraries/Source/Apt/Apt.cpp`, and the callback installer in `BfmeOneHundredTwentyThree.cpp`. These sources were read directly. The hypothesis was that a complete same-TU static definition of the private helper, the actual holder indirection and mutable callback cells would recover the missing calling context. It would be refuted if the complete caller still passed the argument on the stack, if the helper required a receiver, or if the measured target failed to improve over the saved body.

The preferred saved body was compiled first. Its raw result is `build/rva00894380-run/000-probe.log`. The final complete trial is `build/rva00894380-run/040-final-bank.cpp`; its authoritative target metrics are `040-metrics.json`, and its unedited output is `040-target-final-probe.log`. It emits the full retail extent and improves the masked comparison substantially. Its normalized instruction shape is only a diagnostic, not verification. The byte gate still fails; `scoped-gate-final.log` retains the complete target and relocated candidate bytes, including unresolved calls. No pin was added to conceal that failure.

The main improvements came from supplying the real private-helper body with a mutable unsigned parameter, making callback loads come from mutable cells, and advancing the global cursor with `+= strlen(text) + 1`. The last form reproduces the decoded cursor reload and update around string construction. The original bank's owner expression omitted a dereference: retail reads the holder's pointer at +0x122c, dereferences that pointer, then reads the owner's +0x58 value pointer. The corrected expression follows all three loads.

## Boundary, ABI and ownership evidence

`target-disasm.log` decodes the entire target. Its three returns are at target offsets +0x27b, +0x2a8 and +0x2c6. The executable code ends immediately after the last return. A nop follows at +0x2c7, then four jump-table entries occupy +0x2c8 through +0x2d7. Their destinations are the instruction boundaries at +0xb0, +0xb0, +0xcc and +0x12f. `table-boundary.log` retains the raw entries and the following int3 padding before 0x00894660. The dispatch's conditional default reaches +0x169. Ordinary branches remain within the target. The table explains the linear decoder's endpoint warning; the ledger extent must retain it. `checked-target.log` checks the executable extent separately, without treating the table as instructions.

`caller-00894660.log` contains the complete 286-byte caller, and `checked-00894660.log` retains its checked calls. It invokes the target without arguments and discards its result. Both this caller and the target load EAX immediately before calling 0x00892a70. The complete 258-byte helper in `helper-00892a70.log` preserves that incoming EAX value, returns a full EAX integer and uses plain ret. There is no receiver or stack parameter for this private convention. `checked-00892a70.log` identifies every direct target, but its generic inferred convention is superseded by these decoded instructions. The static C++ helper reproduces that argument convention when compiled with its caller. `039-helper-probe.log` records its remaining two instruction-byte differences at +0xa5 and +0xa8. This helper is not an exact recovery and has no new ledger row.

The helper reads the value flags at +4, the output pointer at +0x50, that output's counter at +0x30 and nested pointer at +0x0c, and the nested limit at +0x24. It writes the counter only through the reloaded value and output. Its complete callee 0x008a15f0 reads its sole stack argument with signed `fild` and returns with ret 4; `helper-008a15f0.log` and `checked-008a15f0.log` support the bank's `method(int)` declaration. Other helper calls and receiver adjustments were compared with their current donor declarations. Unknown owner identities remain address-derived.

`helper-008941a0.log` decodes the entire string-list method and all of its return paths. It receives the container in ECX and one pointer to the string wrapper on the stack, with ret 4. The container has count at +0, capacity at +4 and data at +8. This method compares the string's 16-bit length and its text at +8, stores state 3 in the element's +4 field, and passes the constructed pair to 0x00893f10. `container-insert-00893f10.log` shows its actual forward copy target is 0x008926d0, rather than merely a similarly named donor. Its other paths call 0x00892730 and 0x008924b0. Their complete bodies are retained in `item-copy-008926d0-exact.log`, `item-copy-00892730-exact.log` and `item-copy-008924b0.log`, with corresponding `checked-*.log` files. Each reads and writes both fields: a refcounted string handle at +0 and a raw 32-bit state at +4. The state has no independently proved enum or pointer identity. This is a sequential array with string lookup; no tree key or STL specialization is inferred from allocation size. The element constructor and destructor are fully decoded in `item-ctor-00892870.log` and `item-dtor-00892890.log`.

`predicate-00892fd0.log` and `checked-00892fd0.log` establish the complete two-argument predicate, including both ret 8 paths. It caches count times eight and reloads the data pointer for each end comparison. The target inlines equivalent comparisons against states 4 and 2. The bank's volatile qualifiers force those observed reads; there is no independent evidence that the original class declared these members volatile. Its class and member names are retained from the earlier bank, rather than offered as newly identified native declarations. No canonical shared header was found for these opaque views.

The target has one unwind state, covering its local string after construction and during the list call. `target-eh.log` identifies state 0 to -1 and the cleanup at 0x00c56f00, which adjusts ECX to EBP minus 0x3c and tail-jumps to the complete 22-byte release at 0x00891b80. `cleanup-00891b80.log` and `checked-00891b80.log` show the 16-bit reference decrement and the zero-count cdecl free callback through pool +4. `string-0089e680.log` decodes the complete string constructor, including both ret 4 paths, the empty-string retain, all header fields and the text copy. `040-eh-object-final.log` shows that the candidate's single unwind action has the same predecessor and receiver adjustment. `040-cleanup-probe.log` measures the candidate's outlined destructor against that release body with exact masked bytes. The canonical pool global is forward-declared with `BfmeStringPool3AF0`; the bank's existing pool view is used only to access the independently decoded callback slot.

`callback-install-00789440.log` shows that the two callback cells are ordinary writable data, initially set to separate one-byte return stubs. `initial-callback-stubs.log` decodes those stubs and their following padding. The target passes a text pointer to one cell and a record pointer plus a 32-bit byte count to the other, with caller stack cleanup. `insert-008a0700.log` independently confirms the same record cell and two stack arguments. The bank uses the donor's canonical global declarations with typed invocation views. The record physically has two dword stores; the target requests five bytes from it. Dynamic replacement handlers and their result widths are not identified. The caller does not use their results. No new virtual-call declaration is inferred.

## Rejected experiments and remaining work

The bounded EH search retained all eight trials under `build/shape_search/26ef21cfd86842d89e688a1fb28e9fc4/`; none improved the baseline. The bounded family search retained its seven trials under `build/shape_search/fec7192340b64083a84a949a59733005/`; none improved its baseline. Their raw driver output is `eh-search.log` and `family-search.log`. Subsequent experiments changed the actual helper visibility, flag representation, callback declaration, cursor update and container traversal independently. Every numbered source and raw probe remains in the task folder.

The first structural difference now occurs at +0x58: retail calculates its initial end with mov followed by add, while the candidate uses lea. The first loop nevertheless aligns at +0x60. The second traversal repeats this difference at +0x19c and uses different scratch registers, after which the final epilogues are displaced by one byte. The private helper still has the two-byte reload-register residue described above. Direct flag reload and ordinary value-local reload produced the same helper residue; no further unchanged register trial is justified. Generic predicate visibility, iterator wrappers, integer end arithmetic and compound end update did not improve the target. Explicit default dispatch and goto dispatch were worse. The best measured body is retained.

Reopening needs a source or compiler-context explanation for the native traversal's mov/add and register lifetime, or independently justified native array declarations that remove the volatile experiment. Landing additionally needs verified bindings for `?rva008941A0@List00894380@@QAEXABVBfmeStrVKI@@@Z` at 0x008941a0, `?rva00896710@BfmeTracker4310@@QAEXXZ` at 0x00896710, and the private EAX helper call. A standard public cdecl pin is not sufficient evidence for that private convention. No STL row or pin, shared header, tooling or policy was changed.
