## Hypothesis and experiment

The preferred bank already reproduces 77 bytes except the import tail. Its instruction at +0x46 is FF25, an indirect JMP, whereas retail has FF15, an indirect CALL followed by RET at +0x4C. The new hypothesis is that the MSVC 7.1 intrinsic _ReadWriteBarrier after the canonical CoUninitialize call prevents tail-call substitution without emitting another instruction. The observation that would refute it is an unchanged JMP, an additional instruction, or any other byte difference. Earlier recorded empty assembly barriers and compiler-flag changes did not test this intrinsic.

The unchanged bank measures 77 bytes with seven relocation sites and one non-relocation difference at +0x47. The intrinsic trial measures 77 bytes with seven relocation sites and no differences. A separate trial that declares the recorded IAT slot as a typed function pointer still has the one difference and is rejected. The production source adopts SDK GUID, IUnknown and HWND declarations and changes the private BfmeObjECF tag to struct, which uses the already recorded data symbol spelling. Its probe is also exact. The barrier is reconstruction shaping, not evidence that the original source used an intrinsic.

The structural donor is Open BFME 2 donor Code/GameEngine/Source/Common/BfmeConv804.cpp at game.dat 0x00176FA0. Its nested shutdown and release ordering is already represented in the bank. The donor was tested in an earlier run and is not new identity evidence in this run.
