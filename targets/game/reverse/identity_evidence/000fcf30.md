# Opaque record copy construction at 0x000FCF30

The complete 41-byte body copies DWORDs from source offsets 0, 4, and 8 to the
same destination offsets. It then passes source+0x0C to the function at
0x00887B60 with ECX=destination+0x0C, returns the destination, and executes ret 4.
The called 121-byte body copies the source's buffer pointer into the destination
and increments its reference count. It does not release an old destination
buffer. This is the already matched StringBase<char> copy constructor, also
reached by independently matched AsciiString-containing pair constructors at
0x009CE9B0 and 0x009CF180. Canonical AsciiString's inline copy constructor
forwards to that body.

The old MixFileCreator::FileInfoStruct::operator= source instead calls
StringClass::operator=. The full gate fails that call relocation. Assigning a
StringClass pin to the retail string copy constructor would hide the wrong
operation and type. The original enclosing record identity is unknown; neither
its three DWORDs nor adjacency establishes MixFileCreator ownership. The new
Rva000FCF30Record name retains that uncertainty and the address provenance.

The native copy constructor uses three opaque DWORD members and one canonical
AsciiString at +0x0C. Its 41-byte instruction sequence is exact; the scoped gate
also verifies the constructor relocation before landing. It replaces the one
old claim at exactly the same extent, adds no pin, and adds no ledger bytes.
