# Keyboard lookup arrays at VA 0x010FE7E0 and VA 0x010FE828

The retail keyboard compiland contains two independent const lookup arrays. This adds storage under their existing exact COFF names, without proposing another identity or changing any executable instruction or external CODE relocation. Each ordinary C++ declaration is complete for normal compiler sizeof evaluation. The C linkage __identifier definitions allocate those exact existing COFF symbols; there are no linker aliases or locator comments.

## Retail facts and extents

The baseline image SHA-256 is 1fbdc0ced8f283732c094c4f0804ce8dc1e3e3675b720bcab066c94fed964e75. Both arrays lie in .rdata. Each record contains a 32-bit character pointer at offset 0 and a 32-bit integer at offset 4. VA 0x010FE7E0 has eight category records with values 0 through 7, followed by the complete eight-byte null/zero record at VA 0x010FE820. Its logical extent is 72 bytes and ends exactly where the key array begins. VA 0x010FE828 has 86 key token/code records, followed by the complete eight-byte null/zero record at VA 0x010FEAD8. Its logical extent is 696 bytes and ends at VA 0x010FEAE0. Later zeros are excluded. Every pointed-to string including its NUL and every integer code was read from retail. The reference MetaEvent.h CategoryListName and KeyNames tables agree on every token in order, on every compiler-evaluated integer and on their terminators.

The retail image has a stripped base-relocation directory. Initializer pointer targets are established by the stored dwords and complete pointed-to strings, not by the absence of base relocations. The full range scan found no existing datum extent, DIR32 name or symbols.csv pin inside either proposed range. The exact existing g_ spelling for each array occurs in one game file; category access also occurs through the implicit TU-local CategoryListName in KeyboardOptionsMenuPopulateCategoryBox.cpp. The globally owned reference-style CategoryListName and KeyNames in DebugCommandMap.cpp denote different copies at VA 0x0110DE70 and VA 0x0110DEB8 and are not respelled. Literal pointer candidates are additive normal symbols.csv records. No compiler constant receives a data row or DIR32 record.

## Receiver and argument contract

There is no member receiver. KeyboardOptionsMenuSystem at RVA 0x004C9C60 obtains a selected category index, loads both fields with an eight-byte stride from VA 0x010FE7E0, and passes the integer category to fillCommandListBox. Its key search loads the selected MetaMapRec key from offset 8, checks the first name for null, compares each lookup integer at offset 4, advances by eight until the null name, and formats the matched character string. populateCategoryBox at RVA 0x004C90A0 starts at VA 0x010FE7E0, reads the two fields, advances by eight, and stops at VA 0x010FE820 after the eight non-null categories. Its existing local table and function remain unchanged and receive the same scoped gate. Decoded operand searches found these two source consumers and refuted incidental byte matches elsewhere.
