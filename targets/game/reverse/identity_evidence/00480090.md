# GameWindowManager::assignDefaultGadgetLook

The complete retail boundary is `[0x00480090, 0x004827DF)`, 10,063 bytes.
The existing named lift started at 0x004800FC, 108 bytes inside the static
initialization sequence. Retail returns with `ret 12` at 0x004827DC and
INT3 padding starts at 0x004827DF. `lift_extents.csv` independently records
the corrected start and extent. The old 9,955-byte interior claim is retired.

The matched GameWindowManager constructor at 0x00483760 installs vtable
0x010F8B60; the matched W3DGameWindowManager constructor at 0x0078F500
installs 0x01126ED0. Both tables' slot 25 (+0x64) reaches this body through
ILT 0x00010F37. The original GeneralsMD GameWindowManager.cpp method has the
same gadget-style branches, default color initialization, and image names.
The observed ECX receiver and three stack arguments agree with the existing
`assignDefaultGadgetLook(GameWindow *, GameFont *, bool)` identity.

BFME differences recovered in the native body:

- IME text is constructed through `winMakeColor(255, 255, 255, alpha)` and
  its border through `winMakeColor(205, 136, 60, alpha)`. These are calls,
  rather than aliases of the earlier green and blue static colors.
- IME colors are applied after setting the font, before the `assignVisual`
  early return, as well as in the existing gadget branches.
- GlobalLanguage's default font descriptor is at +0xA0. The field-name
  witness identifies `m_defaultWindowFont`; its size and bold fields are
  read at +0xA4 and +0xA8. A local typed view keeps this correction scoped.
- Font lookup is virtual slot 71 (+0x11C). Both manager vtables route that
  slot through ILT 0x0002668E to the independently matched 139-byte
  `winFindFont` at 0x0047A190. Its by-value string, integer size, and Boolean
  arguments are cleaned by `ret 12`. The existing manager shim declares
  this method nonvirtual, so the caller uses a scoped virtual view.
- Font assignment directly calls the existing GameWindow::winSetFont body
  at 0x00478550. Its qualified call preserves that observed dispatch.
- The existing `gamewindow` shim has the witnessed instance-data offset
  +0x30 and inline draw-color offsets. The `gamewindowlist` shim's getters
  are four bytes earlier and left 22 differing displacement bytes.
