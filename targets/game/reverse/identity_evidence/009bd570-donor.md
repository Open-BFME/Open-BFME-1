## Measured code-generation blockers

The new hypothesis was to port the donor's frame with eight-byte alignment and explicit MMX instructions, using `/Z7` to reproduce the saved-original-stack prologue. A wrong prologue or disagreement with the decoded five-argument caller would refute it. Both prologue and ABI were verified. Unlike the SSE donor's 16-byte patterns, BFME 1 writes two dwords per pattern, loads them as qwords and steps eight bytes. Its source-to-destination setup store order also differs from the SSE donor. The frame is 72 bytes, including three 16-byte pattern slots and named scalar slots. Named scalar operands reproduce the same bytes as the raw frame offsets and are used in the final source.

Plain C for every scalar operation with the MMX inner kernel retained emits 213 bytes and differs in 153 bytes. Giving that C body the explicit 72-byte frame fixes the prologue and slot offsets but emits 216 bytes and differs in 154 bytes, first instruction divergence at +0x3A. The remaining differences are field-load scheduling, byte broadcasting, loop update order and branch layout. These are measured code-generation blockers, not an identity claim. The raw probes and complete trials are retained as `small-scalar-c.cpp`, `small-scalar-c-probe.log`, `small-frame-scalar-c.cpp` and `small-frame-scalar-c-probe.log`.

The donor adaptation initially emitted a 48-byte frame. An explicit frame fixes all slot offsets. A trial spelling the padding as LEA ESP,[ESP+0] emits a three-byte instruction and leaves a 231-byte body with 74 differences. The assembler `align 16` directive instead produces retail's four-byte loop padding and the exact 232-byte body. This is an alignment directive, with no emitted opcode bytes. The final integer-argument declaration also reproduces all 232 bytes with zero relocations. Raw final probe and gate are `small-final-probe.log` and `small-add-match.log`. The source and reproducible trial are `game/GameEngine/Source/Common/Rva009BD570.cpp` and `build/vp6-donor-trials/small-final.cpp`.
