## Measurement and hypothesis

The tested revision is `cbcb79d0784092768988547a74ad9640d84a4b42`. The new context includes the landed 777-byte inner terrain query, its complete 24-byte result constructor and 103-byte candidate helper, and existing declarations for the root filter and position setter. The hypothesis was that accurate callee types and lexical lifetimes would permit the status mask to reuse the completed query's storage. It would be refuted if those measured forms left the additional status-mask slot and the first divergent frame reservation unchanged.

The candidate has fourteen relocation sites that do not align with retail operands, so the masked difference count is not a proof of corresponding instructions or resolved calls. The scoped gate fails for both bodies. Its raw resolved comparison reports 231 differing bytes for the original and 223 for the improved candidate within the retail extent; their emitted tails add six and four bytes respectively. The original also has an unresolved `bfmeSetPositionTP` spelling with a record parameter. The corrected candidate uses the existing `BfmePosTP` declaration and has no unresolved symbols.

The first difference remains the frame immediate at target +0x17: retail reserves 0x58 and every successful tested lifetime form reserves 0x64. Relative to the EH frame base, the query and wanted mask start at -0x5C and the kind filter starts at -0x44 in both builds. Retail puts the status mask on the query's first twelve bytes and the root filter at -0x64. The compiler listing instead puts the status mask at -0x68 and the root filter at -0x70. The extra slot, rather than an incorrect query size, explains the displaced ESP operands. An empty query destructor did not change this allocation.

## Retail evidence

The complete target decodes from 0x001AA5B0 to the exclusive endpoint 0x001AA71F. Its two return instructions are at target +0xE5 and +0x16C and both clean four argument bytes. All conditional jumps stay inside the extent. The checked inventory has seven direct callees. Every ILT route was decoded, including the caller route 0x00034CA2 and the query route 0x00023448. Raw evidence is in `build/aa5b0-retry/retail-primary.txt`, `retail-routes.txt` and the `checked-*.txt` files.

The complete matched FireSpreadUpdate caller has an instruction-aligned call at 0x002929E7. It loads TheTerrainLogic into ECX, pushes the point returned by the terrain wrapper and consumes EAX as an Object receiver. This one complete caller supports a thiscall receiver, one pointer argument, a pointer-width return and RET4. The target forwards that pointer as a Coord3D position. The bank's descriptive `TerrainLogicFireSpreadHelper::resolve` and record parameter are retained descriptors, not newly proved EA names.

The inner query consumes five stack slots and ends with RET20; its final slot is a full Int compared with both one and two, rather than a Bool. Its candidate helper reads both coordinates used for distance, the candidate tag and every copied position word. It writes position at +0/+4/+8, tag at +0xC, float score at +0x10 and the borrowed candidate pointer at +0x14. Its constructor initializes those six fields, including 10000000.0f. The query's record stride is 0x30, with occupied/tag at +0xC, constraint bytes at +0x18/+0x2C/+0x2D and next index at +0x2E. These observations establish the local layout without inferring a container payload from allocation size.

The filter constructor at 0x000C3DD0 copies every dword of both 24-byte arguments into +0x8..+0x1C and +0x20..+0x34 after the vptr and next link. The target sets the 0x00200000 bit at mask offset +0x8, which is bit 85, and passes the zero mask as the other argument. It calls link on the kind filter with the root filter as its argument, then passes the kind filter as the closest-query head. The original bank's bit 117 and reversed link are contradicted by the decoded instructions.

The root vtable's predicate route reaches 0x001DCD70, which returns the negated low bit from Object +0x344. Its table is the existing `Rva0025ED50RootFilter` table at 0x01083B80; the existing Flammable table resolves to a different table. This proves the predicate and table route while retaining an address-derived owner. The two complete EH destructors at 0x000C3E50 and 0x000C3E80 are seven-byte base-vptr stores with no member destruction. The target's unwind map has kind state zero followed by root state one, with cleanup offsets -0x44 and -0x64. The deleting wrappers were also decoded; their flag-one branches call delete and their return paths clean four bytes. Target unwind cleanup uses the complete destructors, without deleting flags. No ownership assumption is needed for the copied masks or borrowed query pointer.

The factory and closest wrapper each consume four argument slots and return EAX. The position setter consumes two slots and retains the object receiver. Terrain record clearing ends with an indirect tail call through terrain-visual slot +0x88, forwarding the saved key. All those full bodies and their exits are retained in `retail-helpers.txt`. The full Object constructor additionally shows the actual status payload copy: offsets +0/+4/+8 of its second argument are copied into Object +0x90/+0x94/+0x98. The forwarding hub's private six-word BitFlags declaration is not evidence of that payload size. The actual copy is retained in `retail-object-and-deleting.txt`; the existing BitFlags<86> spelling is preserved, not independently derived from a padding or allocation count.
