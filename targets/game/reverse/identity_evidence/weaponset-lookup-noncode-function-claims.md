# WeaponSet Lookup is data, not executable function evidence

The ordinary-function section guard in 323ec7c273 independently rejects these
claims. They all use the same static `Lookup` object from WeaponSet.cpp:
COFF `.data`, characteristics 0xC0301040, twenty zero bytes and five DIR32
relocations to the Nothing/Firing/Betweening/Reloading/PreAttack arrays.
Every byte was previously substituted from retail through those relocations.
The old verifier therefore reported concrete=20 and equality for arbitrary
twenty-byte retail instruction sequences. This is not function evidence.

For the primary claim at RVA0013D150, both Ghidra and the unpacked 1.03 image
contain `8B 01 C3`, thirteen `CC` padding bytes, then `8B 41 04 C3`:
two independent accessor bodies plus alignment, not a Lookup array/function.
The generated aliases claim unrelated retail code through the identical data
symbol; their exact primary bytes and proper identities need separate recovery.

AGENTS.md requires matched rows backed by real source and byte verification.
Its generated-row rule requires byte-true placeholders, not relocation-based
fabrications. These rows fail both requirements. This transaction removes only
the owned, still-unchanged false claims and tombstones each name/RVA pair.
It does not change the legitimate source data, invent replacement identities,
or grow a baseline. The remaining WeaponSet functions are reverified normally.

The full affected family has 244 rows / 4880 raw claimed bytes (one authored
claim and 243 generated aliases). This transaction retires 244 rows.
