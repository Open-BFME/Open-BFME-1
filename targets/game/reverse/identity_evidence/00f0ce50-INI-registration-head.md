# INI registration head at VA 0x0130CE50

The datum is one zero-initialized `BlockParse *` (four bytes) in retail `.data`. It is a pointer to the first dynamically registered parsing node, not a parse table stored at this address. The chosen established spelling is `?theBlockParseList@@3PAUBlockParse@@A`. Its native definition already exists in `game/GameEngine/Source/Common/INI/ini.cpp`; this correction adds its verified data row and changes the two remaining opaque head declarations to that spelling. All existing pins and DIR32 rows are retained.

Retail's matched BlockParse constructor at RVA 0x0007BCA0 loads the head, stores it at receiver offset 0, stores its two arguments at offsets 4 and 8, and replaces the head with the receiver. The matched lookup at RVA 0x00850820 loads the head, compares the token string at node offset 4, follows the next pointer at offset 0, and returns the parsing callback at offset 8. These independently establish the twelve-byte node's next pointer, token pointer, and callback fields. Static registration writers, including RVA 0x00C6B180 and RVA 0x00C6E180, copy the same head into the first word of their own nodes before installing those nodes as the new head.

The receiver contract belongs to the BlockParse constructor's twelve-byte node. The datum itself has no receiver and contains only one four-byte pointer. The Zero Hour reference's `INI.cpp` uses the same parsing-token and callback roles in its two-field static BlockParse table. BFME's extra linked-list word is directly proven by retail; the reference does not prove an unchanged table representation or an original BFME lexical global name. The chosen role-describing name and type are already carried by the matched native constructor and lookup, rather than newly invented.

Initial bytes are `00 00 00 00`, with no initial relocation. There is no other data row or DIR32 name strictly inside the four-byte extent. The next DIR32 datum begins at VA 0x0130CE58; the four-byte gap is not part of this pointer. A retail walker using a different head or different node offsets, or a changed byte in any respelled registration function, would refute the correction.

Before the correction, the chosen spelling is declared or defined in three game files, `?bfmeRva0130CE50RegistrationHead@@3PAXA` in one, and an additional unpinned `?g_bfmeRva0130CE50Head@@3PAXA` in one. All five consumers now use the same head identity. Registration-node globals keep their existing spellings and addresses.

Raw evidence is in `build/rlink/identity-types-1791203017/0130CE50-retail.txt`, `retail-bodies.txt`, `retail-summary.json`, `game-hits.txt`, `registration-consumers.txt`, and the registration gate receipts recorded in `build/worker-final.md`. The chosen DIR32 row already exists, so no duplicate row or alias is added.
