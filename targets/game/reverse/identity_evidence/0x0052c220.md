# RVA 0x0052C220 identity correction

The old truncated `??1MultiPlayerLoadScreen@@` lift is not a destructor.
The retail body starts by testing this+0x264 == 1 and finishes with a plain RET
without writing a vtable or invoking a base destructor. It iterates eight game
slots and writes four PlayerTable cells per occupied player; its string keys
include Team:%d and GUI:PlayerAlive/Dead/Observer/Gone/ObserverGone.

The independently matched constructor at RVA 0x0052C660 in
`game/GameEngine/Source/GameClient/GUI/AptScreenFactories.cpp` installs
BfmeAptScreenObjectivesVftable (VA 0x01106DEC), registers both
AptObjectivesMenu and AptPlayerStatus callbacks, and places m_players at
+0x258, m_screenType at +0x264, m_playerControls at +0x268 and
m_playerSlots at +0x288. The target appends player colors to +0x258 and
writes slot indices to +0x288. Its sole caller RVA 0x0052C640 (BfmeConv447.cpp)
tests the same +0x264 field then calls this body through ILT RVA 0x0003FE5E.
The already matched MultiPlayerLoadScreen destructor is in
MultiPlayerLoadScreenConstructor.cpp and uses the unrelated load-screen layout.

The owning class is therefore the constructor-identified BfmeAptScreenObjectives.
The method name remains rva0052C220 because no original name is proven.
The boundary is 844 bytes: retail RVA 0x0052C220 through RET at 0x0052C56B.

Callee RVA 0x0052B540 takes ECX plus three stack arguments (row, column,
const UnicodeString reference), builds PlayerTable:%d:%d and returns with RET 12.
All four call sites set ECX=this. Existing BfmePlayerTableZG.cpp provides the
same body under a stdcall view; this target preserves the witnessed member ABI.
