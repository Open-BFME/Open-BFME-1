## Explicitly approved protected-provider experiment

Before editing, the experiment supervisor approved exactly THREE sites to
TWO protected provider symbols, correcting an initial two-site count:

- Gen_00248BE0 -> `?xfer@GarrisonContain@@MAEXPAVXfer@@@Z`;
- Gen_002B5250 and Gen_002C1740 ->
  `?DoXfer@AIUpdateInterface@@MAEXAAVXfer@@@Z`.

The existing protected COFF names are declared as external symbol references,
not defined, aliased or given new identities. Each existing opaque caller uses
a local member-pointer union with its existing receiver class and the actual
Xfer pointer/reference argument. A local compile-time array assertion requires
sizeof(member pointer) == sizeof(code pointer). The compiler emits I386 COFF;
these are four-byte single-code-pointer representations. Writing the raw
pointer initializes the complete union representation, with no uninitialized
adjustment word. There is no invented inheritance, public facade,
protected/public macro, shared class copy, assembly, helper function, or new
pin. The source comment explains why this temporary ABI call view is needed.
This bounded experiment does not authorize spreading the idiom to other sites.

Independent retail instruction checks for EACH protected site:

- 00248BE0+23 calls EAA7. Entry PUSH ECX / PUSH ESI makes
  MOV ESI,[ESP+0C] read the incoming argument at entryESP+4. The unchanged
  receiver is saved by MOV EDI,ECX before the version virtual call. The direct
  call's immediate setup is PUSH ESI / MOV ECX,EDI, with no adjustment.
- 002B5250+0A calls43441. Entry PUSH ESI / MOV ESI,[ESP+8] reads the incoming
  argument. PUSH EDI / PUSH ESI / MOV EDI,ECX does not change ECX before the
  direct call, so its receiver is the original entry receiver.
- 002C1740+23 calls43441. It independently has the same checked incoming
  argument load and saved-receiver restoration as00248BE0; neither receiver
  identity nor offsets are inferred from sharing the target name.
