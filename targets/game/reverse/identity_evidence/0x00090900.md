# Body at 0x00090900 is the OptionPreferences ideal static game detail getter

The 87-byte body at 0x00090900 was lifted as a naked `__emit` copy named
`?useCameraInReplays@OptionPreferences@@QAE_NXZ`. That name was wrong.

- The body builds an AsciiString from the literal `IdealStaticGameLOD` (0x01076CD0),
  looks it up in the preference map at this+4, and returns the int -1 when the key is
  missing. A bool getter would not do that.
- On a hit it passes the found value to `GameLODManager::getStaticGameLODIndex`
  (ILT 0x000245A0) on `TheGameLODManager`.
- Its neighbours at 0x00090970 and 0x00090A00 are getStaticGameDetail and
  getFixedStaticGameDetail, with the same shape and the keys `StaticGameLOD` and
  `FixedStaticGameLOD`. The key `IdealStaticGameLOD` names the third member of that
  family, as in the Zero Hour OptionsMenu.cpp.

The ledger row named getIdealStaticGameDetail at 0x0007E0F0 (942 bytes) is a different
body. A banked verdict identifies it as GameLODManager::findStaticLODLevel, because a
matched caller (ScoreScreen_populatePlayerInfo) reaches it through ILT 0x0002DE02 by
that name.

Probe: 87/87 bytes, exact outside relocations.

The name getIdealStaticGameDetail stays on the 0x0007E0F0 row until that lift is converted,
because the ledger allows one address per name. This body lands under the address-derived
method `OptionPreferences::rva00090900IdealStaticGameDetail`.
