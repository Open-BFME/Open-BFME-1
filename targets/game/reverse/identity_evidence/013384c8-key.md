# Opaque Apt emit key at VA 0x013384C8

The decorated identity `?key013384C8@@3HA` (C `int key013384C8`) owns four
bytes at VA 0x013384C8 in retail `.data`. Retail holds 0 there: the VA is past
`.data` raw_end (0x012EE000) in the zero-filled virtual tail (virtual size
ends at 0x01358000), so the loader semantics the data gate checks
(`reloc_ledger.Image.read`) return zeros. (Raw file bytes past raw_end are
not mapped and must be ignored.)

## Retail facts and contract

`key013384C8` is an opaque cookie used only by address. Its sole retail code
reference comes from `BfmeB1236Emit.cpp`:

- `return m_table != 0 ? (AptValue *)m_table->bfmeFind1024((int)&key013384C8)
  : 0;` — passes `&key` (as an int) as the lookup key.

The value is never read; only the address is taken. The 4-byte size follows
from the `int` declaration, which the C compiler emits as `?key013384C8@@3HA`.

## Extent and all users

4 bytes at VA 0x013384C8. Only 0x013384C8 and its sibling 0x013384C0
(`key013384C0`, rowed separately) are referenced by game/ code; neighboring
slots stay unclaimed.

Defined in place in `game/Libraries/Source/Apt/BfmeB1236Emit.cpp` (its sole
