That was a genuine shared-type qualification: exact pointer-only bodies did not prove the complete class ABI. Original `png_create_struct` at `0x00AABE80` allocates INFO `0x40` and PNG `0x19c`. The shared, D3DX-only `D3DXPngConfig.h` now configures the existing canonical headers identically in Trans and Get; neither `png.h` nor `pngconf.h` is edited, copied or replaced. Both TUs contain compile-time native-size guards; the old published configuration fails both INFO and PNG guards with C2118, not an include failure.

The whole original archive was inspected, not just a selected link map: 228 members and 143 defined PNG external-function records, distinguishing positive section definitions from undefined references. The omitted text/time/significant-bit/chunk features have no corresponding getter/setter/handler publics; `png_set_sRGB_gAMA_and_cHRM` existing does not imply a separate cHRM setter.
