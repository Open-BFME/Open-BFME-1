The stock library is `inputs/vendor/d3dx9/d3dx9.lib`, SHA-256 `9496d4ce606998c2ad7588f2db9aada3c59786515244482230fde0cd6099ed56`. Its `obj/i386/pngget.obj` member is `4a79660c767620e78642a2c3c4f846b9510de28926c6fda8a6f28dd53aca1beb`. It defines nine NODUPLICATES functions, all existing attached-library rows, at `0x00A644E6..0x00A64718` (562 bytes). There is no named static datum. The source is adapted from official libpng `v1.0.5`, tag `860ab2b1c02759c61efb5d63d2b07bd0d484a4c4`, `pngget.c` SHA-256 `4847af5fd97acf61d1f698d023d5dc7f34875dadf8a3420a4d029d70a80953e2`; the retained license is in `LibPNG/png.h`.

The previously published Trans source at `5d9c42eb8e9ab0d06bab68bb834f095777d00f2c` used canonical types whose INFO/PNG sizes were `0xb8/0x1f0`. That was a genuine shared-type qualification: exact pointer-only bodies did not prove the complete class ABI. Original `png_create_struct` at `0x00AABE80` allocates INFO `0x40` and PNG `0x19c`. The shared, D3DX-only `D3DXPngConfig.h` configures the canonical headers identically in Trans and Get. `pngconf.h` is unchanged. `png.h` gains only a configurable callback-convention annotation; its empty default preserves the existing non-D3DX compiler convention, while this profile explicitly selects cdecl. No structure is copied or replaced. Both TUs contain compile-time native-size guards; the old published configuration fails both INFO and PNG guards with C2118, not an include failure.

The whole original archive was inspected, not just a selected link map: 228 members and 143 defined PNG external-function records, distinguishing positive section definitions from undefined references. The omitted text/time/significant-bit/chunk features have no corresponding getter/setter/handler publics; `png_set_sRGB_gAMA_and_cHRM` existing does not imply a separate cHRM setter. Stdio/RFC1123, progressive, user-transform and RGB-to-gray APIs investigated are absent archive-wide. Conversely `png_set_flush` and `png_write_flush` are defined: disabling flush merely to fit a size would be wrong. Supported upstream feature macros are used, not invented fields or padding.

Compiler-only probes include each actual production CPP separately, without command-line feature overrides. Both produce INFO/PNG/row sizes `0x40/0x19c/0x0c`, alignment 4, and identical measured fields. Native operands independently corroborate `flush_dist=0x124` (not the callback pointer), `shift=0x155`, `empty_plte_permitted=0x198`, and INFO `trans=0x30`, `trans_values=0x34`. The original error/read/write/status setter signatures encode cdecl callback pointers (`P6A`), and native `png_warning` pops both callback arguments after its indirect call. A uniform `/Gz` initially made the source typedefs stdcall (`P6G`): size checks and these 17 function bodies did not catch that additional mismatch. The `PNG_CALLBACK` annotation now selects cdecl only for D3DX PNG callbacks; API functions and nested zlib allocation callbacks remain stdcall (`_d3dx_zcalloc@12`). A second negative retains correct sizes but omits the callback selection: only the callback-type guard fails. This and the native function bytes/relocations below establish the used contracts; sizes alone are not the proof.
