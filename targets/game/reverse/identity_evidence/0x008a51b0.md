# 0x008A51B0 is Apt Math.random

The retail BFME executable directly wires VA `0x00CA51B0` (RVA `0x008A51B0`) into the Apt native callback constructor at RVA `0x008A6B29`, storing callback slot `0x0F` (`mov [esp+8], 0x0F` at `0x008A6B1F`). At RVA `0x008A6ABB` the immediately preceding constructor wires known `aptMathPow` RVA `0x008A5160` into slot `0x0E`.

The retail name/index table at executable file offset `0xED53C8` maps ASCII `pow` at VA `0x01136628` to ordinal `15`, and at `0xED53F8` maps ASCII `random` at VA `0x01119DD8` to ordinal `16`. These ordinals are consistently one-based relative to the constructor's slots (`pow` 14 and `random` 15). The same table maps `sqrt` to ordinal `17`, following the random callback. Retail at RVA `0x008C22EE` also loads the exact `random` string literal into the Apt string registration sequence. Thus the formerly banked descriptive `aptMathRandom` name is independently confirmed. The provisional `Rva008A51B0Random` matched claim was introduced only while proving byte shape; this correction preserves the established and independently verified name.

The retired bank already declared the exact helper `Rva008A4EA0MakeFloat(float)` independently of its local `float f`. The new source retains that helper declaration and directly passes the expression instead of keeping a rounded intermediate `f`; a token-alignment check mistakenly pairs removal of `f` with the retained helper symbol. No helper or owning method was renamed to a placeholder. This evidence also documents that false-positive pair for the snapshot-qualified name correction.
