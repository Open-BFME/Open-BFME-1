# RVA 0x0013C2D0 vector destructor

Retail spans 227 bytes through `ret` at +0xE2 followed by INT3. The matched
ModelConditionInfo destructor at RVA 0x0013C3F0 and the matched
`Gen_t_00776240_p128pod` destructor call this body via ILT 0x0003FFD0 for a
vector subobject. The begin/end iteration, 20-byte element stride, and
STLport capacity-to-byte conversion followed by its 128-byte allocation
threshold independently identify vector destruction. The existing bank's
address-derived `Rva0013C2D0Record` remains opaque: no EA element name is
claimed.

The EH handler at RVA 0x00C037A0 references FuncInfo 0x00DF1D80. Independent
decoding against the unpacked retail image gives:

- State 0 -> -1 calls RVA 0x0013B0B0 through ILT 0x00001C6C on the saved
  vector receiver. Its already matched 65-byte body releases storage using
  the same 20-byte capacity scale and allocator threshold.
- State 1 -> 0 calls RVA 0x0013AD20 through ILT 0x00024EEC on the saved
  element pointer. This complete eight-byte helper adds 0x0C to ECX and
  tail-jumps to canonical `StringBase<char>::releaseBuffer`, RVA 0x00887940.

The source therefore represents the string-bearing portion as
`Rva0013AD20View`, followed by the pointer at element offset 0x10 in the
derived record. This expresses the observed element-level cleanup boundary;
it does not assert the original EA inheritance hierarchy. The old bank put
the string directly in the element and incorrectly attributed its register
allocation and missing loop alignment to an immutable compiler limitation.
Using the real `ascii_string.h` and this cleanup view yields the retail
EBP receiver, EDI end pointer, and nine-byte loop alignment sequence.

The element's explicit cleanup tests its pointer, decrements the signed count
at referent +0x28, and invokes slot zero on referent +0x24 with argument 1
when the resulting count is nonpositive. A small inline decrement accessor
and its enclosing cleanup view recover the observed EDX-to-EAX result copy.
The helper names retain instruction addresses (0x0013C322 and 0x0013C31C);
they describe inlined source views, not additional standalone retail claims.
The virtual operation is called `slot00`: the bank's `deleteInstance` spelling
had no independent name witness and is not promoted to an EA method identity.

The real STLport vector/allocator headers emit the destructor. All three
direct call targets agree with `tools/callees.py`: string release at
0x00887940, operator delete at 0x00881EB0, and node allocator deallocation
at 0x0082E5F0. Strict source verification matches all 227 bytes with existing
relocation bindings. No new pin, shared-header edit, generated-source edit,
volatile field, manual alignment, or assembly is used.
