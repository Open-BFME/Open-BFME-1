# AudioEventInfoRef assignment at RVA 0x000AFA60

The existing row `?dup_000afa60@@YAXXZ` uses the generic 73-byte retained-pointer
assignment in `Rva00087750Assign.cpp`. This address is the audio-info instance
of that operation; its identity follows from independently matched producers.

* `AudioManager::newAudioEventInfo` at RVA `0x006AE710` returns
  `AudioEventInfoRef`; see `AudioManagerNewAudioEventInfo.cpp`. Its slot is
  `+0x110` in the AudioManager table. `findAudioEventInfo` at `0x006AEA10`
  returns the same type through slot `+0x118`; see
  `AudioManagerFindAudioEventInfo.cpp` and its table/Zero Hour evidence.
* The MusicTrack parser, independently named by INI registry row VA
  `0x012A829C`, calls slot `+0x110` with a hidden four-byte result pointer,
  passes that returned object's address to ILT `0x00046970`, and then releases
  the returned temporary. The ILT is a single jump to `0x000AFA60`.
* The target at `0x000AFA60` compares the two handle addresses, increments
  the incoming object's count at `+4`, releases the previous object through
  its deleting destructor when its decremented count is nonpositive, copies
  the incoming pointer, returns the receiver in EAX, and ends in `ret 4`.
  That is copy assignment of the returned owning handle, not a constructor.
* The visible `AudioEventInfoRef::operator=` in
  `INIAudioDefinitionParsers.cpp` independently reproduces all 73 bytes
  modulo its two CRT import relocations. Keeping that body visible without
  inlining also lets the compiler prove the parser's local handle does not
  escape and reproduce retail's exception-frame slot reuse.

The source uses an address-labelled audio-info layout view; this identity
claim is for the one-pointer handle assignment, not an invented base class.
The pin at ILT `0x00046970` records `route=0x000AFA60` separately from the
73-byte body address.
