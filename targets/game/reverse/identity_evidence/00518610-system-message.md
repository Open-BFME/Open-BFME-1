## Retry hypothesis and measurements

The earlier bank's register-allocation diagnosis did not account for its incorrect switch semantics. Retail's two `DEC EDI` instructions branch on zero, proving cases 1 and 2; the bank instead compares the decremented value against 0x4014 and 0x4013. Retail returns 1 for recognized messages even when a gadget comparison fails, and invokes the state setter with null when the selected game is absent. The hypothesis was that correcting the complete control flow would also restore the argument-home reuse and register allocation. It would have been refuted by unchanged or worse measured bytes at the verified 367-byte extent.

The saved bank reproduced 349 bytes, 225 non-relocation differences and nine shifted relocation sites, first differing at `+0x3C`. `01-correct-switch.cpp` emitted 367 bytes with zero differences outside 12 relocation slots. A canonical-declaration trial with an incorrectly calculated layout gap had exactly four wrong field displacements; correcting the gap from 0x40 to 0x44 restored zero differences. Canonical forwarding views and correct virtual-slot declarations retained the same exact shape. No register-order search or assembly workaround was needed. The unchanged trial sources and raw probe outputs are retained in `build/00518610-retry/`, including `00-bank-raw-probe.log`, `01-switch-raw-probe.log`, `02-canonical-probe.log`, `03-canonical-layout-probe.log`, `04-named-views-probe.log` and `final-source-probe.log`.

The identity claim would be refuted by a different primary-table installation or a different decoded slot-2 route. The calling convention would be refuted by different argument order or cleanup in the complete manager, dispatch helper or target. The lookup pin would be refuted by a different decoded ILT destination, output representation or return cleanup. The byte recovery requires the ordinary scoped byte gate, including relocation target validation; probe equality alone is insufficient.
