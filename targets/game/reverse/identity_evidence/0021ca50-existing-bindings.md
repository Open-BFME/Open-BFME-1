# Existing bindings for 0x0021CA50

The reconstruction is tested against revision `bda2b4843ea50fba8af39c67fdc7cb97373e0243` and its retail baseline. The hypothesis is that the bank's complete pointer-map operation can call the already recorded unsigned tree helper and the actual intermediate jump body without new identity pins. A different complete value-copy contract, receiver adjustment, return-storage convention, name regression or strict byte mismatch would refute this route. The supplied donor README contains finishing instructions and held BFME 1 sources, but no Open BFME 2 source file or game.dat address for this target. No donor identity or verbatim cross-game relationship is asserted.

## Complete boundaries and calling conventions

`build/stl-b2-writer4/21-retail.log` decodes all 626 target bytes. Its only normal return is at +0x271 and the extent ends at 0x0021CCC2. Every conditional destination is inside the extent, and there is no tail jump or local exception-registration frame. `21-checked-target.log` retains the independent checked call inventory. The receiver remains in ECX, the operation has no stack arguments, and the primary vtable entry makes no receiver adjustment.

The named ContestableContain constructor at 0x0021BEE0 installs vtable 0x010AB3C0. Slot 1 reaches 0x0021CA50 through ILT 0x0002D0E2. The complete constructor, slot and thunk decodes are in `21-retail.log`, `21-vtable.log` and `21-exception-decode.log`. The semantic method spelling is unproved, so the bank's `Rva0021CA50::method` identity remains address-derived. `21-oracle-target.log` reports CONTRADICTED when that invented spelling is tested as a vendor name. It is a placeholder, exempt under the existing ILT guard's tier rule, and is not claimed as EA's spelling.

The first direct call targets ILT 0x00031DC2, which jumps to the separately recorded jump body at 0x00248C40. The remaining route is 0x00038C12 to 0x0021DCA0 to 0x0002ECC1 to 0x00225960. Every hop preserves ECX. The complete 249-byte final operation includes its normal return and trailing nonreturning throw path. The source names the existing `j_00248c40` body through a niladic member-pointer ABI view; it does not bind a new method at a thunk or collapse those separately recorded jump bodies. The strict gate reproduces the original first call operand.

The indirect call at target +0xA5 uses primary vtable slot 0x5C, passing an Object pointer and two zero boolean slots. Vtable slot 23 reaches the complete 200-byte operation at 0x002264F0 through ILT 0x00004160. Its argument accesses and `ret 0x0C` agree with the retained `addOrRemoveObjFromWorld(Object *, bool, bool)` declaration. Its virtual and indirect calls are visible in the complete decode, independently of the direct-call inventory.

## Values, lists and tree ABI

The actual insertion route is ILT 0x0000EE2B to 0x0021BE20, ILT 0x0004499F to 0x0021B600 and ILT 0x0002292B to 0x0021AAA0. All three complete bodies are decoded in `21-retail.log`. The 29-byte value helper reads and writes all three words at offsets 0, 4 and 8. The target obtains the first two words from complete GameLogic object-ID lookups and zeros the count byte in the last word. The complete recount at 0x0021B960 reads the target pointer at node+0x14 and updates the count byte at node+0x18. Unsigned node-key comparison occurs at node+0x10. This supports the native Object pointer key and pointer-plus-count payload independently of allocation size or template names.

The existing `Rva0021BE20Value` represents the payload as eight opaque bytes. The source retains `ContestableMapEntry`, `m_object`, `m_count` and every other banked descriptive identifier, then passes their decoded representation to the existing unsigned tree instantiation. The tree stores a twelve-byte value after its sixteen-byte node header. Both insertion return paths fill caller-provided iterator/bool storage and clean eight stack bytes. The complete four-argument node insertion uses hidden iterator storage and `ret 0x14`; the complete value copy is cdecl with destination followed by source reference. The payload remains byte-for-byte represented; there is no scalar-value inference from a node allocation size.

The pending list reads one ID at node+8; the records list reads IDs at node+8 and node+12. The active list stores Object pointers. The canonical `GameLogicObjectLookup.h` is included and its authentic inline implementation is retained. All three lookup returns, buckets at +0xB4/+0xB8 and hash-node value at +8 are decoded in `21-retail.log`. The allocator and deallocator are complete 162-byte and 85-byte cdecl bodies in `21-allocator-full-decode.log`, with their complete checked inventories. Earlier trial logs requested truncated allocator extents; those are rejected experiments, superseded by these full decodes.

## Exceptions and measured experiments

This target is not a constructor and has no local EH cleanup map to reconstruct; the owner constructor is evidence only and is unchanged.
