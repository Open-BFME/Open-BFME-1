# Address-derived callback at RVA 0x003E5B80

## Identity and boundary

The already matched 478-byte cell walker at RVA 0x003E8440 is
`Pathfinder::iterateCellsAlongLine(..., Rva003E5A50Info *)` in
`PathfinderIterateCellsAlongLineCallbacks.cpp`. Its compiled callback operand
names `?rva003e5b80@Rva003E5A50Info@@QAEHPAVPathfindCell@@0HH@Z`.
The existing symbol pin points to ILT 0x0001B5B8, whose jump reaches
0x003E5B80. The walker passes its payload in ECX and four arguments on the
stack: previous cell, current cell, X, and Y. Retail returns an Int and uses
`ret 0x10`. The matched world-space lineClear forwarder in
`PathfinderLineQueries.cpp` independently uses the same payload type.

The original matched `?d_003e5b80@@YAXXZ` row in
`game/gen_asm/d_003dd7a0.asm` records a 224-byte body at 0x003E5B80.
Its final instruction is `ret 0x10` at +0xDD, ending exactly at +0xE0.
All 224 retail bytes match the reconstruction after resolving its three
existing callee operands. The old bank's `GroundPathPassableStruct` and
`groundPathPassableCallback` names were hypotheses; this conversion keeps
only the address-derived name proved by the matched caller.

## Native layout and typed calls

The reconstruction includes the existing retail
`inputs/reference/shims/pathfind/GameLogic/AIPathfind.h`. Its PathfindCell is
16 bytes, with type bits 0..2 and layer bits 6..11 in the dword at +0x0C.
The shipped Zero Hour cell has a different eight-byte layout and cannot
replace this retail header. ICoord2D and Pathfinder also come from that
header. No existing layout or API is replaced.

The payload's reads and writes directly prove these offsets: Pathfinder
pointer +0x00, Object pointer +0x04, current coordinate +0x08, layer +0x10,
byte guard +0x34, dword guard +0x38, query coordinate +0x3C, validity argument
block +0x44, and incremented integer +0x50. Other bytes remain unnamed.
The address-derived fields and views avoid giving unproved meanings to the
bank's old member names. `name_oracle.py` reports no witnessed layout for
Rva003E5A50Info at +0x50.

The three existing address-derived callee declarations added to Pathfinder
are independently used by the already matched 0x003E5820 and 0x003E5950
callbacks. Their signatures are ECX=this, a Bool result tested in AL, and
these argument lists:

| Existing callee | Retail call operand | ILT route | Arguments |
|---|---|---|---|
| bfmeStepE0930 | +0x3A | 0x00024299 -> 0x003E0930 | Object *, ICoord2D *, ICoord2D * |
| bfmeStepE05B0 | +0x56 | 0x0004A980 -> 0x003E05B0 | Object *, ICoord2D * |
| bfmeStepD4F90 | +0xD0 | 0x0002B9E0 -> 0x003D4F90 | void *, PathfindCell * |

The corresponding retail bodies have proven extents 938, 715, and 158 bytes.
`pin_consistency.py --symbol` accepts all three existing routes. No pin or
callee identity is added. The header change supplies only these declarations
and an Object forward declaration; it changes no fields or layout.

## Compiler shape and verification

The 0.94 bank differed because MSVC 7.1 merged two identical return-one
blocks. Retail has separate epilogues at +0x42 and +0x5E, and both later
guards branch to +0x42. The already exact 0x003E5950 sibling uses distinct
_WriteBarrier and _ReadWriteBarrier intrinsics to retain those epilogues.
Applying the same zero-instruction lever produces all 224 bytes here.
There is no assembly body, emitted instruction, runtime call, or relocation
for either intrinsic.

The scoped gate verifies 17/17 rows across the new callback, its eight cell
walkers, world-space queries, and the 203-byte sibling. The official header
include graph conservatively reaches 61 ledger TUs; the normal full header
gate is required before publication. The historical ae75 link index refuses
to preview the new source's unknown link position. Its old queue's 4,302-byte
caller projection is not a fresh closure measurement.

## Exact source-name corrections

The 0x003E5B80 bank explicitly carried a speculative ground-path callback
identity. The independently matched walker and world-space forwarder name
Rva003E5A50Info, so they refute GroundPathPassableStruct ownership and the
bank's groundPathPassableCallback method name. The bank's TCheckMovementInfo
and semantic field labels were inherited hypotheses, without a shipped
payload declaration or witnessed native member names. The replacement retains
the actual Object and Pathfinder pointer types and coordinate/layer operations;
it names only the proven member offsets. The integer at +0x38 is tested for
nonzero, not counted here; the +0x50 integer is incremented, without evidence
that its native name or semantic identity is hitCount. The opaque argument
blocks and byte guard likewise retain their exact offsets and operations.

The checker also aligns the separate 0x003E5A50 constructor bank with this
0x003E5B80 callback because their payload names share an address prefix.
That constructor and its source remain unchanged at a different RVA. Its
Team and BfmeSubBIA declarations concern Object controlling-player lookups;
they are not the callback's coordinate and validity argument blocks. Matching
those tokens to Rva003E5A50InfoAt3C/At08 is a false source pairing. Similarly,
Object is not renamed to Rva003E5A50InfoAt44: Object remains declared in the
adopted header and is the unchanged type of the +0x04 pointer. The constructor
bank's m_radius at +0x14 is not the callback's +0x44 validity block. Exact
old/new snapshot hashes and identifier pairs in name_corrections.json close
only these reviewed mappings; they do not authorize other renames or alter
any guard.
