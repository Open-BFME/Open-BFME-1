# Lua state parameter identity at RVA 0x00990210

The 62-byte matched body in `game/GameEngine/Source/Common/Rva00990210RecordLookup.cpp` takes a `lua_State *` and a signed index and returns an unsigned value. `targets/game/reverse/symbols.csv:12847` already pins `?Rva00990210Lookup@@YAIPAUlua_State@@H@Z` to RVA 0x00990210 with a reviewed state-layout and cdecl-argument note. The prior spelling `?Rva00990210Lookup@@YAIPAURva00990210Range@@H@Z` gives the same state pointer an opaque type. The sibling correction at RVA 0x00990030 is recorded in commit `36c57c2146c2c8dea78aa4571592be4b7dd172e9`.

Retail loads the index from `[esp+8]` and the state from `[esp+4]`. For a nonnegative index it reads the pointer at state offset 0x10, computes `Cbase + 16 * (index - 1)`, and rejects a slot at or above the pointer at offset 0. For a negative index it reads the pointer at offset 0 and computes `top + 16 * index`. A null slot or a slot with tag 1 returns zero. Tag 6 returns the unsigned word at slot offset 8. Other tags return one. All returns are plain `ret`, and callers remove the two stack arguments. This is a cdecl free-function contract, with no ECX receiver.

The Lua 4.0.1 declaration in `game/Libraries/Source/Lua/lstate.h:46` places `top` first, followed by `stack`, `stack_last`, `stacksize`, and `Cbase`. On retail's 32-bit ABI these put the two accessed fields at offsets 0x00 and 0x10. `game/Libraries/Source/Lua/lapi.c:42` and `:54` use exactly the observed positive and negative index rules. `game/Libraries/Source/Lua/lua.h:25` records the library version and `:70` identifies tag 1 as nil. Retail `lua_gettop` at RVA 0x0098FDD0 independently reads offsets 0 and 0x10 and divides their difference by 16. The local `lua_State` ABI slice names only the fields this lookup reads; the record type retains its address-derived name.

The matched retail `ObjectHideSubObject` caller at RVA 0x002E5D40 loads its state argument into ESI at offset 0x17. It pushes that ESI for `lua_gettop` at RVA 0x002E5D5D, the sibling lookup at 0x002E5D71, `lua_type` at 0x002E5D82, `lua_tostring` at 0x002E5DA4, and this lookup at 0x002E5DC7 with index 3. `ObjectHideSubObjectPermanently` at RVA 0x002E5E40 has the same contract at the corresponding addresses 0x100 bytes later. The five-byte calls at 0x002E5DC7 (`e8 44 a4 6a 00`) and 0x002E5EC7 (`e8 44 a3 6a 00`) target VA 0x00D90210, which is RVA 0x00990210. The body starts with `8b 44 24 08 85`, not an ILT jump. A scan of every five-byte E9 candidate in retail's .text finds no predecessor that targets either lookup, so these witnessed routes are direct. The route probe also records direct calls from the four sources already declaring the pinned spelling.

Before correction, `git grep -n Rva00990210Lookup -- game` finds the old parameter spelling declared or defined in three game files (the provider and the two hide-subobject callbacks) and the pinned parameter spelling declared in four game files. The reviewed pin and retail state contract decide the spelling independently of these counts. The correction respells the provider and those two callers, removes their unused `Rva00990210Range` declarations and casts, and tombstones the old ledger identity. It adds no pin or datum and preserves the body extent, field offsets, slot stride, and return contract.

A caller passing a different pointer from its Lua API state, a call or E9 chain resolving to another body, a state field at a different offset, a slot stride other than 16, an argument contract other than the witnessed cdecl pair, or any changed instruction byte would refute the correction. The before and after COFF probes compare all bytes of each of the three touched rows and permit only the lookup spelling to change in the callers' relocation names.
