# Typed lookup retry at 0x00077CE0

The retained body is a partial reconstruction under the existing name `Rva00077ce0::apply(int)`. It is not a verified source recovery. No function row or callee pin is changed. The retained native declarations require STL symbols whose addition is paused pending the STLport header transition.

## Hypothesis and refutation

The current landed singleton accessors, one-word output helpers and integer-key tree searches permit typed C++ calls instead of the bank's inline assembly call plumbing. The target's receiver spill, repeated local loads and switch snapshot support testing `/Od` instead of the saved `/O2` profile. A complete typed body that fails to improve the original bank at the independently checked retail extent refutes this retry hypothesis. Improved probes support the narrower claim that this removes substantial plumbing and optimization drift; they do not establish a match.

The immediate address neighbours `0x00077C70` and `0x00077E90` still have dump rows at the tested revision. The brief's claim that both immediate neighbours were authored C++ is refuted. The usable landed sources are `BfmeTreeSingletonYN.cpp`, `BfmeTreeSingletonYK.cpp`, `Rva72510ValueCopy.cpp`, `Rva724F0ValueCopy.cpp`, the tree-search donor in `GameClient/System/Image.cpp` and the insertion sources under `WWVegas/WWLib`. Their source bodies were read directly. The helper names in the generator inventory were not treated as type evidence.

## Boundary and ABI evidence

The complete target occupies `[0x00077CE0,0x00077E33)`. Its sole return is `ret 4` at `0x00077E30`; preceding and following bytes are INT3 padding. Every conditional branch stays inside this extent and reaches the shared marker and epilogue. The body has no tail jump, indirect call or exception registration. ECX is stored at `[ebp-0x40]` and never subsequently read. The one incoming four-byte argument at `[ebp+8]` is passed by address to both searches. The source preserves the saved bank's member signature; the original owner and method name remain unknown.

The reported caller `0x0007AC77` is a tail fragment, not a complete entry. Decoding the enclosing body from `0x00079060` through `0x0007ACFA` establishes the instruction boundary of the actual call at `0x0007ACE2`. It follows `push 0x36` and `lea ecx,[ebp+0xB]`, where a byte local was initialized to zero. The caller reads no EAX result before its epilogue. This establishes one stack argument and an unused return at this observed site (n=1). It supplies no original class identity. Catch entries and shared continuation code are included in the enclosing decode; no caller ledger boundary was edited.

Every ILT route in the target was decoded. The singleton routes terminate at `0x000779E0` and `0x000777D0`, whose complete accessors return their respective static object addresses in EAX without stack arguments. The target passes no receiver adjustment. The lookup wrappers at `0x000762B0` and `0x00075E80` each forward a hidden output pointer and a key reference to the complete searches at `0x00072D70` and `0x00072730`, then return the output pointer and execute `ret 8`. Each search writes exactly one node pointer through that output, returns it in EAX and has two fully decoded `ret 8` paths. This refutes the generated `hash_map<int,...>::equal_range` model, which promises a pair of hash iterators. No paused STL ledger identity was corrected.

The complete output helpers at `0x00072510` and `0x000724F0` copy the receiver's first word through the caller's output pointer, return that pointer in EAX and execute `ret 4`. The native `end()` hypothesis uses the equivalent member aggregate-return ABI. Equality at `0x00061B60` and inequality at `0x00064370` each read one node pointer from both iterator objects, return a boolean and execute `ret 4`. The target zero-extends AL before testing it. Its first test proceeds when the first lookup equals its sentinel; its second proceeds when the second lookup differs from its sentinel. The old bank's commentary described both as successful finds, which is incorrect.

The dereference helper at `0x0006B540` reads the node pointer from the iterator and returns node plus `0x10` with plain `ret`. The actual value-copy helper at `0x0006C5E0` reads source words at `+0` and `+4`, writes destination words at `+0` and `+4`, returns the destination receiver in EAX and executes `ret 4`. There are no other field accesses or return paths. The target copies the second word into `rec` and dereferences it as a record pointer. The first word is the unsigned-ordered key read by the search at node `+0x10`. Thus the second container's value is a key and record-pointer pair; a generated twelve-byte payload is not justified.

The first container's construction was checked independently through `0x00077C70 -> 0x00076E10 -> 0x00076190 -> 0x00072C90`. Both allocation branches in the complete `0x00072C90` body read one source word and write it to node `+0x10`, with no second value field. Both then initialize the node links, rebalance and return through the same `ret 0x14`. This proves a scalar key value for this insertion route independently of allocation size and the donor's pointer typedef. Both searches and insertion comparisons use unsigned conditions. The native trial models these unsigned-ordered key words as `unsigned int`; the complete caller's immediate key supports an integer identifier. A more specific original typedef remains unknown.

The retained `ModifierRecord` names come from the existing bank. Retail reads operation at `+0x18`, value at `+0x20`, destination pointer at `+0x24` and a four-byte processed flag at `+0x30`. Operation cases assign, add or subtract a four-byte destination value, then store one to the processed flag. A record already marked processed calls `0x00077C70` with the same key. The complete `0x00077C70` body ignores its incoming receiver and inserts the key into the first container; its result is unused here. No destructor or ownership claim is made for the copied record pointer. This target constructs no owning container and has no constructor unwind path to recover.

## Measured shapes and remaining blockers

All trial sources, unedited probe output, strict gate output and subprocess receipts are retained in `build/target-00077ce0/`. `measurements.txt` is generated from the raw probe output. `11-mismatch.json` retains the chosen source, object and retail hashes, relocation entries, every differing offset and missing suffix. The corresponding object is retained as `11-native-stl-od.obj`.

The changed profile, typed singleton calls, hidden iterator returns, correct copied pair and nested predicates improve the original bank. Signed and unsigned switch expressions, explicit integer conversion, moving a pointer declaration within its block, moving it to function scope and an enum operation view do not remove the switch residue. `/Og` and `/Os` worsen the measured shape. Adding an unaccessed frame array changes stack reservation but disrupts the witnessed local positions; that trial is rejected and is not retained as the preferred body. The family generator finds no applicable source-level lever for the clean native body, so there is no choices file to feed to `shape_search.py`.

The remaining first divergence is the frame-size immediate at `+0x0005`, followed by the receiver slot at `+0x0008`. Retail reserves `0x48` bytes and stores ECX at `-0x40`; the retained trial reserves `0x28` and stores ECX at `-0x24`. End-result, copied-pair, record-pointer and flag slots also differ. At target `+0x00BD`, retail copies the operation snapshot into a second stack temporary; its following tests decrement that temporary instead of comparing it repeatedly with literals. The candidate omits this extra copy. Its zero flag is an immediate byte store rather than retail's register zero and byte store. These switch and flag differences shorten the body and shift the helper call and exit marker.

The native candidate keeps only the two decoded marker brackets in inline assembly and refers to its entry marker with a symbolic label. The full clean C++ trial omits those brackets and is worse. The marker's provenance is not independently established as a particular protection product, so no such identity is asserted. This diagnostic bank is not evidence that the repository should accept marker assembly as a converted source.

Probe masks relocations at candidate positions. Two candidate relocation operands do not align with retail: the final helper call and the exit marker address. Its differing-byte count is therefore a diagnostic lower bound, not a resolved byte comparison. The strict scoped gate fails on actual byte differences and seven unresolved symbols. Six are the native set/map lookup, end, dereference and pair-copy declarations shown verbatim in `11-native-stl-od.gate.log`; the seventh is `Rva00077C70Receiver::method(int)`. No pins were invented or added. The existing iterator comparison and singleton names resolve.

Reopening is justified by evidence for the missing local lifetime and switch snapshot, a compiler profile that reproduces the decoded unoptimized lowering, or the permitted canonical STL declarations after the header transition. An allocation size, a pointer donor name, or another register-only spelling does not establish any of these.

No shared header or shim is changed, so no full gate is required for this partial bank.
