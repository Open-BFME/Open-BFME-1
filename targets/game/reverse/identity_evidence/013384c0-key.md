# Opaque Apt emit key at VA 0x013384C0

The decorated identity `?key013384C0@@3HA` (C `int key013384C0`) owns four
bytes at VA 0x013384C0 in retail `.data`. Retail holds 0 there: the VA is past
`.data` raw_end (0x012EE000) in the zero-filled virtual tail (virtual size
ends at 0x01358000), so the loader semantics the data gate checks
(`reloc_ledger.Image.read`) return zeros. (Raw file bytes past raw_end are
not mapped and must be ignored.)

## Retail facts and contract

`key013384C0` is an opaque cookie used only by address. Its sole retail code
references come from `BfmeB1236Emit.cpp`:

- `Rva00899770 *created = Rva008AE770TheStack.createString(this, 0,
  (BfmeStrVKI *)&key013384C0, 1, 1, 0);` — passes `&key` as a key pointer.

The value is never read; only the address is taken. The 4-byte size follows
from the `int` declaration, which the C compiler emits as `?key013384C0@@3HA`.

## Extent and all users

4 bytes at VA 0x013384C0. Only 0x013384C0 and 0x013384C8 (`key013384C8`)
are referenced by game/ code, so only those two get rows; neighboring slots
stay unclaimed. (Raw file bytes around the VA are past `.data` raw_end and
unmapped; they say nothing about the loaded image.)
