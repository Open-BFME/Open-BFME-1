# STLport stream objects at VA 0x0130BD38 through 0x0130C010

The seven addresses below are complete STLport stream objects, not pointer cells or character arrays. Their existing definitions in `game/stlport/X4Iostream.cpp` are the single owners. The definitions instantiate STLport 4.5.3's stream types under the existing build flags. This correction adds the missing data rows and replaces the two remaining character-array declarations in `BfmeConv918.cpp`; it does not change any function's identity or verified instructions.

All seven extents are in the zero-filled virtual tail of retail `.data`. Every initial byte is zero. The executable has no PE base relocation directory, and these initial zero-filled objects contain no pointer relocations. The direct code operands and the compiler's relocations establish their addresses independently. `sizeof` probes compiled under each owner's build flags prove 100 bytes for output streams and 104 bytes for the input stream. The eight-byte allocation alignment introduces four bytes of padding after most output objects; the padding is not part of the datum. In particular, `wcerr` ends at VA 0x0130C074, where the next named string begins. No existing data row overlaps any corrected extent, and no DIR32 name starts strictly inside it.

The output cleanups load the object's first word as a virtual-base table, fetch the signed displacement at table offset 4, and install the output vtable through that displacement. They then invoke the basic_ios destructor with the receiver advanced by 4. The input cleanup advances its receiver by 8. RTTI for the written vtables identifies narrow `basic_ostream` at VA 0x0112F304, wide `basic_ostream` at VA 0x0112F30C, and wide `basic_istream` at VA 0x0112F2FC. The complete-object initializers pass ECX equal to the datum's start, a null streambuf, and the complete-object flag. Narrow output construction uses ILT VA 0x00441E5C, whose five bytes `e9 cf a3 58 00` route to VA 0x009CC230. Wide output construction reaches VA 0x00C43860, and wide input construction reaches VA 0x00C438F0. Each initializer registers the corresponding cleanup with atexit.

Retail `_STL::ios_base::_S_initialize` at RVA 0x00843990 constructs the objects and connects them to stream buffers. `_S_uninitialize` at RVA 0x00842C00 reads the virtual-base information, clears buffers, and destroys them. `sync_with_stdio` at RVA 0x00842F80 reads and replaces the narrow buffers. These bodies reproduce the use documented by the vendored STLport headers and the existing upstream-derived `X4Iostream.cpp`. The named global definitions and ordinal initializer order establish which same-typed output stream occupies each address. A `char *` spelling is misplaced: retail supplies the object's address as a complete stream receiver and writes its virtual-base state, rather than loading a pointer cell and accessing the pointed-to character array.

The named stream definitions already have DIR32 rows, which are retained alongside the old spellings. No duplicate row or new symbols.csv pin is needed.
