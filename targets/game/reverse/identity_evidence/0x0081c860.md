# RVA 0x0081C860: address-owned initialization wrapper

The preceding retail routine ends with RET 4 at 0x0081C85D (ending at
0x0081C85F). This body starts at 0x0081C860, returns with RET 4 at +0x22,
and is followed by INT3 at +0x25. Its extent is 37 bytes. The old generated
row had the same extent; its generic int3-carved note did not accurately
describe the immediately preceding RET boundary.

The body takes ECX as a receiver and one stack word, clears receiver +0 and
+4, passes that stack word and zero to 0x0081C6A0 with receiver +8, and
returns the original receiver in EAX. The clean C++ view states exactly
those operations and retains addresses in both type and method names.
It does not claim the original constructor or container identity.

## Independently decoded callee ABI

`callees.py 0x0081C860 37` identifies the existing address-owned callee
`?dup_0081c6a0@@YAXXZ`. Its 11-byte body at 0x0081C6A0 is:

```
mov eax, ecx
mov ecx, [esp+8]
mov [eax], ecx
ret 8
```

INT3 precedes and follows that callee. It ignores the first stack word,
stores the second word at receiver +0, returns the receiver, and cleans
two stack words. The current native object symbol in GameAudio.cpp is an
STLport allocator-proxy constructor taking an allocator reference and an
unsigned word, consistent with this ABI. That symbol is not independent
proof of the wrapper's template parameters, so neither AudioEventInfo nor
an allocator type is introduced into the reconstruction.

One typed address-specific pin names this physical body with its observed
thiscall ABI: pointer-shaped ignored first word, unsigned second word,
receiver pointer result. It adds no ledger body or semantic identity and
leaves the existing duplicate row and GameAudio.cpp unchanged. No routing
thunk or alternate target is used: the caller has a direct REL32 to the
11-byte body. The prior reported exact stash is absent from this checkout;
the new reconstruction independently reproduces all 37 bytes modulo that
one call relocation. A separate native C++ ABI probe reproduces all 11
callee bytes with zero relocations. The first scoped gate failed only on
this unresolved call; the repaired gate binds it to the decoded body.

All instruction and boundary observations above were cross-checked against
retail-1.03-unpacked lotrbfme.exe using pefile/Capstone. No original full
method name is inferred from this byte match.
