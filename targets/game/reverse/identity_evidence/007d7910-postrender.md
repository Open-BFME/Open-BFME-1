Slots 5 and 6 reach the existing `set` at RVA 0x007D81C0 and `reset` at RVA 0x007D75E0. The target calls these slots without a receiver adjustment. This establishes the receiver and dispatch role without borrowing the adjacent highlight filter's identity.

The complete target interval is [0x007D7910, 0x007D8001), 1777 bytes. Its conditional branches remain inside that interval. Its return instructions are at offsets 0x41, 0x62 and 0x6EE, each with RET 0x10. ## Caller arguments and return representation

The wrapper at RVA 0x00716A50 forwards four stack words through filter slot 3. It uses ECX for the filter receiver and has no hidden return buffer. The complete caller at RVA 0x0073E050 calls that wrapper through ILT RVA 0x00035F3F at eleven decoded instruction boundaries. At caller offset 0x134, it pushes a display-size float-pair pointer, a byte flag pointer, a scroll-delta pointer, a mode word and the filter index, then removes 0x14 bytes and tests AL. The wrapper removes the filter-index argument from the forwarded call; the target removes the four remaining words with RET 0x10 and returns a byte Boolean in AL. All three target return paths were checked.

The caller's saved ledger size is 5126, which ends inside its final `mov esp, ebp`. The actual complete caller ends at RET offset 0x1408 and has extent 5129. The following bytes are INT3 padding. No caller ledger row is changed by this recovery. `retail-caller-complete.txt`, `checked-caller-complete.txt` and `caller-tail.txt` retain the complete decode and boundary evidence. Raw call hits were accepted only after this decode confirmed their instruction boundaries.

Before the offset-0x134 call, the caller converts the display's unsigned width and height results into floats and stores them consecutively at stack offsets 0x1C and 0x20. That pair's address becomes the fourth target argument. The target divides by the two four-byte float fields at argument offsets 0 and 4. The second argument points to the pair populated by matched `W3DView::calcDeltaScroll` at RVA 0x0073B6B0. Its complete 157-byte decode writes both output fields with x87 stores and returns with RET 4. The target does not read that second argument. The third argument is written with a byte store on the early-return path. `Coord2D` is included from its canonical existing header.

The tactical-view calls use slots 0x4C, 0x3C and 0x44. The constructor-proven W3DView table at VA 0x011217A0 routes them through ILTs 0x00006AB4, 0x0003F12A and 0x0001B892 to View bodies 0x0045BA80, 0x0045BA30 and 0x0045BA50. The iterator receives four elements with stride 0x20. The actual callback pointer is ILT VA 0x00444486, which jumps to RVA 0x007D75C0. The complete callback is `mov eax, ecx; ret`: it reads and writes no element fields, has no cleanup or ownership behavior, and returns its receiver. The iterator calls the callback with each element in ECX, advances by the supplied stride and returns with RET 0x10. The source passes the existing thunk address explicitly as a four-byte opaque callback address because MSVC 7.1 cannot spell the compiler's receiver-callback function-pointer convention in a normal free-function declaration. It adds no callback identity or pin.

Element types come from the target's complete reads and writes, rather than the stride or callback name. ## Experiments and refutation

The new hypothesis was that the saved body's final UV expressions and lifetimes were wrong, rather than an isolated compiler register choice. Retail's stores to both pairs, its direct first-pass Y division and its reuse of the integer width after the first draw support that hypothesis. A complete paired-coordinate reconstruction that retained the old frame and register mismatch would have refuted its proposed effect on allocation.

The original bank was measured first at the proven retail extent. Restoring both final UV pairs alone and then correcting three device-stage operands did not improve the positional byte count. Removing cached float right/bottom values alone also failed. Reconstructing each complete per-vertex expression, with direct first-pass Y division and live integer sums, reproduced the frame, receiver register and entire normalized instruction shape. Correcting the initial writes from the second UV pair to the first then produced exact bytes modulo relocations. These are field and expression corrections; the earlier unsuccessful inheritance and explicit-register hypotheses were not repeated.

The first strict gate rejected only the generated local constructor's unrecorded DIR32 name. A trial using a free-function `__thiscall` callback type failed to compile. Passing the independently decoded existing callback thunk as an opaque address retained the exact body and removed that unresolved identity. Declaring the iterator directly with `extern "C" __stdcall` added an unwanted `@16` suffix to its already decorated compiler symbol, so that trial remained unresolved. The final source takes the existing symbol's address and invokes it through the independently verified stdcall iterator ABI. Every trial source and unedited probe is retained under `build/worker-007d7910/`; `build/verdict.txt` was updated after each measurement. `probe-baseline.txt` and `probe-trial01-paired-uv.txt` through `probe-trial09-iterator-abi.txt` preserve the successful and rejected measurements. Final gate and source-check receipts are in the same folder.

`add-match-iterator-abi.txt` and the independently invoked `gate-scoped-bash.txt` both pass the scoped byte, source-claim, string, constant, DIR32 and body-guard checks. `class-gate-final.txt`, `declared-unmatched.txt`, `name-regression.txt` and `pin-consistency.txt` retain the other passing checks. The name-regression CLI accepts revisions rather than file paths in this checkout; its own `regressions` snapshot comparison was applied to the preserved bank and final source without writing Git state. No shared header or shim changes, so a full gate is not required.

Collection still requires the coordinator to stage the new source and retired bank, then run the ordinary staged CSV check. In this run Git is read-only. The working-tree `check_csv.py` crashes while opening the retired bank still present in the unchanged index (`check-csv.txt`). Applying all of its validators to existing working-tree members additionally reports the expected new-source tracking requirement and no other finding (`csv-working-snapshot.txt`). Neither requirement was suppressed or bypassed. The source, replacement row, tombstone and bank deletion remain an uncommitted transaction.

The identity claim would be refuted by a different constructor-installed table, a slot-3 thunk targeting another body, or a complete caller showing different argument representations. The layout claim would be refuted by an actual callback field write, a target access outside the stated element fields, or an indirect call with different stack cleanup. The recovery requires both exact bytes and successful relocation validation; a masked probe alone is not acceptance.
