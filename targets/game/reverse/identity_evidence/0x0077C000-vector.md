# ModelConditionInfo vector overflow at RVA 0x0077C000

Identity is supported by the matched parser call chain, not the old lift name.
`W3DModelDrawModuleData::parseConditionState` at RVA 0x0077C860 builds its
ModelConditionInfo local and passes it to the +0x18 condition-state vector via
ILT 0x00019916 -> RVA 0x0077C670. This push_back is matched in
`RvaVectorPushBack.cpp`; its opaque 296-byte element is the parser's
ModelConditionInfo. Its overflow branch at RVA 0x0077C6A7 calls ILT 0x00015F41
-> RVA 0x0077C000 with position, value, empty tag, fill count one and atEnd true.
The native STLport `_vector.h` `_M_insert_overflow` algorithm is the source twin
for this five-argument method. The type identity is further established by
this vector's cleanup calling the matched ModelConditionInfo destructor through
ILT 0x0002306F. The complete body ends at RET 20 (RVA 0x0077C11E), followed by
INT3 at 0x0077C121: 289 bytes.

Start point was the preferred exact-shape bank at attempts/0x0077c000.cpp.
The implementation now lives with the verified constructor, destructor and
clear method in the existing BFME class home. Its actual 0x128-byte layout is
used rather than the bank's opaque whole-object array. The class is declared
as struct, as in the Zero Hour header, preserving the template's U mangling.
Only the native vector overflow is newly claimed; emission anchors and the
already-matched helper are not counted as additional progress.

Two narrow template specializations preserve existing opaque retail bindings:

- `_Construct<ModelConditionInfo>` calls ILT 0x00039676 -> RVA 0x0013A700
  using cdecl(destination, const value reference). Retail tests destination
  for null, pushes the second pointer into its member copy call, restores its
  EH frame and uses plain RET. The caller cleans eight bytes. No claim is made
  that the old generated pair-type identity at 0x0013A700 is correct.
- `vector<ModelConditionInfo>::_M_clear` calls ILT 0x0000CF04 -> RVA 0x0077BBA0
  with this in ECX and no stack arguments. That existing matched body destroys
  0x128-byte elements through ModelConditionInfo's destructor and frees the
  allocation. Both method/ILT bindings were present before this change.

The suffix-copy call uses existing ILT 0x00043937 -> the already-matched
`Rva00774760` at RVA 0x00774760. The helper reads three pointer arguments,
loops in 0x128-byte strides calling ILT 0x00039676, returns the final destination
cursor in EAX, and ends with RET at 0x00774792 then INT3. The native STLport
`__uninitialized_copy<ModelConditionInfo*, ModelConditionInfo*>` emitted from
the draft independently probes exactly over all 51 bytes, with its sole
relocation naming that same existing construction ILT. The CALLER also pushes
an empty false-type tag reference and cleans 16 bytes; the helper does not read
the fourth argument. The adapter therefore retains all four cdecl arguments,
including a default-constructed empty tag. A three-argument adapter would be
five bytes short, and value-initializing the external-call tag adds a spurious
zero store that native inlining can eliminate.

The vector method is a narrow specialization of the unchanged native STLport
algorithm: the prefix copy and fill retain their native inlined loops; the
suffix copy explicitly uses the already-existing ILT with the four-argument
ABI above. This resolves the preferred bank's final helper without any new
pin, renamed helper body, or dependency ledger change. The template identity
and source algorithm remain those of the vendor header.

All addresses and extents above were cross-checked against the current unpacked
retail image with pefile/capstone. The source/ledger strict gate additionally
verifies the parent call targets, its unchanged class siblings and DIR32 refs.

The name scanner pairs the removed C __emit anchor with an unrelated
rva00774B60Clear adapter already present in the destination before this change.
The actual replacement preserves the full native vector<ModelConditionInfo>
_M_insert_overflow identity. The exact source-hash correction records this
false cross-file pairing; no established method name is downgraded.
