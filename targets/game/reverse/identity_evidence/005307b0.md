# WOL staging tooltip helper at 0x005307B0

The 2068-byte Ghidra/anchor extent is truncated. Its nominal end at body
offset `+0x814` falls inside the seven-byte `lea ecx,[esp+0x438]` beginning at
`+0x813`. The complete cleanup continues through a one-argument `ret 4` at
`+0x842`; the complete boundary is therefore
`[0x005307B0, 0x00530FF5)`, 2117 bytes. All 23 direct callees resolve.

The body receives one four-byte string-like value at entry stack `+0x04`. It
passes that value by reference to `UnicodeString::translate`, uses the result
to query `TheGameSpyInfo`, accumulates the staging player's profile statistics,
formats the WOL locale/rank/player tooltip strings, and finally calls the mouse
tooltip setter. These operations and the `TOOLTIP:StagingPlayerInfo`,
`TOOLTIP:ProfiledPlayer`, buddy/local/generic-player string family place it in
the `WOLGameSetupMenu.cpp` staging tooltip flow, not `PopupPlayerInfo.cpp`.

It is not the static three-argument cdecl `playerTooltip(GameWindow *,
WinInstanceData *, UnsignedInt)`: that decorated identity is already matched
at the distinct 1517-byte body `0x004FA800`, and this body's `ret 4` proves a
different ABI. No named caller reaches the body or its ILT `0x00002E1E`, so
the exact BFME-only helper name remains unproved and must stay opaque.
