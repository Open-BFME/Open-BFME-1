# _heap_abort at 0x0088A5F0 (was claimed as Debug::IsWindowed)

The 78-byte body at 0x0088A5F0 pushes VA 0x01133150, whose .rdata bytes are the literal "Fatal heap error.". In the Zero Hour twin that literal appears only in debug_debug.cpp: `void __cdecl _heap_abort(void) { DCRASH_RELEASE("Fatal heap error."); }`. The body is __cdecl: it ends in a bare ret and never reads ECX as a this pointer, which contradicts the lift's thiscall `bool Debug::IsWindowed(void)` claim (IsWindowed would read a member through ECX and return a bool). The body runs the BFME release crash chain on the debug manager global 0x01336E5C: slot 0x5C(returnAddress 1) as the matched _bfme_debugRecordCallsite 0x008896A0 does, then slots 0x60 and 0x6C(0 0) -> 0x38(msg) -> 0x4C(true). That is the same sequence as matched DebugReAllocMemory 0x0088EB90. In ZH, IsWindowed sits directly before _heap_abort in debug_debug.cpp, which explains how an adjacency-based lift mislabelled this address. Probe: 78/78 bytes, exact outside relocations.
