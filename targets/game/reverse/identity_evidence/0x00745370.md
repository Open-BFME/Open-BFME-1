# 0x00745370: W3DView pick slot kept under an address name

- Boundary [0x00745370, 0x00745689), 793 B; reached through ILT thunk 0x0003E3EC
  (slot 50171), a W3DView vtable slot. The Zero Hour twin of the slot is
  `W3DView::pickDrawable` (GeneralsMD W3DView.cpp), and the BFME body still opens
  with ZH's window-under-cursor loop, getPickRay and RayCollisionTestClass setup.
- `tools/ilt_oracle.py check` CONTRADICTS
  `?pickDrawable@W3DView@@UAEPAVDrawable@@PBUICoord2D@@_NW4PickType@@@Z` at this
  address (window 29703-29709) and every variant tried in session 556: access
  U/Q/A/E/M/I, ICoord2D as struct or class, pointer const or not, Bool as `_N` or
  `H`, PickType as the enum, `H` or `I`, Drawable as class or struct. So retail's
  decorated name for this slot is not the ZH one, and the BFME name is unknown.
- The conversion therefore keeps the address name `W3DView::rva00745370`
  (the convention of the class's other unresolved slots, e.g. rva00741250,
  rva00743F80) by a TU `#define pickDrawable rva00745370`; the vtable is the
  only reference to the symbol. The ZH role ("pick drawable under a screen
  point") stays in the source comments.
