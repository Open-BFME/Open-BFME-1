# Exception dialog callback boundary

The rows at RVA 0x0088DC30 and RVA 0x0088DC68 describe one stdcall callback spanning [0x0088DC30, 0x0088DFDC). The second row is an interior branch destination. The complete clean C++ port retains the bank's name `_Rva0088DC30DialogProc@16`. The donor's `ExceptionDlgProc` name is structural evidence, so this port does not adopt it as an independently proven BFME 1 identity.

## Boundary and caller evidence

The entry at 0x0088DC30 establishes EBP and reserves 0x48 bytes. The `je` at 0x0088DC3E enters 0x0088DC68 for WM_INITDIALOG. That destination saves registers and reads the entry's `[ebp+8]` argument; it has no independent frame setup. Its column and item locals occupy `[ebp-0x20]` and `[ebp-0x48]`. All direct branch destinations of the complete callback are internal instruction starts. Its three return instructions at 0x0088DC65, 0x0088DDDE and 0x0088DFD9 clean sixteen argument bytes. The last ends at 0x0088DFDC, followed by four `int3` padding bytes and the next ledger body at 0x0088DFE0. The old interior row ends at 0x0088DFD3, inside the final `mov eax,1` instruction.

The completely decoded `DebugExceptionhandler::ExceptionFilter` caller at RVA 0x0088E5F0 pushes callback VA 0x00C8DC30 at RVA 0x0088E880, the template VA 0x012D4D98 at RVA 0x0088E887, and calls the PE import `USER32.dll!DialogBoxIndirectParamA` at RVA 0x0088E89B. The template contains the UTF-16 title `Exception`. This proves the callback role and entry independently of the donor. The stripped retail image has no base-relocation directory, so no claim that the entire image lacks references to the interior address is made.

## ABI, layout and state

The callback reads its dialog handle at `[ebp+8]`, message at `[ebp+0xC]` and command at `[ebp+0x10]`. It compares only the command's low sixteen bits and zero-extends those bits before EndDialog. The fourth callback argument is unused. Results are a full EAX zero or one; there is no hidden return storage, receiver or receiver adjustment. The three `ret 0x10` paths agree with four 32-bit stdcall arguments. No exception frame or unwind cleanup exists in this callback.

The actual GetProcAddress import receives the literal `IsDebuggerPresent`; the returned pointer is invoked without arguments and its full EAX result is tested. EDI first holds the imported SendDlgItemMessageA slot and later SendMessageA; EBX holds the imported cdecl strtok slot in the stack loop. Those register calls are imports rather than virtual dispatch. Windows and common-control declarations come from the same SDK headers already used by the owning exception-filter source. LVCOLUMNA writes mask, width, text and format at offsets 0, 8, 12 and 4. LVITEMA writes mask, row, subitem and text at offsets 0, 4, 8 and 20. The allocated locals use the canonical 32-byte and 40-byte layouts.

GetAddress at RVA 0x0088C6C0 is decoded completely: a signed index is bounded to [0,256), ECX supplies the Signature receiver, the result comes from `[ecx+4+index*4]` or zero, and both paths use `ret 4`. GetSymbol at RVA 0x0088C6E0 is decoded through all three plain returns. Its three cdecl arguments are the 32-bit address, writable byte buffer and unsigned byte capacity. The caller cleans twelve bytes and consumes no result. The canonical `debug_stack.h` supplies these declarations and the inline count accessor.

GetExceptionType at RVA 0x0088D430 reads the exception-record pointer at offset zero of its first argument, the exception code at record offset zero, and access-violation fields at record offsets 0x14 and 0x18. Its second argument is a writable explanation buffer. Every path returns a string pointer in EAX with plain `ret`, consistent with cdecl and the callback's eight-byte cleanup. Its recorded 1044-byte extent contains 845 code bytes, alignment, two jump tables and a byte selector table. Linear decoding of all 1044 bytes stops inside the final data entry; decoding the full code extent succeeds. Both decoded table dispatches and every table destination were checked separately against instruction boundaries, accounting for the whole ledger extent.

The port uses the owning source's existing `verInfo`, `regInfo`, `exPtrs` and `sig` statics. Every callback reference resolves to the same symbol base as the independently matched ExceptionFilter: respectively VA 0x01336EB8, 0x01336FB8, 0x013373B8 and 0x013373C8. The decoded caller bounds and terminates the two buffers, stores the exception pointer before creating the dialog, and supplies the same Signature to StackWalk. The callback reads ContextRecord at exception-pointer offset four and Eip at context offset 0xB8. There are no STL containers, value-copy helpers or owned elements in this callback.
