# New hypothesis and refutation

The earlier bank selected the raw image texture field directly. Its compiler removed the fallback-address null test, although retail retains that test after taking the local handle's address. The current source and ledger provide a native accessor and canonical helper declarations that the old bank did not use. The Zero Hour `GeneralsMD/Code/GameEngine/Include/GameClient/Image.h` declares `getRawTextureData()`. The complete target loads that field at image offset `0x2C` and passes the selected address to the decoded value-texture accessor. An in-class accessor returning that handle view can change the compiler's knowledge of the conditional expression without adding a call or changing the payload. This hypothesis would be refuted if its compiled body still omitted the test at target offset `0xF3`, or if the source changed the selected address or its dereference depth.

`trial03-native-getter.cpp` restores the target's fallback test and loop alignment. The final source also includes the existing `surfaceclass.h` and `ascii_string.h`, uses the nested `SurfaceClass::SurfaceDescription`, names the empty-string global through the existing DIR32 record, and uses the actual diagnostic string literal. No pin or ledger row was added. The unlock declaration was corrected from unsigned character to the existing canonical `char` declaration after the relocation-aware gate exposed the former unresolved mangling. Its return value is discarded in this target.
