# GadgetComboBoxInput and its compiler-private helper

The recovery replaces the generated row at RVA `0x004B4010` with `GadgetComboBoxInput`. Its executable extent remains 539 bytes. The complete static helper at `0x004B3E30` is retained in the caller's translation unit to reproduce its compiler-private calling convention. That helper's generated ledger row remains outside this assignment.

## Independent identity and ABI evidence

Retail's FunctionLexicon entry at RVA `0x00EA9734` contains a zero name key, the string pointer VA `0x010871F4` (`GadgetComboBoxInput`), and callback VA `0x0042EFD7`. The complete five-byte ILT body at RVA `0x0002EFD7` jumps to `0x004B4010`. Adjacent twelve-byte records name the list-box and image-combo input callbacks. This is shipped name evidence, independently checked against the table layout in `Common/FunctionLexicon.h` and the donor input table in `Common/System/FunctionLexicon.cpp`.

The complete caller at `0x00790420` pushes its three four-byte arguments followed by ECX, calls that ILT thunk, removes sixteen bytes, and returns with `ret 12`. The target returns a four-byte handled result in EAX with plain `ret`; it has four stack arguments, no hidden return storage, and no receiver adjustment. The donor `GeneralsMD/Code/GameEngine/Source/GameClient/GUI/Gadget/GadgetComboBox.cpp` gives the corresponding `GameWindow*` and three unsigned message words.

The target's complete decode ends at its final `ret` at offset `0x21A`. All direct conditional branches stay inside that executable extent. The indirect switch uses six destinations at offsets `0x1DA`, `0x102`, `0x195`, `0x1EC`, `0x63`, and `0x205`. A padding byte, six destination dwords and seventeen selector bytes follow the code. They explain the compiler object's 581-byte section; they do not justify enlarging the executable ledger extent. The final strict audit independently checks each table destination and selector.

## Layout, callee and ownership checks

Complete decoded accessors establish GameWindow instance data at `+0x30`, user data at `+0x2C`, and owner at `+0x44`. The caller reads ComboBoxData's edit window at `+0x28`; the helper reads its list window at `+0x2C`, maximum display count at `+0x04`, entry count at `+0x20`, and writes the byte at `+0x1C`. These accesses agree with the neighbouring landed combo accessors and HideListBox source. WinInstanceData's style and font fields are at `+0x0C` and `+0x184`, respectively, as confirmed by the current layout oracle. The helper's additional list-record fields remain offset-named where their identity is unknown.

Both the base and W3D GameWindowManager vtables route slots `0x94`, `0x98`, `0xBC`, `0xC0`, `0xD4`, `0xD8`, and `0x10C` to completely decoded bodies. The message senders consume four stack words and return a four-byte handled result; tab navigation and lone-window setters consume one pointer. Slot `0xC0` reads the same manager field that `winSetLoneWindow` writes. Its source name remains `rva0047D080`; it is not asserted to be `winGetFocus`.

The Miles audio primary vtable's slot `0x44` routes to the already matched AudioManager wrapper at `0x006B9A40`. Its canonical declaration returns an unsigned four-byte handle and accepts `const AudioEventRTS*`; the target ignores that result. Retail constructs the event with an AsciiString reference and a four-byte integer `2`, not the obsolete one-argument constructor declaration. The complete constructor at `0x000B2CC0`, common initialization at `0x000B24C0`, destructor at `0x000B31F0`, string constructor at `0x00888BC0`, string assignment at `0x00887C90`, and release at `0x00887940` were decoded. The local event occupies `0x70` bytes; the canonical AsciiString and Coord3D headers are included.

The event constructor's six unwind states clean up those five strings and the counted pointer. The caller's three-state map is `0 -> -1`, `1 -> 0`, `2 -> -1`; its cleanup actions use the AsciiString temporary at `[ebp-0x80]` and event at `[ebp-0x7C]`. The strict audit compares the compiled predecessor map, complete cleanup bytes and resolved destructor destinations against retail. The event lifetime view uses the existing ledger's direct complete-destructor spelling `??1AudioEventRTS@@QAE@XZ`, matching the actual direct calls and cleanup jumps. Its payload remains opaque because this caller never accesses its fields; the complete external constructor and destructor retain ownership. The unrelated legacy `UAE` pin routes through `0x0002671F` to `0x000CFA40`; it is left untouched and is not used by this recovery.

The static helper's complete 384-byte body tests incoming EBX, does not assign it, consumes no stack argument, and preserves it on every return path. Compiling its complete source beside the caller reproduces that private convention. Its typed address-derived pin documents this restriction; an ordinary external declaration does not reproduce its ABI. No STL ledger row or pin is changed.

## Measurements and refutation

Raw trials and reproducible audit scripts are retained under `build/combobox-004b4010/`. The unchanged donor source produced 1,070 bytes with 388 non-relocation differences. The complete retail-shaped caller with an external helper declaration produced 303 differences, starting at offset `0x18`. Giving the compiler the complete static helper produced zero differences throughout the 539 executable bytes. The helper itself matched all 384 bytes. Corrected canonical declarations and the shared Coord3D header preserved the result.

The final scoped gate passes all 76 ledger rows across the new source and the unchanged donor TU. Removing the donor's existing input definition stops emission of `getFont@WinInstanceData`, which two other ledger rows still use. That removal trial is preserved in `GadgetComboBox-with-input-removed.cpp` with its raw failure receipt `scoped-gate-removal-failed.txt`. The donor file is therefore unchanged; the assigned row exclusively names `GadgetComboBoxInput.cpp`. No other function row was repaired or repointed. `check_csv.py` reports only that the new source is untracked; staging is reserved for the coordinator in this seat.

The private-helper hypothesis would be refuted by a mismatching helper body, a stack argument at the actual call, a different incoming register, or differing EH cleanup. A different FunctionLexicon callback route would refute the named identity. A branch or table destination outside the decoded code would refute the boundary. None of those conditions was found. Raw strict, probe and repository gate receipts are retained in the task directory; the final verdict names their paths.
