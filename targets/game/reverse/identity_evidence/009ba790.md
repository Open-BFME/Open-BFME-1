# RVA 009BA790: MMX dispatch body

The identity remains address-derived. `_Rva009BA790` replaces the anonymous
11,476-byte dump; it does not claim an upstream codec function name.

## Boundary and ABI

Retail returns from the preceding body at RVA `009BA78F`. The next instruction,
`009BA790 push ebx`, starts the aligned-stack prologue, saving the incoming stack
in EBX and allocating `0x988` bytes below EBP. The complete body ends at
`009BD463 ret`, followed by twelve INT3 bytes and the next prologue at `009BD470`.
Thus its extent is exactly `009BD464 - 009BA790 = 11476` bytes.

The already matched CPU dispatch installer writes VA `00DBA790` to slot
`01356E60` at RVA `009B0FB1` in its MMX arm. Independently, the caller at
`009A62CB..009A62DE` pushes five arguments, calls `[01356E60]`, and adds `0x14`
to ESP. In push order these are a scalar parameter, stride from context `+98`,
height from `+94` multiplied by eight, width from `+90` multiplied by eight,
and a byte pointer formed from context `+78` plus `+14`.

The body independently reads the corresponding incoming arguments at saved
EBX offsets `+18`, `+14`, `+10`, `+0C`, and `+08`. Width controls a signed
eight-byte-step loop; height uses the unsigned outer-loop check. This witnesses
the cdecl signature `(unsigned char *, int, unsigned int, int, int)`.
The dispatch TU's former no-argument C++ declaration and its sole
`?Rva009BA790@@YAXXZ` pin are retired together. The new function row supplies
the actual `_Rva009BA790` mapping; no new pin is needed.

## Narrow MMX compiler exception

MSVC 7.1 `/O2 /Oy- /Z7 /MD` compiles the original intrinsic body to 11,460
bytes rather than 11,476. The original probe has 402 non-relocation byte
differences, beginning at `+2AAB`; four relocation sites also move. It combines
the row addresses, keeps the imported `rand` address in EDI, uses an MM0 noise
temporary, schedules that load before the final saturating subtract, and
increments both a pointer and counter. Retail instead uses the ESI/EDI indexed
addresses, MM2 temporary, and one index.

The following bounded intrinsic variants were compiled:

* A named `__m64 addition` local and a `const __m64 *` noise read produce the
  same instruction shape as the original.
* Reversing the commutative `_mm_add_pi8` operands changes the MMX allocation,
  but retains the 11,460-byte extent and does not improve the match.
* Volatile addition, sample, or pixel access fail to compile: this compiler's
  `__m64` union copy cannot accept the volatile-qualified source.
* Replacing only the final candidate's kernel with the original intrinsic
  operations, retaining its corrected native setup and row locals, still
  produces 11,460 bytes and 378 differing non-relocation bytes. The same MMX
  scheduling, address combination and surrounding spill differences remain.

The exception is limited to the 57 bytes at `+2C7E..+2CB6`: loading the three
named operands and the eight-byte pixel kernel. It uses named C++ locals for
every argument, pointer and pattern; it has no raw frame offsets, naked
prologue, byte emission, or copied function tail. The native outer loop owns
the row count and stride update. This is less than 0.5% of the complete body.

The native shape fixes were separately established: a C++ zero-fill loop
recovers the temporary destination register that `memset` elides; named byte
pattern values preserve the early byte negation; and `height > 0` with a scoped
row pointer reproduces the single unsigned guard. The final probe is exact
over all 11,476 bytes modulo 13 relocation slots. `add_match.py` then verifies
the full body with resolved calls and data. The dispatch TU is byte-gated too.
