# Two complete receiver-forwarding methods

Both complete 11-byte methods were compared against retail PE and Ghidra
memory, including their following five INT3 bytes. Their existing generated
five-byte E9 rows were interior instructions, not independent ILT entries;
Ghidra has no references to either interior address. Only those two ledger
rows are retired, with tombstones; generated source is not edited.

## 006E9B80 ABI

The full 8277-byte callee00934940 consumes incoming ECX in EDI at+1D,
reads receiver+1C, uses no incoming stack argument, and restores its EH
frame before plain RET at00936994. Its skipped-work path enters0093697E;
there is no scalar return computation shared between the two paths.
Ghidra's independent decompilation also reports a void one-register entry.
The original opaque d_00934940 function-ledger symbol is retained as the
relocation target. A one-argument fastcall pointer view supplies ECX and no
stack arguments, exactly this physical no-explicit-argument thiscall ABI.
No new semantic callee name or pin is introduced. In particular the existing
Render2DClass::Render row is at00933E50, a distinct2015-byte body, and is
not used as an alias for this8277-byte callee.

The wrapper owner and method remain Rva006E9B80::method. Its loaded field
keeps offset164 in the name; a neighboring receiver-forwarding method does
not by itself prove a full identity here.

## 0092C320 ABI

The existing native178-byte provider00924C40 in meshgeometry.cpp is emitted
as MeshGeometryClass::Set_User_Text(char*). Its complete RET4 is00924CEF,
then five INT3 bytes. Independently decoded instructions release its prior
owned string at receiver+10, allocate/copy the zero-terminated input string,
and restore the EH frame. The canonical meshgeometry.h declaration supplies
the exact callee type; its existing pin and object-symbol row are reused.
No new declaration of a covered type or new binding is added. The wrapper
forwards that same char pointer and loads the callee receiver at+C8.
It stays Rva0092C320::method because no independent full method-name witness
is asserted. Both full wrappers pass resolved-target gates, not just masked
probes. callees.py was run on both entries; its E8-only list omits the E9s.
