# 0x006C1B50 / 0x00107550: the counted ping handle's operator= and destructor

BFME 1 target evidence:
- W3DRadar::drawEvents (0x006C3170, matched C++ in W3DRadarDrawEvents.cpp)
  assigns the fetched ping handle to the event's +0x4C handle by calling
  0x006C1B50 through ILT 0x000345A4 four times (ECX = &event.ping, one pushed
  source-handle address, callee `ret 4`, EAX = this) and inlines the same body
  once (beacon arm). It destroys two of the five handle temporaries by calling
  0x00107550 through ILT 0x00018336 (ECX = temporary) and inlines the other
  three. That split is VC7.1's inline budget for one operator= and one
  destructor of one class.
- 0x006C1B50 (57 B): `if (this != &o) { if (o.p) ++o.p->ref(+4); release
  old p; p = o.p; } return this;` 0x00107550 (26 B): release `p` (decrement
  +4, call vtable slot 0 with 1 at zero).
- The COMDATs W3DRadarDrawEvents.cpp emits for
  `??4Rva0058C2B0RefPtr@@QAEAAV0@ABV0@@Z` and `??1Rva0058C2B0RefPtr@@QAE@XZ`
  are byte-identical to both retail bodies (objdump of the scoped build).
