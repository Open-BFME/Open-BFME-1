# The terrain's buffer children: W3DTreeBuffer, W3DShrubBuffer, W3DFloorBuffer

The pseudo-classes `BaseHeightMapResetBuffer`, `BaseHeightMapResetList` and
`BaseHeightMapResetTerrain` named the terrain's children by their offsets, and the
ledger gave W3DTreeBuffer's name to the bodies of the shrub buffer.

* **Construction.** BaseHeightMapRenderObjClass's constructor stores each child
  constructor's result into its member:

  | Member | Constructor (ILT) | Store | Class |
  |---|---|---|---|
  | +0x3094 | 0x00736720 (0x00038974) | 0x006CFCE4 | W3DTreeBuffer |
  | +0x3098 | 0x00720820 (0x00023849) | 0x006CFD29 | W3DShrubBuffer |
  | +0x30A0 | 0x006D73C0 (0x0002A9E1) | 0x006CFD95 | W3DBibBuffer (row) |
  | +0x30A4 | 0x006F92D0 (0x000223D6) | 0x006CFE0F | W3DFloorBuffer |
  | +0x30AC | 0x0070FB70 (0x0001E46B) | 0x006CFE72 | W3DRoadBuffer (row) |
  | +0x30B0 | 0x006D8B60 (0x00009D7C) | 0x006CFDDC | W3DBridgeBuffer (row) |
  | +0x30B4 | 0x006DED60 (0x0003D749) | 0x006CFEA5 | Rva006DED60RoadBuffer |

* **Class names.** Three constructors install a vtable whose slot 2 returns the
  class-name literal stored right after the table: 0x00736720 installs 0x01121608
  (at 0x00736742), slot 2 is 0x007366E0 `mov eax,0x0112161C`, "W3DTreeBuffer";
  0x00720820 installs 0x01120F94 (at 0x00720841), slot 2 is 0x007207E0
  `mov eax,0x01120FA8`, "W3DShrubBuffer"; 0x006F92D0 installs 0x01120360 (at
  0x006F92F0), slot 2 is 0x006F9290 `mov eax,0x01120374`, "W3DFloorBuffer". Slot 0
  is each class's scalar deleting destructor (ILT 0x0003CECA to 0x007366F0, ILT
  0x0003430B to 0x007207F0), so both tree-buffer destructors are virtual.
* **Source files.** `targets/game/reverse/string_xrefs.tsv` binds W3DShrubBuffer.cpp's `__FILE__`
  literal to 0x0071C0E0 and 0x00720D10 and W3DTreeBuffer.cpp's to 0x00732500 and
  0x00736B60. 0x0071C470 loads `Shrubs_darken.vs` and `Shrubs_lighten.vs` where its
  twin 0x00732B00 loads the tree shaders.
* **Receivers.** All 25 terrain call sites found into these bodies load `this` from
  +0x3094 for a 0x0073xxxx body and from +0x3098 for a 0x0071xxxx body; for example
  releaseResources 0x006C6140 frees +0x3098 at 0x006C615C and +0x3094 at 0x006C616C,
  and reset 0x006D03B0 clears +0x3094 at 0x006D03CA and +0x3098 at 0x006D03E8. Every
  other reference to a 0x0071xxxx body comes from a 0x0071xxxx body, from the shrub
  vtable or from an unwind funclet.
* **clearAllTrees.** 0x00732E70 and 0x0071C7E0 are Zero Hour's clearAllTrees with
  BFME additions: count zeroed, bounds reset to 0 and 1, textures released, changed
  flag set, 64 type meshes released, type count zeroed; the shrub's also refills the
  50 by 50 partition with the end marker. Each constructor calls it right before
  allocateTreeBuffers and the terrain's reset calls the +0x3094 one first, both as in
  Zero Hour.

So BFME's W3DShrubBuffer carries Zero Hour's tree code, and BFME's W3DTreeBuffer is
the rewritten class at 0x00732500 to 0x00737B70. Method names on W3DShrubBuffer follow
the Zero Hour W3DTreeBuffer bodies they match, as updateSway and addTreeType already
did; resetMatchingRow, stampShroudVisible and removeTreeAtIndex keep their names.

* **Terrain methods.** reset calls 0x006CB8D0 with the terrain as `this` (as do
  ParseEnvironmentData and two unnamed paths), and it reloads the stage-three texture
  from the macro texture name, as Zero Hour's one-argument updateMacroTexture does;
  the pin `bfmeUpdateMacroTexture@BaseHeightMapRenderObjClass` already named its
  class. reset() still spells the call through the TU-local `BaseHeightMapResetTerrain`,
  because a plain AsciiString temporary changes reset's unwind code (372 to 364
  bytes); its pin at ILT 0x00003CE2 maps that spelling.
* **Unproven method names.** The +0x30A4 and +0x30B4 reset bodies take their
  addresses. `freeRoadBuffers`, the constructor's name for 0x006DEB70, matches
  neither Zero Hour's freeRoadBuffers (it deletes two arrays) nor its clearAllRoads.
* **List class.** 0x0094CE50 clears the list members at +0xC0/+0xE8 of the tree
  buffer and +0x1458/+0x1480 of the shrub buffer, which the shrub constructor builds
  with 0x0094D1E0, already pinned as `Rva0094D1E0List`.
* **Not changed.** The shrub (0x0071EAC0/0x0071EA00) and the tree (0x00735D80/
  0x00735CC0) each have their own tree-type constructor and destructor; which pair
  is Zero Hour's TTreeType needs more than analogy, so the names stay. The tree
  constructor 0x00736720 is still a dump.
