Artifact

Where the files sit
-------------------
Upstream ships four source directories; this tree is those flattened into one,
which is how EA built it:

    src/        lapi lcode ldebug ldo lfunc lgc llex lmem lobject lparser
                lstate lstring ltable ltm lundump lvm lzio (+ their headers,
                llimits.h, lopcodes.h)
    src/lib/    lauxlib lbaselib ldblib liolib lmathlib lstrlib
    src/luac/   luac.h print.h
    include/    lua.h lauxlib.h lualib.h luadebug.h

Each .c carries a `// cl: /MD` first line. /MD is load-bearing: retail linked
the DLL CRT, so its libc calls go through `__imp__` indirections, and the
static-CRT direct calls do not byte-match.

What differs from upstream
--------------------------
Twelve of the 48 files differ in code. BFME's Lua is EA's own fork of 4.0.1 —
it has a real boolean type where stock 4.0.1 has none — and the changes below
are a RECONSTRUCTION of that fork inferred from retail's bytes, not a copy of
EA's source, which has never been published. Every one of them is marked at
the point of change in the file itself as well as here.

    lvm.c       58   the boolean tag itself: `not` yields a boolean, the four
                     conditional-jump opcodes test it, tostring/lessthan handle
                     it, and OP_PUSHBOOL is dispatched. OP_PUSHNILJMP pushes
                     EA boolean false. A zero-instruction MSVC _WriteBarrier
                     keeps the two conditional-jump pop tails separate;
                     this compiler-shaping addition is not claimed as EA source.
    lcode.c     31   OP_PUSHBOOL's opcode-mode table entry; `true` compiles to
                     OP_PUSHBOOL rather than stock's PUSHINT 1; plus
                     `codepushbool`, a function with NO upstream counterpart
                     (see the caveat below); __assume(i != 0) preserves
                     retail encoding order without an emitted instruction
    lobject.h   15   LUA_TMARK 6 -> 7 and NUM_TAGS 6 -> 7 (retail's luaD_call
                     stores 7); `int b` added to Value and `bvalue()` to reach
                     it; `int reqsize` added to Hash
    lparser.c   14   simpleexp gains TK_TRUE and TK_FALSE cases
    lobject.c    4   luaO_equalval handles tag 6
    llex.c       3   "true"/"false" added to the reserved-word table
    llex.h       3   TK_TRUE, TK_FALSE, and NUM_RESERVED counted to TK_FALSE
    ltable.c     3   luaH_new takes and stores the caller's requested size
    ltable.h     2   luaH_new's declaration follows it
    lopcodes.h   2   OP_PUSHBOOL inserted after OP_POP
    lapi.c       2   the luaH_new call site
    lstate.c     2   the luaH_new call site

The other 36 files are byte-for-byte upstream apart from the header comment
block at the top. Re-derive the split with:

    curl -L -o lua-4.0.1.tar.gz https://www.lua.org/ftp/lua-4.0.1.tar.gz

and diff each file from its `** $Id` line down.

The boolean tag has no name in this tree because it has none in the image:
retail switches on the literal 6, and lotrbfme.exe exports no Lua symbols and
carries no string naming the tag. Writing `LUA_TBOOLEAN` here would assert a
spelling the image does not witness, so the literal is used and commented.

What this tree does NOT claim
-----------------------------
1. `codepushbool` in lcode.c is THIS repository's C, not upstream's and not
   EA's. It reproduces all 151 bytes at 0x0099EF70, including the
   call-vs-encode order around `codelineinfo()`. A compiler assumption that
   the encoded instruction is nonzero is valid because OP_PUSHBOOL is 6;
   it supplies a second use that prevents MSVC's single-use folding while
   emitting no instruction. This reconstruction shaping is not claimed as
   original EA source. The ledger now attributes the address to lcode.c.

2. `LoadInt`/`LoadSize` in lundump.c compile to the same 25 bytes, and exactly
   two unclaimed addresses hold them: 0x0099D670 and 0x0099D690. Counts agree,
   so both are certainly present, but nothing decides which is which. Neither
   is claimed, following the same standard as the LZHL `_wrap`/`_distance`
   pair and the vendor/d3dx9 twins. See `reverse/re_attempts.log`.

3. The reconstruction is pinned by bytes, not by documents. No EA Lua source
   exists publicly to diff against; the evidence that these are EA's changes
   is that the bodies compiled from them reproduce retail exactly, and that
   the stock 4.0.1 bodies do not.
