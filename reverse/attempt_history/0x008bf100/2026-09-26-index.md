`[esp+0x2DC]`, decrements at +0xA7, and compares at +0xAA. Both streams rejoin
at +0xAE. EDI's first working use is +0x48AB in the zeroing tail. This also
shifts the first table-store relocation. The compiler cause remains unknown.

These 45 measured full sources produced 13 distinct main-body
fingerprints. Identical fingerprints are one instruction/relocation result,
not independent improvements. No variant improved the checkpoint.

Key interpretations:

- Tail helper/scope changes isolate EDI's first use; assignment/initialization
  scopes isolate preceding liveness. They leave the residue unchanged.
- Out-of-class/derived/base/member storage and release helper changes leave
  the residue unchanged. Typed table changes relocation names but not the
  instruction shape; it is not a matching improvement.
- `/EHs`, `/Z7`, `/Ob1`, `/Oa`, destructor-only optimization controls, and CRT
  memset declaration/automatic intrinsic selection leave the residue unchanged.
  `/Z7` here tests the matched-switch parent, unlike the old non-switch test.
- C++ linkage on the barrier loses intrinsic recognition and emits calls.
  Assignment-exit barrier changes scheduling broadly. Whole-class optimization
  suppression prevents constructor inlining. A visible real setter or all named
  local lifetimes loses the frame/slot result. Complete-lifetime helper fails to
  inline; its short main body is not missing EH evidence in the parser.
- Volatile full-width bitfield and unused-result scalar decrement were controls
  for different lowering paths; they expand the body. Comparison-only volatility
  and branch-local barriers without the pre-decrement barrier reproduce the
  older 2,137-difference result with wrong EH-store order. No volatile variant
  is accepted into the bank.

Resume from the bank and these measurements; another equivalent release rewrite
or unconstrained flag sweep has no supporting new hypothesis. The next attempt
must explain the compiler-generated EDI save placement while preserving the
full frame, EH, relocation and dependency contracts.
