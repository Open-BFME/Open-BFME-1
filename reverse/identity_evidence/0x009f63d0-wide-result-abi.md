# 0x009F63D0 wide-result query, still a dump

The retail body is 555 bytes and ends in `ret 0x1C`. Three matched wrappers in `BfmeWideResultForward.cpp` call it with a hidden result pointer and six stack arguments. This proves the call ABI but the wrappers' synthetic names do not establish the retail owner's original spelling; keep an RVA-qualified owner until independent evidence appears.

The body calls the matched result constructor at `0x009F39F0` once. It accepts a mode value 0 through 4, optionally derives a mask from the matched `0x009F2AB0` getter, uses the matched `0x009F46E0/0x009F4750` indexers to bound a point or range, and loops through 17 twelve-byte records beginning at `this+0x18`. For each selected record it calls the matched recursive query at `0x009F4130`. The distance callback comes from the retail table at VA `0x012DBD60`; that table's semantic identity is not proved or pinned here. The tail optionally calls the matched `0x009F4020` result operation, then returns the result pointer and releases its local reference.

The typed baseline in ignored `build/rva009f63d0-probe.cpp` reuses the matched result payload/constructor and recursive-query declarations. Its first probe emitted 528/555 bytes with 411 non-relocation differences and 16 displaced relocation sites; the first instruction difference at `+0x15` is a 0x10 frame versus retail's 0x1C frame. Forcing the bounds locals to stack with `volatile` emitted 539/555 but worsened to 434 differences and did not fix the frame or saved-register schedule. These are hypothesis probes, not byte claims. The callback table, result lifetime, and argument scheduling still need source-level evidence before this row can be replaced.
