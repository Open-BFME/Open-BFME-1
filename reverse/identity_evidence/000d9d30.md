# 0x000D9D30 is not `Player::loadPostProcess`

* **The real loadPostProcess.** Player's vftable 0x010840CC holds the one-byte
  `ret` at 0x000DD960 in slot 1, BFME's Snapshot loadPostProcess slot (slot 2
  returns the snapshot name, slot 3 is xfer; about forty classes' slot 1 bodies
  are named loadPostProcess on the same evidence). Zero Hour's
  Player::loadPostProcess is empty.
* **This body.** No vftable references 0x000D9D30 or its ILT thunk
  0x00406906. Its only caller is the PlayerList routine at 0x000DF330, which
  calls it once per player. It creates the player's starting object from the
  player template and runs the new-map step: work Zero Hour does not do in
  loadPostProcess.
* **Name.** The method's real name is not proven, so the row takes an
  address-derived owner, `Rva000D9D30Player::method`, over the same C++.
